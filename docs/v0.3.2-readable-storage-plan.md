## 1. 冻结的设计

保留工程旁`.data`与`attempts`根。新增工程默认使用可读布局；旧存储JSON未声明新版布局时继续UUID目录。
UUID仍是内部正式身份，N/R/A仅是存储定位编号。目录名、章节标签和索引都不能成为Graph或Runtime权威。

```text
Example.data/
├── 文件目录.html
├── .zniku-storage-owner.json
└── attempts/
    ├── common/分章分叶__N003/R002-A001/outputs/{A,B,C}/...
    ├── chapters/0001-A/
    │   ├── 逐叶增强-leaf-0001__N004/R002-A001/...
    │   ├── 章节增强合并__N007/R002-A001/...
    │   ├── FI上下文准备__N008/R002-A001/...
    │   ├── 外部FI补帧__N009/R002-A001/{incoming,outputs,logs}/...
    │   └── FI精确裁边__N010/R002-A001/...
    ├── program/连续视频编码__N020/R002-A001/...
    └── custom/其他任务__N022/R002-A001/...
```

这是纯合成示意，未对应任何用户运行身份。阶段名称由Project Service按精确内建节点定义提供纯数据提示；
Runtime不识别业务名称，普通自定义节点不要求有章节。多源、多输出、多实例保持合法，不用节点ID或文件名
反推媒体身份。一次Split仍在一个独立attempt内产生全部章叶，不额外复制媒体来拼目录。

节点存储编号与首次选定目录在SQLite中固化；运行编号及NodeRun路径与其插入在同一事务提交。失败不留下
半套映射。编号不来自当前画布排序、临时UI显示序号、文件系统扫描或目录最大值。改别名、拖动节点、展示
分组不重命名旧目录；删除/重跑节点不回收其编号或媒体。新attempt不覆盖历史，新Run复用原Artifact。

## 2. 兼容与安全

- 新存储合同明确版本化；旧`0.3.0`与缺省字段继续解释为UUID布局，未知格式失败关闭。SQLite继续复用
  既有工程存储JSON，不新增Graph版本、全局scope、证据链或第二张图。
- 兼容方向是新包读取旧工程；旧候选不认识新的存储合同，不能保证打开已使用新版布局的工程。成功整理
  会更新`.zniku`中的定位记录；“保留原件”指媒体及旧数据根，并不等于自动保存旧工程文件副本。
  若需要回到旧候选，整理前先自行备份`.zniku`，并同时保留原数据根。
- 工作目录只接受服务端持久绑定的根内受控路径。拒绝上跳、绝对注入、链接/reparse、重叠/嵌套attempt、
  Windows危险组件及超出受支持预算的路径；既有UUID路径继续可读和提交。
- 可读attempt路径限制为180个UTF-16单位，声明输出全路径不超过259个单位。路径超长明确报错，
  不截断正式媒体文件名或悄悄换盘。请优先使用较短的数据父目录；外部AI可在其专用短目录处理后通过UI导入。
  本次保留既有端口收件子目录编码，不把所有外部应用的长路径支持当成保证。
- 外部收件仍以端口和当前handoff绑定，任意来件名须选择、检查、收纳及显式Submit；不得凭文件出现自动推进。
- 内部媒体点分命名和FI raw/crop职责不变。原素材、外部原件、已登记产物、历史attempt永久保留。
- 除显式用户存储维护外，不改任何Graph、Run snapshot、媒体参数、定义版本或reuse/stale结论。

## 3. 整理、换盘与重新定位

整理旧目录：选新的数据父目录 → 预览旧/新映射、文件数、字节数与外部依赖 → 明确确认 → 复制并核对 →
同一事务切换已声明的工作/日志/handoff/Artifact定位。原数据保留，失败保留原工程与原件，不原地批量改名。
普通换盘可以保留旧布局，整理操作才显式转换为可读布局；新数据配置不能隐式清空已分配映射。

恢复已有副本：选择已经复制或搬到新盘的`.data`本体 → 预览匹配范围与未包含依赖 → 明确确认后重定位。
它不复制、不删除、不猜选任意媒体，也不修改外部素材或成片路径。原位置缺失时只开放工程维修入口，
不创建空数据根、不回退系统盘、不启动Runtime；重新定位成功后才恢复执行能力。
新数据根的归属标记只重复数据库中的随机`data_id`，不是媒体清单、内容摘要或执行依据。原位置缺失时
必须匹配此标记；没有历史绑定的旧工程需先恢复原位置，再显式整理或正常迁移，不能仅凭同形目录收养。
旧数据不可读时，数据库已登记文件的路径/大小/mtime匹配不等于内容证明，界面必须披露核对范围；不宣称
第三方隐含文件或完整离线归档已被验证。活动和外部等待任务禁止迁移/重新定位。

## 4. 文件目录与操作者界面

“工程数据”中按当前位置与布局、整理/换盘、归档检查和重新定位分类。所有有副作用操作保持native picker
取消无副作用、一次性预览确认、会话/CAS重验、单操作互斥和迟到响应保护。

显式生成`文件目录.html`：由Python从工程、Run及Artifact生成，展示可读任务/批次、文件、模型声明、
媒体信息、有效/历史/失效状态及外部依赖。使用HTML转义和安全链接，不注入插件脚本，不复制第二套媒体。
它是可重建浏览索引，不是运行依据或强制归档Manifest；生成索引失败不能回滚已完成媒体。
仅通过受控的当前工程索引reference复用文件管理器定位能力；不允许浏览器传任意本机路径执行HTML。
历史日志与已结束交接文件保留原始内容；其中旧的绝对路径仅表示当时现场，迁移后的当前位置以工程和新生成
文件目录为准，不批量改写用户文件或已结束的交接文档。

归档检查继续列出原素材、根外输出、缺失与未检查范围。完整离线打包/自动收集未知插件路径、跨机器工具与
模型安装不在本专项范围内，不能把`.zniku + .data`宣传为无条件可迁移的完整成品工程。

## 6. 操作者验收入口

1. 在当前`0.3.2`候选页面使用“退出应用”，确认旧候选服务停止；不要只关闭标签页。新旧候选共享同一
   `0.3.2`本机状态通道，因此未退出旧进程就双击新包，仍可能打开旧页面。
2. 双击本次独立候选的`ZNIKU Studio.exe`。原候选完整保留；新包也必须保留整个目录和`_internal`。
3. 用新建的合成或短样本工程验证默认目录；新工程无需手动选择布局。节点开始执行或进入外部等待时建立
   对应实体目录；仅创建Run或复用成果不复制媒体、不会凭空生成一整套输出文件。
4. 若要整理旧工程，先备份`.zniku`以便旧版本回退，再打开“工程 → 工程数据”，选择“选择新父目录并预览整理”。
   先看总字节数、目标、
   根外依赖及路径对照，再确认复制；目标父目录下不能已有同名`.data`。预计需要至少容纳本次复制清单的
   可用空间，原目录不会清除。长复制期间保持应用运行，失败不自动重试或删除副本。
5. 完成后点“生成文件目录”，再“在文件管理器中定位目录索引”，可自行双击HTML找文件。索引是生成当时的
   快照，继续处理、改参数或迁移后应重新生成。归档时仍需同时保留`.zniku`、`.data`和清单列出的根外依赖。

旧真实验收工程尚未自动整理；原布局继续可用。新存储功能的合成验收不替代操作者真实换盘、归档及外部AI验收，
也不改变分章与重叠FI计划中仍待完成的专项状态。
