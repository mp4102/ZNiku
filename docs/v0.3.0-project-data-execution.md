## 已冻结的范围

1. 新桌面工程默认使用最终工程名旁的 `.data/attempts`，允许选择专用磁盘；配置存入工程，不依赖本机偏好。
2. 旧工程不自动搬迁。已有 attempt 后必须单独预览并确认迁移；首版迁移仅支持没有活动/等待 Run 的工程。
3. 每个 attempt 继续独立，最后一级保留 UUID 身份。章目录和点分名称位于其受控输出内，UI 使用友好任务
   名和直接打开目录按钮，不要求操作者抄写 UUID。
4. 外部节点准备成功后已有 `incoming/<端口安全编码>`，支持直接放入任意名称的候选和 UI 选择复制。
   目录编码不限制合法 Graph port ID，也不是领域 digest；用户通过“打开收件文件夹”使用，不手工拼接。
5. 自动发现不自动认领/提交，不把尺寸暂稳当作工具结束。多个候选明确选择，多输出不猜测绑定。
6. 收件目录内候选经明确确认、同一 validator 通过后受控收纳，避免第二份完整复制；外部源选择仍复制保源。
7. 已登记成果、人工交付与旧执行结果长期保留；只有程序创建的临时暂存可以自动清理。保留失败数据不表示
   支持节点内部 resume，重跑仍从头创建新 attempt。
8. 不增媒体算法、章片副本、节点内部断点、全局 hash/receipt 或强制归档 Manifest，不变更产品版本。

## 点分命名

命名由 Python AV27 节点适配提供，Runtime 只消费已解析的相对输出路径，不理解 A/B、Enhancement 或 FI。
基名是已保存的纯命名值，不能成为媒体身份。章内 leaf 从 0001 命名，内部全局 port/leaf ID 和 ordinal 不变。

| 角色 | 示例（合成名称） |
| --- | --- |
| 已存在或显式导出的章片 | `Example (2026).A.mkv` |
| leaf | `Example (2026).A.leaf-0001.mkv` |
| leaf 增强 | `Example (2026).A.leaf-0001.enhancement.mov` |
| 章内合并 | `Example (2026).A.enhancement.mov` |
| 章节 FI | `Example (2026).A.enhancement.fi.mov` |

当前 AtomicSplit 直接生成 leaves；本专项不为了第一行名称增加整章实体文件。也不跳过单 leaf 的 Merge。
旧 handoff 的固化输出名保持有效；新名称必须进入 Python 正式 target 并由同一 validator 验证，不能只改 UI。

## 迁移和归档边界

只迁移当前工程记录的 attempt 子树，不扫描复制全局 AppData。拒绝路径逃逸、链接/reparse、重叠根和目标
冲突。复制核对完成前不改数据库；最后事务只切路径与存储配置，Graph、状态、历史身份与媒体参数不变。
原件不删除，失败也不得覆盖源或其他工程。大文件维护使用同一单操作 busy 门禁，状态仍可读取。
迁移失败可能保留目标副本，界面会说明；再次尝试请选择新的父目录，不自动清理或覆盖失败副本。
已配置的数据位置缺失或变成联接时，打开工程会明确失败，不重新创建空目录或静默回退 AppData。
当前配置保存绝对本机位置，手动搬动 `.zniku` 不会自动重定位 `.data`；换盘使用明确迁移操作。

归档检查只证明已声明检查范围：已登记 Artifact、工作目录与其缺失/外部依赖。它不是自动打包，也不能证明
第三方节点任意未声明的路径依赖；界面必须明确提示外部原素材/输出仍需一并保留。

## 必须验证

- 工程旁默认位置、专用盘、取消无副作用、路径不可用不回退；旧配置/未知版本失败语义。
- 迁移源保留、数据比对、无数据库半切换、冲突/空间/复制失败、工程外依赖与已登记缺失。
- A/B 章内编号、旧固定名兼容、正式新名验收、外部候选不同名但同一媒体合同。
- 无候选/一个/多个、复制中或变化、迟到/重放、目标换代、覆盖明确确认和失败原件保留。
- 同名节点与新 attempt 不串收件目录；发现/收纳不自动 Artifact/Submit。
- Studio typecheck、完整测试、生产构建及生产 E2E；Python 全量与 Windows/Linux strict mypy、Ruff、
  Schema、架构/文档链接和 Git 卫生。

当前用户真实工程只用于已授权的只读核对，不作为自动迁移目标。完成后提供新包和验收步骤，由用户显式
决定何时迁移已有工程。

## 操作者验收顺序

1. 使用新本地候选启动，先创建一个新工程。在选择素材页确认默认“工程旁”，或选择专用磁盘父目录。
   开始分析前不创建数据目录；确认分析时才建立 `<工程名>.data/attempts`。片名和年份组成保存的媒体基础名。
2. 进入外部步骤，点击“打开收件文件夹”，复制处理完成的 `.mov`，原名不限。等列表发现后明确选择候选，
   查看规范目标名并“确认检查并收纳”。收纳只是移动并验证，再执行原有“检查输出 → 提交并继续”。
3. 也可继续使用“选择处理好的文件”；此方式复制外部原文件到规范位置，保留原文件，不要求先改名。
4. 打开顶栏“工程数据”，查看位置、已登记资产和归档外部依赖。原素材与工程目录外成片仍需另外保留。
5. 旧工程只有明确选择新位置、预览并确认后才迁移。先结束/放弃全部活动或等待任务；迁移逐文件复制比对，
   完成后工程指向新位置，原位置的全部数据仍保留。不自动改历史文件名，也不代表完整离线归档。
