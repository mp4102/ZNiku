## 1. 已实现的编辑体验

- 单一 Graph 的撤销／重做：添加、删除、复制、连接、移动、参数应用、有序输入重排及批量添加；
  同一次拖动只在结束后提交，批量“为所有输出添加下一步”以及模板展开各是一条历史记录；
- 历史保留当前编辑会话最近 100 条操作；新编辑清空 redo，无变化不生成记录，重开工程清空历史；
- 友好节点与端口名称、实例别名、关键参数摘要、节点折叠，以及纯展示的章节／Leaf 分组、颜色与折叠；
- 兼容输入高亮、从输出拖到空白后选择下一步、自动连接、多个输出分别添加相同节点的普通 Graph 宏；
- 键盘“连接节点”对话框、确定性 DAG 布局、适应画布、缩放到选区、画布搜索与视口恢复；
- `ordered_many` 使用可拖动的输入列表及上移／下移按钮，显示来源节点与来源端口，普通模式不要求编辑
  ordinal；高级模式仍可检查协议字段；
- 创作者／高级节点图模式只是本机信息密度偏好，读写同一工程。不会生成另一张图，也不改变运行结论。

参数表单继续采用 Phase 1 的显式应用边界。无效或未应用的 ParameterDraft 不进入 Graph、自动保存、运行或
切换工程；保存等待期间发生的新参数输入也会阻断后续切换／运行。

## 2. 持久化与失败语义

### 独立 StudioState

Python 公开 `StudioState`、`NodeViewState`、`GroupViewState`、`StudioViewport`、
`ProjectAuthoringSnapshot`、`AuthoringDiagnostic` 与 `StudioWarning`。新增字段不进入 Core
`ProjectSnapshot` 或 `Run.graph_snapshot`：

| 数据 | 保存位置 | 用途 |
| --- | --- | --- |
| `NodeInstance.ui_position` | 原 Graph 字段 | 保持已有位置兼容；仍不进入执行签名 |
| `node_views` | 独立 `studio_state` SQLite 表 | 按稳定 node_id 保存别名、折叠、分组引用 |
| `groups` | 同表 JSON | 稳定 group_id、纯文本标题、闭合颜色 token、折叠 |
| `viewport` | 同表 JSON | 有限 x/y、正 zoom；null 使用默认适应布局 |
| `storage_revision` | 同表独立整数列 | 存储 CAS，绝不是领域级 Revision 或执行身份 |
| `project_session_id` | Project Service 当前内存会话 | 隔离重开、换工程和迟到请求，不写进 Graph |

展示数据拒绝未知字段、版本、重复身份、悬空节点／分组引用、非法文本及非有限坐标。已存展示 JSON 损坏时，
读取回退默认展示并报告 `W_PROJECT_STUDIO_STATE_RESET`，不偷偷修写文件，不影响 Graph／历史 Run／Artifact。
storage revision、Core Graph 或 definitions 损坏则继续失败关闭，不按展示 warning 降级。

### schema 2 → 3

- 新工程使用 schema 3。旧 schema 2 工程只读打开和运行不会被提前升版；第一次 authoring 保存才迁移；
- 保存先完整校验允许落盘的 Graph、definitions、StudioState 和 CAS；随后在同一写事务中创建一致的旧库
  备份，再写 schema、Graph、展示与递增的 storage revision；
- 备份保存在原工程旁的 `.zniku-schema2-backup-<UUID>.zniku`，排他创建、验证 SQLite 完整性，绝不覆盖
  已有备份。备份失败或后续迁移失败保持原工程事务不变；成功创建的备份保留供人工恢复；
- 原 Run、attempt、Artifact、NodeResult、日志索引及 stale 标记原样保留；UI-only 保存不触发 stale；
- SQLite 读取与备份连接均显式关闭；Windows 上不依赖垃圾回收释放工程文件句柄；
- 不支持 schema 3 的旧客户端不得修改它。schema 升级是既定基线的存储演进，不是第二层执行权威。

### 同一张图的安全草稿

`GraphValidator` 的一次完整诊断提供机器可读 `validator_keyword`，保存只允许
`E_REQUIRED_INPUT_MISSING` 与 `E_PARAMETERS_INVALID + required`。不会解析本地化错误文案来放行。
其他 Schema violation、组合规则失败、未知定义／executor、悬空引用、类型不兼容、多入边、ordinal 错误及
cycle 全部拒绝，原工程保持不变。

安全草稿显示“已保存，但暂不可运行”。创建 Run 仍执行同一 Python GraphValidator 的完整校验；有任何
diagnostic 都不得创建 Run、snapshot、attempt、handoff 或 Artifact。

### 自动保存与运行门

- Graph 和 StudioState 是同一个不可变编辑文档；500 ms debounce、single-flight、latest-wins；
- 回执只确认已发送快照，绝不覆盖在途期间的较新编辑。Undo 回到旧值但旧写入仍在途时仍视为 dirty；
- 成功确认要求 exact session、路径、Project／StudioState 内容及 `expected_revision + 1`；意外新 revision
  或其他窗口内容不是可自动重试的授权；
- 冲突、网络失败或错误回执保留本地编辑并停止自动发送。手工重试不自行采用远端新 revision；
  “重新载入磁盘版本”需要明确确认放弃本地编辑和历史；
- 未保存内容及未应用参数提供页面离开保护；工程切换先 flush，失败不切换；
- Run all、Run to here、Rerun from here 在 flush 后使用 exact session／CAS；事务中再次检查版本与实际
  snapshot。冲突不得先创建 attempt 或修改 stale；
- 正在运行时可以编辑、保存当前图，但不会改变正在执行的 snapshot。外部提交仍绑定原 Run／handoff；
- 模板确认回执必须与本次 Python preview 一致；复制、撤销或任何执行配置修改后，“模板已就绪”提示失效，
  单纯改名、分组、视口和布局不误报配置变化。

## 4. 操作者快速检查

1. 按 README 启动当前分支的 Python host 和 Studio，前后端同时更新；旧无 CAS 请求会被明确拒绝。
2. 新建或打开工程，添加节点；缺连接或缺必填参数时应自动保存并明确提示暂不可运行。
3. 选择输出节点，使用“为所有输出添加下一步”，或从输出拖到空白处；一次撤销应移除整批新增及连线。
4. 在“连接节点”中用键盘选择来源和目标；在有序输入列表中拖动或上下移动，不需要输入 ordinal。
5. 设置节点别名、展示分组与折叠，保存后刷新页面；Graph、位置、顺序、别名与分组应一致。
6. 使用 Ctrl+Z、Ctrl+Shift+Z／Ctrl+Y、Ctrl+S，验证新操作会清空重做；未应用参数应先应用或放弃。

## 5. 交付边界

本阶段没有重做 Phase 4 的创作者运行中心、外部处理助手或错误翻译，没有交付 Phase 5 的双击 launcher、
预览、完整无障碍及性能收敛，更不代表 Phase 6 的真实媒体／新用户验收或正式发行。

分组由操作者显式组织，标题中的章节／Leaf 只是 UI 文本，不从 node_id 猜业务范围，也不施加固定拓扑。
Undo 不回滚已经执行的 Runtime 副作用，不提供节点内部 checkpoint 或 resume。

package/product 版本保持 `0.2.0`，开发线仍为 `v0.3.0`；本次授权仅 commit/push，不创建 tag、Release、PR
或合并到 main。
