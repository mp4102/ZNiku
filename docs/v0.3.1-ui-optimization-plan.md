## 1. 产品判断与本次目标

采用 **画布优先、精简常驻、按任务渐进展开** 的专业工作区。

功能可以丰富，但屏幕不能同时充当工程管理器、节点编辑器、运行控制台、文件管理器和调试终端。用户首先
需要知道“正在编辑什么、哪里可以改、现在要做什么”，然后才是日志和内部身份。高级节点图不是调试模式；
用户需要精确参数或复杂分支，不代表他希望全部日志与 JSON 常驻。

本次不把自由节点图降级为固定向导，也不制作一套只适用于 AVEnhanceFlow 的精简图。模板用于帮助开始，
运行后的修改、添加、连线、分支和汇合仍在同一张自由 Graph 上完成。

成功结果是：视频编辑者不学习 Run、NodeRun、Artifact 或 JSON，也能独立配置、处理、提交外部产物、
理解失败和找到输出；技术操作者仍能精确编辑合法 Graph，并查到完整诊断。

### 2.2 检查点验证事实与远端门禁缺口

2026-09-08 提交前，Windows / Python 3.13.12 的 pytest 为 941 passed / 1 skipped（本机符号链接权限）；
Ruff、118 文件的 Windows/Linux 静态 mypy、lock、生成 Schema 通过。Studio 的 387 项测试、typecheck、
构建、7 项生产 E2E 和本地 npm audit（0 漏洞）通过。它们证明当前检查点，不是未来 UI 的验收结果。

推送后 [Studio CI](https://github.com/mp4102/ZNiku/actions/runs/34218031105) 的 Schema、类型、387 项
单测与构建通过，但 Ubuntu 生产 E2E 为 **6 失败 / 1 通过**，后续 audit 未执行，不能宣称远端全绿。

- 前五项工程/素材选择、导入确认及相关页面断言与上一检查点同型。代码核查确认 Linux 合成 HostBridge
  返回 POSIX 路径，而前端路径解析只接受 Windows 盘符/UNC；这是此组失败的主要解释，需要专门回归证实。
- 新工程数据用例通过收纳、字节检查及输出检查后，Submit 后 15 秒等待结束仍为 `running`。现有记录不能
  区分运行耗时与 Runtime 异常，不能直接增加超时或归为同一路径问题。
- 该 CI 没有上传失败截图/上下文且 trace 关闭。修复门禁时需补受控合成诊断，包含绑定、状态、网络结果和
  fixture stderr，不上传真实工程资料，也不统一过滤错误。
- [Core CI](https://github.com/mp4102/ZNiku/actions/runs/34218031069) 最终为 938 passed / 1 failed / 3 skipped；
  符号链接拒绝测试预期 `E_HANDOFF_IMPORT_PATH`，实际由更早的关系检查抛出 `E_HANDOFF_RELATION_CORRUPT`。
  它在 Windows 因创建链接权限而跳过。必须核对正确拒绝层并补回归，不能放宽为任意异常或伪称安全门禁通过。

这两类 E2E 问题列入实施前门禁：先区分产品正式 Windows 支持面与跨平台合成测试合同，再做最小修复。
不因 Linux fixture 失败而擅自扩大原生桌面支持平台或放宽路径安全。新增超时单独诊断。以上为实施前已确认
缺口，门禁执行中的修复和最新证据另记，不追改旧 CI 的失败事实。

## 3. 问题、根因与可验收结果

| 用户报告 | 已核实的根因 | 目标结果 |
| --- | --- | --- |
| 顶部按钮混乱 | 工程、编辑、执行、视图和开发动作同权重排列 | 一级顶栏仅保留工程上下文、编辑、历史与一个主操作 |
| “查看 Run”“高级运行操作”难懂 | 内部对象名直接作为任务入口，局部处理与危险命令混放 | 用“处理记录”“处理到此步骤”等明确动作，按作用对象归位 |
| 底部进度遮挡画布 | `RunCanvasOverlays` 通过 absolute 覆盖画布 | 独立布局行与可展开任务区，不覆盖节点和画布工具 |
| 节点设置混乱 | 运行报告、媒体信息、日志、展示设置与参数串成长列 | 稳定的“设置 / 文件 / 诊断”，参数在设置页首屏可达 |
| 连线横穿其他节点 | smoothstep 不感知障碍；布局使用固定层间/行间距 | 测量几何、尺寸感知布局、有界避障与路径强调共同解决 |

另外必须处理：卡片对象/数组摘要泄漏、历史完成与当前编辑混淆、端口多时锚点越界、轮询干扰草稿和焦点、
错误只藏在折叠区、人工等待被误读为进度等问题。它们与上述五项直接相关，不作为独立的功能扩张。

## 5. 不可改变的边界

1. 继续使用唯一 `Project.graph`、Python GraphValidator 和 Runtime。所有启动、复用、失效、检查与
   Submit 资格来自现有服务，不在 TypeScript 重写。
2. 当前图与历史普通 snapshot 明确分开；不新增 Compiler、Freeze、ExecutionPlan、领域 Revision 或第二张
   “可运行图”。UI 的视图选择不是新的 Graph authority。
3. Presentation 仍是 Python 声明、严格验证的纯数据。控件提示不添加第二套参数约束、任意 callback、
   命令模板、HTML 或插件 React。
4. 保留多 Source、多 Output、零 Output、合法分支与汇合；不把 A/B、唯一 Final 或固定媒体拓扑设为全局规则。
5. 参数继续“编辑草稿 → 显式应用”；布局、别名、分组、折叠、选中与诊断展开不改变执行及 reuse/stale。
6. 中断、失败节点从头创建新 attempt；不增加节点内部暂停续跑、断点或进度接管。
7. 外部文件选择、复制、观察、收纳、检查、Submit 各自保留边界；发现文件不自动提交，不绕过覆盖确认和
   Python validator，不自动启动外部软件。
8. 工程数据长期保留，保留显式换盘迁移与旧路径。界面刷新、完成、退出、重跑、删除节点不自动清理媒体。
9. 不调整 AV27 配方、编码参数默认值、分章/分页语义、Merge 后 FI 的关系或已经冻结的点分命名。
10. 真实媒体、工程、日志、路径、token、本机设置与试验产物不进入 Git；本次不修改 AVEnhanceFlow 仓库。

## 6. 工作区信息架构

| 区域 | 常驻内容 | 按需内容 | 不应该承载 |
| --- | --- | --- | --- |
| 顶栏 | 工程菜单、工程名/保存状态、撤销重做、处理记录、一个上下文主操作 | 视图菜单及工程动作 | 参数、日志、多个同权重执行按钮 |
| 左工具区 | 可发现的“添加节点”入口 | 可搜索节点库、模板与筛选，可固定 | 第二套固定流程或独立参数副本 |
| 中央画布 | 节点、端口、连线、选中与必要状态 | 查找、整理、缩放、小地图、路径追踪 | 长报告、遮挡式任务进度 |
| 右侧 Inspector | 选中对象标题及“设置 / 文件 / 诊断” | 当前对象适用内容 | 整个工程的历史、放弃整个 Run |
| 底部任务区 | 一行可信任务摘要 | 当前处理、历史记录、问题 | 覆盖画布的浮动长面板 |

### 6.1 顶栏与工程菜单

- 工程菜单收纳新建、打开、最近工程、工程数据、显式保存、返回首页和退出；保留现有快捷键。
- 已保存、保存中、尚未保存、保存失败必须可区分。“参数未应用”独立标识，不把保存当前 Graph 当作应用草稿。
- 保存失败提供原有重试/冲突处理，不偷偷另存、覆盖远端版本或丢弃本地编辑。基于当前 Graph 的启动/重跑
  和切工程继续走现有保存/离开门禁；已有 handoff 的检查/Submit 仍依据其固化绑定，不增设当前图保存条件。
- 向导突出于新建和未完成准备情境；已有工程不长期占据顶栏主操作。节点库与模板有明确添加入口。
- 视图菜单可切创作者密度/高级节点图、显示小地图等；高级模式不自动展开诊断。诊断入口始终可达。
- 开发状态与内部 ID 不与主操作并排。退出仍走原 launcher 的安全确认，取消不停止服务。
- 不新增“删除工程及全部媒体”命令；工程与数据删除政策不属于本版 UI 收敛范围。

### 6.2 当前图、历史图与主操作

打开工程默认显示当前完整 `Project.graph`。显式选择处理历史、定位某次处理步骤或启动 Run 时，才进入
对应的只读 snapshot 视图。历史视图持续显示“本次/历史处理使用的流程（只读）”与“返回当前编辑”。

| 情境 | 顶栏主操作 | 说明与约束 |
| --- | --- | --- |
| 当前图尚不能运行 | 检查工作流 | 显示已有服务诊断并定位；不能只变灰且不解释 |
| 当前图已保存且符合运行资格 | 开始处理 | 对当前 Graph 执行正式启动流程；一次意图不能生成重复 Run |
| 当前图准备启动，但参数未应用或保存未完成 | 完成设置 / 查看保存问题 | 引导处理未完成编辑；不自动应用，不带旧参数启动 |
| 本次自动处理进行中 | 查看进度 | 打开当前任务，不再次启动 |
| 一项外部任务待操作 | 处理外部文件 | 定位绑定的具体实例与文件页 |
| 多项外部任务待操作 | 处理外部文件（数量） | 先列任务供选择，不根据名字猜测或自动选任意一项 |
| 本次失败或受阻 | 查看问题 | 说明原因、影响与下一步，重试仍需现有资格与确认 |
| 本次完成 | 查看输出 | 展示输出列表；支持多个或零个 Output，不假设唯一成片 |
| 当前图已变更、上次处理完成 | 开始处理 / 检查工作流 | 同时标识“上次已完成”“当前已改变”；不能宣称当前图完成 |
| 正在浏览旧历史 | 查看本次输出 / 查看本次问题 / 返回当前编辑 | 不把历史选择当作活动 Run，不默认对历史图启动处理 |
| 服务不可达或会话已失效 | 重新连接 / 查看连接问题 | 展示最后可信状态及时间，不伪造失败或完成，禁止无资格变更 |

这张表定义用户语言与路由，不新增 Runtime 状态。多条件共存时，主操作按以下视图归属确定：

1. 服务/会话不可用先显示连接问题，阻止无资格变更，但不隐藏最后可信的只读信息。
2. 正在查看当前编辑图时，使用该视图的既有服务资格与活动任务投影；准备启动当前图才检查草稿和保存。
   下一次处理的未应用草稿不改变已有 handoff 的检查/Submit 资格。导航离开草稿时仍执行原有离开提示。
3. 正在查看只读处理记录时，顶栏主操作只定位这个被查看对象的输出、问题或进度，不暗中切换到另一 Run。
   底部摘要同时明确“当前另有 N 项任务待操作”，其“查看”只导航到对应活动任务，不提交或启动。
4. 例如旧历史已完成、活动任务等待外部文件、当前编辑有草稿：历史顶栏显示“查看本次输出”，任务行显示
   独立的待操作提示，草稿保留；用户明确选择活动任务后才进入该任务文件页，Submit 仍按其原绑定执行。

活动待办与被查看的历史对象必须有不同的明确标题和绑定；不把历史选择写成全局 active Run。多个活动任务
由正式服务投影并供用户选择，不由前端猜测最新 ID。重连后刷新投影，不自动启动、重试或提交。

“处理到此步骤”“从此步骤重新处理”归选中节点上下文，并解释祖先依赖与下游影响；不承诺只执行一个节点。
“放弃本次处理”归任务详情的危险操作。切换查看上下文不赋予执行权限；所有变更仍使用精确服务绑定与原确认。

### 6.3 历史、有效性和进度的展示规则

- 相同 `node_id` 不足以将旧 Run 的完成、进度、产物投到已编辑的当前节点。只使用服务提供且绑定正确的投影。
- 历史 `NodeRun.state` 不因当前图编辑而改写；`stale` 是当前结果有效性结论，不是新造的历史 NodeRun 状态。
- “完成 5/12 步”是步骤数，不是媒体处理完成 42%。自动百分比仅来自真实进度；缺测量时展示不确定进度。
- 人工任务显示等待、文件及交接状态，不显示倒计时或假 ETA；等待时间使用该 handoff 的真实开始时间。
- 轮询刷新不能自动切 Inspector 页签、打开日志、抢焦点、覆盖草稿或把当前编辑切回历史。
- 抽屉与节点状态复用同一投影/轮询所有者，不新建任务数据库、执行队列或第二套重试资格计算。

### 6.4 占位任务抽屉

收起时是画布外的固定布局行，显示状态、步骤计数和需要操作的数量。展开时从工作区分配高度，画布容器
随之缩小，而不是盖住已有节点。保留可调整高度、收起、键盘入口和关闭后的焦点恢复。

页签为“当前处理 / 历史记录 / 问题”。历史使用时间、处理范围、结果与实例名称，不以 UUID 作为条目标题；
完整精确身份可在详情复制。历史继续有界加载；没有活动任务时明确显示“没有正在处理的任务”或“上次已完成”。

收起摘要中的动作优先为定位/展开，不再放第二套同权重启动和重试按钮。失败和待人工操作的数量不能随着
抽屉关闭消失。主操作和任务区对同一对象的名称、状态必须一致。

## 7. 选中对象 Inspector

### 7.1 设置

1. 首屏依次显示节点名称、用途、基础参数；不要求先滚过日志与输出报告。
2. 常用字段按 Python Presentation 分组，显示中文名称、单位和当前值；帧率等精确数据可显示
   `59.94（60000/1001）`，但不得把显示近似值写回参数。
3. required 或非法高级字段必须显露，并关联错误；“高级”不是隐藏运行阻塞问题的地方。
4. 对象和数组继续由通用 Schema 表单处理。人类解释来自 Presentation，不对 `type_id` 写另一套 TS 业务表单。
5. 有序输入显示来源、实例名与可理解序号，保留现有排序行为；不能根据画布左右位置自动重写 ordinal。
6. “应用设置 / 放弃更改”位于设置页固定布局底部，占据空间。切页签保留同一 ParameterDraft；离开节点或
   工程遇到未应用更改，沿用明确的应用/放弃/取消，不自动应用或静默丢弃。
7. 原始参数仍编辑同一草稿，仅在高级/诊断入口按需打开，不形成第二份参数。Presentation 缺失或损坏时
   按已有隔离/通用 Schema 回退显示，不忽略正式 Schema 错误。
8. 别名、分组和折叠归“显示设置”，与处理参数分隔并解释只影响外观；不触发执行失效。

### 7.2 文件

按“输入及要求 → 待处理任务 → 已检查/已登记输出”组织，而不是把所有路径和媒体字段平铺。

- 自动节点只显示适用的输入、输出及按需预览；没有文件任务时不显示无效导入控件。
- 外部节点显示完整可区分的实例名、实际输入、任务要求、实际收件位置与候选状态。
- 主要操作使用“打开输入文件夹”“打开收件文件夹”“选择处理好的文件”“检查输出”“提交并继续”。
- 操作者能看到实际存放目录，但正常路径不要求手写绝对路径。位置必须来自服务，不由前端拼接。
- 同名实例仍以现有实例别名/展示信息区别，最终绑定依赖精确身份，不靠文件名认领任务。
- 媒体预览及系统播放器按需打开，不新增常驻监看器。没有可预览输出时解释原因，不显示伪成功占位图。

### 7.3 诊断

按需显示稳定错误码、错误详情、精确 definition/version、身份、原始媒体信息和有界日志。高级图形模式不
自动打开这些内容。失败摘要、涉及字段和可执行的修复动作仍在正常路径可见。

复制诊断需要说明可能含本机路径，不默认上传、打包真实媒体或推送 Git。错误翻译保留稳定码，不能统一
改成“未知错误”；未知错误保留原文并给安全下一步。

### 7.4 其他选择情境

未选中节点时显示轻量操作提示，不展开所有工程报告；选中边时显示来源、目标、端口与顺序说明。多选默认
只提供现有安全批量动作及共同展示信息，不新增混合参数一键覆盖。切换页签与选择处理应保留键盘焦点、
未应用草稿提示和只读历史边界。

## 8. 外部处理与工程数据：改善操作，不改变安全合同

两种收件方式在同一任务文件页并列说明：直接复制到专属收件目录，或在 UI 选择文件并复制。收件文件夹
进入外部等待时已由既有服务创建；界面不能在路径失效时自行回退系统盘或新建“看起来相同”的任务目录。

交互顺序为：查看输入与要求 → 在外部处理 → 放入/选择产物 → 查看候选 → 预览并确认收纳/覆盖（适用时）
→ 检查输出 → **显式提交并继续**。任何点击都不能暗中把“选择文件”扩大为 Submit。

| 情况 | 应显示与允许的动作 | 必须保留的失败语义 |
| --- | --- | --- |
| 无文件 | 等待文件，打开目录或选择文件 | 不显示完成，不倒计时自动失败 |
| 服务报告复制中，或仅观察到候选变化 | 分别显示“复制中”或“候选发生变化，请稍后检查” | 不猜外部进度；稳定不等于处理完成，不接受半成品 |
| 多个候选 | 列出并明确选择 | 不挑最新、最大或名称最像的文件 |
| 候选不符要求 | 人类原因、预期值与实际值、重新选择 | 源文件与现有合格目标保持原状 |
| 目标已存在 | 明确覆盖影响与确认 | 不因点击一次导入而隐式覆盖 |
| 检查通过、尚未提交 | “检查通过，等待提交” | 不宣称 Runtime 已完成 |
| Submit 成功 | 刷新对应任务与下游状态 | 保留观察暂停及新鲜状态后恢复，拒绝旧 waiting 响应回流 |
| 切工程/切任务后的迟到响应 | 丢弃不再匹配的响应 | 不更新其他 handoff，不抢占新页面 |

所有变更绑定 exact Project/session/Run/NodeRun/handoff/port。当前 Run 与历史 Run 并列可见时尤其需要
显示操作目标；只有服务允许的活动任务可以提交。中止、过期、重复确认及冲突仍失败关闭。

工程数据入口移入工程菜单，但必须保留实际数据根、归档依赖、长期保留说明与显式迁移入口。迁移仍要求
原资格、预览、确认、复制验证与事务切换，保留原目录；不能为了少一步操作而自动迁移旧工程。

显示文件名使用合成示例 `Example (2026).A.leaf-0001.enhancement.mov`、
`Example (2026).A.enhancement.mov`、`Example (2026).A.enhancement.fi.mov`。这些只是既有命名合同的
显示示例，不生成新的整章 Artifact，不重命名历史 handoff 或已验收成果。

## 9. 节点卡片、端口与真实几何

卡片默认只呈现名称、状态、两三项人类可读摘要和端口。移除对象/数组的默认 JSON 长摘要；不显示大段
executor、ID 或完整合同。摘要收敛不能隐藏端口、错误、required 参数提示和执行方向。

输入在左、输出在右；每个端口有实际布局行和名称，节点高度由内容与端口决定。不得继续使用能将多端口
定位到卡片外的百分比公式。长名称采用截断加可访问完整名称，不用无限撑高或极小字号解决。

节点与端口的测量必须覆盖折叠、不同摘要、错误提示、缩放和字体布局变化。沿用既有拖动/measurement
缓存修复，不因状态投影重建 React Flow identity、丢失尺寸或让节点在拖动中消失。

### 9.1 图形与参数的分界

- `ui_position` 沿用现有存储与 Undo；测量宽高、屏幕矩形、端口锚点和拖动标记为 session 几何缓存。
- 端口锚点位置不改变端口身份。连线从外观上的左/右移动，不等于反转 output→input。
- 改卡片摘要只影响展示，不修改参数；无障碍文本与视觉摘要来自同一可信投影。
- 拖动完成是一条 authoring 手势：一次 Undo、一次正式保存批次，不按每帧写库。

## 10. 布局与连线可读性

### 10.1 显式尺寸感知整理

继续提供明确的“整理布局”，使用真实尺寸、依赖层级、分支/汇合与跨层通道安排节点。算法必须有稳定的
并列排序规则；不得以视觉上下位置更方便为理由重写端口绑定或 ordered_many。

自动整理可 Undo，结果按现有位置保存；手动拖动不全图重排。整理前后的选择、草稿、Run snapshot、参数、
Edge、ordinal 与 reuse/stale 结论保持不变。首版以完整图整理为主，不额外引入复杂的持久锁定/排版合同。

### 10.2 有界避障路由

路由输入只包括当前节点矩形、端口锚点、边及显示所需安全边距。输出为临时渲染路径，使用正交/圆角表现，
不写 Graph、parameters、StudioState 或 Run snapshot。

1. 对无关节点扩展安全边距；源和目标有明确的端口出入口通道，不能把自己的端口出口判为障碍。
2. 使用尺寸与几何版本缓存；节点尺寸/位置、端口、边或折叠变化才使相关路径失效。无几何变化的进度轮询
   不触发全图求解。
3. 无关节点移入某条线的通道也必须失效该路线，不能只重算移动节点的入边和出边。
4. 拖动期间采用有界轻量更新，保持节点和线可见；落下后执行更完整的受限求解。合并连续请求，拒绝旧几何
   版本结果，不以无界后台队列换取表面流畅。
5. 同一输入、同一算法配置应得到稳定路线。求解必须有节点/通道/耗时预算，并记录命中缓存、耗时与降级次数。
6. 不能把 smoothstep 改名为“智能避障”就算完成；必须用线段与障碍矩形相交检查证明。

实施前以纯合成图比较可用的布局/路由库与小型专用算法。先检查许可证、维护边界、依赖和 bundle 增量、
确定性、取消能力及性能，再选择一种正式路径。不预先承诺特定库最优，也不因选型引入整个编辑器框架。
若纯组件内求解无法满足预算，可评估 Worker；必须说明取消与版本绑定，不能先引入多线程再补安全边界。

### 10.3 线、方向与交叉

- 悬停、选择或键盘聚焦节点/端口时强调直连路径；可进一步查看上游/下游链。其他线降低权重但仍可见。
- 线端有方向，端口名可读，颜色不是唯一表达。多入边保持可区分的轨道与顺序提示。
- 交叉处使用可辨识的跨线/断口样式，不能画成真实连接圆点；只有端口才是真实连接/汇合点。
- 不将多条边视觉合成一个无法辨别来源的总线，不为了少画线改变实际 Edge 数量。

### 10.4 无解与性能降级

不承诺任意用户位置、节点重叠或非平面图完全无交叉。标准目标是：节点不重叠且存在可用通道的 fixtures
不穿越无关节点；不能完全避免的线交叉仍能追踪。

节点重叠、端口被包围或求解超预算时，保留可见的区分式降级路线和“建议整理布局”提示；降级线仍须连接
当前正确的 source/target 端口锚点，不能复用旧端点或任意非空 SVG 占位。不能返回空路径、隐藏连线、
静默挪动节点、删除/重连边或假称已避障。降级数量可在诊断查看，正常失败提示必须可发现。

### 10.5 本版不做持久手动走线点

该取舍已随总体方向采纳。v0.3.1 先解决自动几何与避障，不增加可执行 Reroute 节点。未来若需要保存手动
控制点，必须先定义 Python 严格 UI-only edge-view 合同、引用清理、ordinal/边身份变化和旧工程兼容；不能
把未知字段直接塞入严格 JSON。临时绕线缓存也不能伪装成永久手工位置。

## 11. 视觉、响应式与无障碍

- 沿用克制的专业品牌；减少多层边框、重复标题和无任务价值的大写英文眉题。状态色配文字，品牌色突出
  选中与主操作，不把所有节点涂成警报色。
- 普通说明与控件目标字号约 14 CSS px，次要信息约 12 CSS px；以实际可读性验收，不靠缩小字体塞满面板。
- 左工具库 240–280 CSS px、右 Inspector 320–380 CSS px、收起任务行 32–36 CSS px 是原型起始范围，
  不是冻结像素常数。可调整的边界、最小画布和默认值由实施前测量确定。
- 窄窗口先收起工具库；仍不足时 Inspector 进入独立的可返回详情布局，不能形成覆盖后无法编辑的无提示面板。
  返回画布保留视口、选择和草稿。底部抽屉展开时仍占布局空间。
- 面板各自有受控滚动，应用/放弃栏和任务条不能覆盖内容。展开/收起及调整尺寸有键盘等价操作。
- Tab/Shift+Tab、Enter、Escape、现有编辑快捷键与输入框互不抢占；关闭菜单/抽屉/对话框恢复合理焦点。
- focus-visible、控件名称、错误关联、aria-expanded 与非颜色状态必需；进度播报限频，不连续打断读屏。
- 支持 reduced motion、200% 浏览器缩放和 Windows 高 DPI；物理分辨率、CSS viewport、DPR 分开记录。
- 至少检查 1280×720、1366×768、1920×1080；真实 Windows 125%/150%/200% 与自动化 DPR 模拟分别记证据。
- 本版不是品牌重做或新增主题系统；保留已有主题适配，不以大量装饰、动画或新图标依赖替代任务可用性。

## 17. 自动验证与量化矩阵

### 17.1 图形 fixtures

全部使用仓库内纯合成定义/参数和临时工程；文件名、路径、图和截图不取自用户真实工程。

| 编号 | 图形 | 必须断言 |
| --- | --- | --- |
| G01 | 普通单链 | 端口锚点、方向、整理稳定、无遮挡 |
| G02 | 跨多层长边及中间无关节点 | 路线绕障，不只测试相邻边 |
| G03 | 两分支及多层汇合 | 来源可辨，交叉不等于连接，不假设固定 A/B 身份 |
| G04 | 多 Source、多 Output、零 Output | 自由图仍合法，输出列表/空结果文案正确 |
| G05 | 1/2/6/8/16 个端口 | 全部端口在卡片边界内，名称与实际绑定对应 |
| G06 | 长名称、动态高度、折叠与错误摘要 | 尺寸改变触发正确测量/走线，不丢选择和草稿 |
| G07 | 拖动节点穿过其他边通道 | 非入/出边也能失效；拖动中与松手后可见，端点贴合当前正确锚点 |
| G08 | 平行边和 ordered_many | 顺序保持，轨道可辨，视觉整理不重排输入 |
| G09 | 节点重叠、端口被围、超预算 | 可见降级与正确端点，无空边、隐式挪动、断连或无限求解 |
| G10 | 50/200 节点及 1000 条历史 | 有界加载，交互与路由耗时/缓存/降级可测 |

纯几何测试对最终线段与扩展障碍矩形检查相交，明确排除源/目标自身合法端口出入口；圆角也须位于允许
通道内。仅有截图或“选了 smoothstep”不能通过。真实浏览器断言节点/线存在且可见，不只记录函数耗时。

布局与走线前后对比 Graph：只允许原有 UI 位置等展示数据发生预期变化；参数、端口绑定、Edge、ordinal、
reuse/stale 及历史 snapshot 不变。保存重开继续验证位置、端口与路径重新计算。

另外测试“异步整理/路由未完成 → 继续拖动或切换 current/snapshot（同 node_id、不同位置）”：请求须绑定
视图及几何版本，迟到结果不得挪回节点或串用路径；被取消的整理不能另造 Undo/保存操作。

### 17.2 行为与安全回归

- 正常/高级模式、设置/文件/诊断、抽屉开关的组合不得产生不同 Graph 或不同运行资格。
- 当前图变更后查看同 node_id 的旧历史，检查旧输出不能伪装为当前有效结果。
- 旧 completed 历史、活动 waiting handoff 与未应用当前草稿同时存在：主操作、待办提示、草稿及 Submit
  资格各自绑定正确，不将下一次处理草稿变成已有交接的新阻塞条件。
- 未应用草稿下切节点、历史、工程、页签、离开页面，以及保存失败、CAS 冲突均不静默丢弃或自动应用。
- 快速切工程/任务、重连与轮询迟到不串绑；Submit 后不恢复旧 waiting 观察，不重复执行副作用。
- 外部收件覆盖无文件、变化中文件、多候选、错误尺寸/帧率、替换目标、权限失败、过期确认及正确提交。
- 数据位置缺失/链接异常不回退；旧工程不自动迁移；完成、退出和删除节点不清理媒体。
- 生产 E2E 要求零非预期 console/page error。负向用例的 422/409 等逐项断言 endpoint、状态和错误码，
  不通过全局过滤错误使测试变绿。

### 17.3 性能与工具门禁

维持既有标准：50 节点常用选择、拖动、参数展开 p95 ≤150 ms；200 节点/1000 Run 不无界读取或冻结界面。
路由另记总耗时、单次主线程工作、缓存命中与降级次数，以相同设备、viewport 和生产构建比较；不能仅凭
一次快照宣称所有图都流畅。选型时给求解工作设实测预算，超限走可见降级，不降低 validator。

每次修改 Studio，至少执行 `npm run typecheck`、`npm run test:run`、`npm run build`；每批退出再执行
`npm run test:e2e`。涉及 Python Presentation、DTO、参数解释或命令投影时同步运行相关 Python 测试、
Schema drift 与类型检查；每批最终集成门禁运行完整 Python 套件、Ruff、Windows/Linux 静态 mypy、
lock/版本/架构一致性、npm audit 和 Git diff/敏感文件检查。Linux 静态检查不是 Linux 运行证据。

## 18. 首次用户验收：不降低原正式门槛

至少 5 名未读仓库文档、不需理解 JSON/DAG/Runtime 的首次目标用户，各执行五条 Journey 的代表任务；
另设 1 名技术操作者验证高级自由图。使用合成素材或仓库外只读短片，记录匿名结果而非个人路径/媒体。

| 指标 | 门槛 |
| --- | --- |
| 无协助任务完成率 | 25 个任务至少 23 个完成（≥92%） |
| 独立端到端 | 至少 4/5 无人工提示完成 |
| 安全关键动作 | 5/5 不覆盖 Source、不提交非法产物、不误删上游 |
| 默认路径技术泄漏 | 要求 JSON、CLI、绝对路径、Run/Artifact ID 或日志的次数为 0 |
| 新建到合法工作流 | 中位数 ≤5 分钟，不含媒体处理时间 |
| 修改三个参数 | 中位数 ≤90 秒 |
| 添加并连接节点 | 中位数 ≤2 分钟 |
| 定位失败并正确重试 | 中位数 ≤2 分钟 |
| 外部产物检查与提交 | 中位数 ≤3 分钟，不含外部处理时间 |
| 解释错误原因与下一步 | 至少 4/5 能正确说明 |
| Single Ease Question | 各关键任务中位数 ≥5.5/7 |
| System Usability Scale | 总体中位数 ≥80 |
| 自动化无障碍 | critical/serious 为 0 |
| 领域正确性 | Source 改写、非法 Artifact、伪完成、伪进度均为 0 |

测试主持人不先讲 Run、配置字段或步骤答案；中途提示须计为有协助。新增 UI 专项检查：能找到开始处理、
理解当前等待对象、直接修改参数、区分历史只读与当前编辑、追踪跨层连线和找到输出。它们融入既有 Journey，
不通过更换简单任务降低原门槛。

任何数据破坏、非法 Artifact、假完成、默认路径被迫用 JSON/终端、snapshot 被改写或绕过 Submit，直接失败，
不能用平均分抵消。作者操作者验收、合成 E2E、原生 Windows 检查与首次用户测试分栏记录，互不替代。

## 19. 交付物、风险与恢复

计划交付应用实现、合成图形/行为测试、生产截图、路由选型报告和统一验收记录；使用
[UI 验收记录](v0.3.1-ui-acceptance.md) 持续记录实施前门禁及各批次证据，不提前填通过。媒体/工程/日志留在仓库外。

| 风险 | 控制与恢复方式 |
| --- | --- |
| 重排组件导致草稿或命令绑定丢失 | 先锁定状态所有者再迁移视图；用精确绑定/迟到响应测试拦截 |
| 一次塞入太多“高级”内容 | 以任务和对象分配，必要错误/参数始终可见；首次用户测试纠正 |
| 避障库大、慢或许可证不适合 | 实施前有界试验，选一种路径；不引入未经核对依赖 |
| 路由失效漏算、拖动再次消失 | 保留测量缓存与可见性断言，覆盖无关障碍移动及 stale solve |
| 跨分辨率布局失效 | CSS 空间和真实 DPI 分测，保留可返回详情布局，不强撑所有面板 |
| 外部流程因“少点击”被合并 | 保留独立确认/检查/Submit，重新运行完整真实服务合成闭环 |
| 打包后与源码不同或旧服务仍在 | 检查包内代码/生产资源对应提交；明确退出旧服务再测试，不能把刷新当升级 |
| 缺首次用户或原生测试证据 | 交付“技术候选可测试、相关门槛待验”，不假称阶段/正式产品完成 |

实施中的恢复优先为正常修复或经授权的可追踪 revert，不使用 reset --hard、覆盖用户改动或清空工程数据。
如果候选有阻塞缺陷，只能回退到明确支持 schema 4、工程数据及当前 handoff 合同的指定基准候选，并先
核验其构建内容与已验证状态。更早的旧包不承诺可打开升级工程，不自动降级数据库、恢复过时备份或迁移媒体。
新 UI 不改变数据格式，回退也不得自动搬移/删除工程数据。
如出现必须修改存储/执行合同的需求，停止该扩张并列出决策，不把它藏进布局补丁。
