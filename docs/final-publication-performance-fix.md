# 成片直接发布与进度热路径修复

- 日期：2026-09-23；用户已批准实施。
- 开发线：`codex/chapter-batch-enhancement`；保持产品版本 `0.3.5`。
- 上位权威：[Graph Core](architecture/graph-core-baseline.md)；展示遵循
  [Studio UX](architecture/studio-ux-baseline.md)。
- 保留前一轮未提交的存储故障修复，不实施 UX-001–003 的整体界面改造。

## 1. 已确认的问题

最后的 OutputFile 是复制发布，不是再次编码。原实现每次进度 callback 都重建整个 Run 并校验历史成果关系；
进度持久化和返回值读取还会重复这项工作。真实工程只读采样中，单次绑定检查约 0.34–0.40 秒。
复制循环按 callback 开始前的时间限频，一旦 callback 比 250 ms 更慢，下一块又立即报告，最终几乎每
1 MiB 都同步重复整套读取。此开销不属于媒体正确性校验所需的逐块成本。

另外，旧流程先把最终封装结果登记在工作目录，再由 OutputFile 复制到正式位置，会产生完整成片的第二份副本。
已登记的上游 Artifact 不能直接搬走，否则其他分支与已完成结果复用失去原路径。

## 2. 本次实现边界

### 2.1 进度检查保持严格，但只检查当前尝试

- 每次采样仍确认 Run、NodeRun、attempt、最新尝试、running 和 automatic 的精确绑定。
- 持久化在同一事务内检查单调性，只更新当前 progress；不重新读取整次运行作为返回值。
- 不缓存另一份执行权威，不增加状态，不把 sample 当作媒体完成或成果登记。
- Graph 与全部成果关系仍在正式读取、运行准入和完成边界执行原有严格检查。
- 复制限频从 callback 返回后计时，首个样本与复制结束样本保留；不让慢 callback 使限频失效。

### 2.2 新流程在最终位置生成并发布

新增独立 exact `zniku.source-admitted.chapter-batch.final-publish@0.3.5`，不改变旧 final 定义。

1. 根据用户明确设置的输出位置及覆盖策略，检查输出边界和所有受保护输入。
2. 在最终目录内创建本次尝试独占的临时候选子目录；封装不移动或覆盖上游编码视频、源音轨。
3. 进程成功、候选非空、媒体识别和原 final 媒体合同全部通过后，再按覆盖策略发布正式名称。
4. 仅正式路径登记为 Artifact；新默认流程的 OutputFile 使用 `reference`，不再复制成片。

候选区位于最终目录内，发布不跨卷，不依赖“同一台 NAS 必然同卷”的假设，不增加 hardlink/reflink 平台依赖。
无覆盖模式不得覆盖竞争出现的目标；覆盖模式也必须先验收候选。失败保留候选和用户文件，不自动清理。
文件发布和 SQLite 成果登记不是跨系统原子事务：若已发布而登记失败，必须报告事实并保留文件，
不能伪造 completed、自动认领文件或在下一次重跑中静默覆盖。

强制路径保护覆盖全部直接输入和显式 `protected_paths`，不宣称递归审计整个工程的历史祖先文件。
默认始终不覆盖；高级用户显式改成片目录、目标与覆盖策略时仍须核对自己的目标。
Runtime 的登记异常提示仅陈述本次 Runner 已声明的文件和“登记未确认”，不按媒体业务名称判断，
也不把文件存在升级为完成证据；若事务已经提交但后续读取失败，保留真实 `completed` 状态。

### 2.3 展示真实复制状态

只有正式节点确实执行复制且提供 bytes 测量时，才显示复制语义、已复制/总容量与有依据的步骤平均速度。
字节到达 100% 而 NodeRun 仍 running 时，显示等待完成确认，不宣称已完成，也不猜测具体检查阶段。
其他节点及无测量样本保持原有真实、不确定进度规则。

## 3. 旧工程与现场处理

- 旧 Graph、NodeDefinition、Run snapshot、Artifact 路径不自动迁移；已有 final.mkv 不直接移动。
- 旧 copy 节点获得实现层性能修复，不改变复制、覆盖、保护源和验收含义。
- 候选包独立构建；不能在运行中替换服务文件或强行接管旧进程。
- 如需更换现场程序，先确认旧处理停止并备份工程；任何失败仅创建新 attempt 从头重跑发布，
  已完成增强、FI、编码和封装继续复用。旧 partial 不静默删除或覆盖。
- 本次不包含 commit/push、PR、tag 或 Release。

## 4. 验证门槛

- 进度错误绑定、换代、终态、manual 节点、非法/回退 sample 仍 fail closed；查询量不随历史成果扩大，
  不调用全 Run/历史路径检查；慢 callback 不导致每个块都报告。
- 新旧 exact 定义隔离；旧模板与旧工程不被改写。
- 同目录候选发布、目标竞争、覆盖显式、路径/输入保护、媒体验收失败、发布失败、登记失败的保留语义。
- 合成媒体完整处理到新正式输出路径，确认没有第二份整片复制；复用及原音轨/帧数合同保持。
- Python、Studio、类型/质量、一致性、相关浏览器门禁及候选包精确内容审计。

### 5.1 有界性能对照

同一真实工程、只读 SQLite 连接、未启用 profiler，当前绑定检查三次测量：

- 修复前：396、338、349 ms。
- 修复后：5.45、1.61、1.15 ms。

这些数字仅表示当前绑定检查开销，不等于 NAS 实际复制吞吐量；这组测量未对真实工程做写入基准，
也没有把新代码注入仍运行的旧包。完整媒体检查未因此移除。
