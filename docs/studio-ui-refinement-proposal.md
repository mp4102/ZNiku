# ZNIKU Studio 界面与交互收敛提案

- 日期：2026-09-08
- 状态：设计建议，待审阅；不是新增正式架构基线，也不代表已实现。
- 归属：现有 v0.3.0 创作者体验收敛，不重开一套 Phase 编号，不改变版本号。
- 上位约束：`architecture/graph-core-baseline.md`；下位约束：`architecture/studio-ux-baseline.md`。
- 本轮范围：只读界面与代码审计、官网研究、布局示意；不修改应用实现或真实工程，不启动媒体处理。

## 1. 结论

选择“画布优先的专业工作区 + 精简常驻布局 + 按任务渐进展开”。

不选择全部面板常驻的丰富布局，也不选择隐藏自由画布的简易向导。功能应丰富，但当前屏幕只突出正在进行的
任务。折叠技术细节，不折叠失败、必要参数、执行关系和下一步操作。

真实端到端结果证明已测试的媒体主路径基本可用，不等于首次用户易用性已经达标。本轮问题主要是任务职责、
信息层级和图形几何没有收敛，不是用户不会操作，也不是缺一套新的 Runtime。

## 2. 已观察到的问题

| 区域 | 当前事实 | 影响 |
| --- | --- | --- |
| 顶部 | 退出、工程数据、撤销重做、模式、首页、向导、打开、保存、开发入口并列 | 工程管理、编辑、处理、开发没有层级 |
| 处理区 | 历史选择、主操作、局部执行、重跑与服务通道放在一起 | 第一次使用需要先学习 Run 的内部概念 |
| 画布底部 | 历史 Run 范围与完成数以 absolute 浮层覆盖当前图 | 挡住节点，还容易将历史结果误读为当前图状态 |
| 右侧 | 输出及媒体详情、日志、预览、展示设置、输入排序排在参数之前 | 想改参数却要先穿过运行报告 |
| 节点卡片 | 高级显示含大段 JSON 摘要、英文内部身份，卡片高度差异明显 | 适应画布后字体过小，图的结构退居其次 |
| 连线 | 已使用 smoothstep，但没有把其他节点作为障碍物；布局为固定层级网格 | 长跨层边穿过其他节点，交叉与真实汇合难区分 |

现场页面处于高级显示模式：`查看 Run` 与 UUID 的显示受到该模式控制，不能声称创作者模式文案也完全相同。
但高级模式也不应默认把所有日志铺开；参数精度和排错密度是两种不同需求。

主要代码位置：

- `apps/studio/src/studio/components/ProjectShell.tsx`：顶部操作分组。
- `apps/studio/src/studio/components/RunCenter.tsx`：主操作、历史与高级运行命令。
- `apps/studio/src/studio/components/NodeInspector.tsx`：运行内容、文件与设置排序。
- `apps/studio/src/styles.css`：`.canvas-run-overlays` 的绝对定位遮挡。
- `apps/studio/src/studio/StudioWorkspace.tsx`：smoothstep 边投影及当前图/历史记录绑定。
- `apps/studio/src/studio/graph.ts`：固定 rank/row 间距的自动布局。

## 4. 推荐工作区

### 4.1 顶部：一排工程工具，一个上下文主操作

建议排列：工程菜单 / 工程名与保存状态 / 撤销与重做 / 处理记录 / 上下文主操作。

- 工程菜单收纳新建、打开、最近工程、工程数据、返回首页、退出。
- 保存状态明确区分已保存、尚未保存、保存失败；参数未应用单独提示。保留显式保存与快捷键，但不常驻
  一个长期禁用、又让人误以为不会自动保存的按钮。
- 工具库和模板归添加节点入口。向导在新建与未完成准备时突出，不在已完成工程中持续抢占主位。
- 高级节点图放入视图菜单，始终可达；开发信息进入专门诊断入口，不与创作按钮并列。
- 主操作依可信上下文为开始处理、查看进度、处理外部文件、查看问题或查看输出。中止等危险操作仍明确可达，
  但不与正常推进同等强调。
- 已完成历史与已变更当前图同时存在时，分开写“上次处理已完成”“当前设置已改变”，不得合成一个含糊状态。

### 4.2 中间：画布是主要工作区域

- 左侧工具库可展开、可固定；画布上保留带文字的“添加节点”，不能把添加能力只藏在图标、右键或快捷键中。
- 画布工具只提供添加、查找、视图与整理。复制、删除、批量添加下一步归选中对象工具，保留键盘等价入口。
- 节点卡默认只显示名称、两三项人类可读摘要、端口与状态。对象/数组不再原样 stringify 到卡片。
- 用户需要的特殊参数仍能展开，required 或非法的隐藏字段必须自动显露。
- 分组只改变显示。一般自由图不强制 A/B 章节；模板展示标签从 Python 提供，不从文件名推导身份。
- 自动整理是用户主动操作，可 Undo；拖动节点不会触发全图自动重排。

### 4.3 右侧：只回答选中对象的问题

固定页签为“设置 / 文件 / 诊断”，保持位置稳定，不因轮询自动切换用户正在编辑的页签。

**设置**：标题与别名、基础参数、有序输入（适用时）、高级参数。单位紧邻数值；宽高、帧率、枚举和分章方式
使用业务语言，不暴露 `mode: exact_frames`、`项目 1`、原始对象作为默认控件说明。所有解释仍来自正式
Schema 与 Python Presentation，不在 TypeScript 重写业务合法性。

“应用设置 / 放弃更改”固定在设置页底部，并占据布局空间；未应用更改要明确提示。离开节点仍按现有合同
处理，不能自动应用或静默丢弃。

**文件**：输入、要求、外部收件与可用输出。普通节点只显示适用内容；外部等待时点击主操作直接定位对应节点
的文件页，展示“打开输入 → 放入/选择处理好的文件 → 检查 → 显式提交”。多个任务必须指明 A/B 或实例名，
不能凭文件名自动决定归属。

**诊断**：稳定错误、完整精确参数/合同、ID、日志与媒体原始信息。正常模式切换不自动展开全部内容；默认错误
摘要与修复动作不能因为诊断折叠而消失。整个 Run 的放弃操作归处理任务，不放在某个节点设置末尾。

画面预览按需从文件页打开，不新建常驻视频监看器，也不扩展为 NLE。

### 4.4 底部：占位的处理任务抽屉，不是画布浮层

- 收起时为约 32–36 CSS px 的布局行；它位于画布外，不与缩放工具、小地图或节点重叠。
- 显示本次状态、已完成步骤数、需要操作的数量。没有活动任务时写“上次处理已完成”，不常驻 100% 大进度条。
- 展开后从布局中分配高度，画布相应缩小；支持调整高度、关闭与焦点返回，不能盖住画布。
- 页签为当前处理、历史记录、问题；完整历史分页也归这里，而不藏在问题面板末尾。
- 历史项用时间、范围、结果、人类说明标识；ID 在详情中复制。选历史时明确“历史流程，只读”，并有显眼的
  “返回当前编辑”。选择历史不得偷偷改写当前工程。
- 自动节点百分比仅显示实测值；人工步骤只显示等待与交接状态。“完成 5/12 步”不能解释成媒体完成 42%。
- 当前图只显示与其对应的可信有效性投影；旧 snapshot 结果不能不加说明地当作当前图的完成状态。

## 5. 运行语言与命令归属

| 当前表达 | 推荐用户表达 / 位置 | 不得改变的语义 |
| --- | --- | --- |
| 查看 Run | 处理记录；任务抽屉的历史页 | 浏览已存在的 Run，不是执行 |
| Run all | 开始处理整个工作流；正常主操作 | 同一 Python 完整运行校验 |
| Run to here | 处理到此步骤；选中节点上下文 | 依赖仍需执行或复用，不承诺只运行单个节点 |
| Rerun from here | 从此步骤重新处理；明确影响预览 | 创建新 attempt，从头执行；不暗示内部断点续跑 |
| Run snapshot | 本次/历史处理使用的流程（只读） | 原 snapshot 不被编辑改写 |
| stale | 设置或输入已改变，需要重新处理 | 解释服务端结论，不增加 UI 失效判定 |
| Abandon Run | 放弃本次处理；任务级危险操作 | 保留已有媒体，不表示删除工程 |

“高级运行操作”不再作为一个混装区。常用局部处理应有直白名称与位置；内部名仅在诊断中补充。

## 6. 连线可读性：必须同时改几何、视觉与交互

现有线已经是圆角正交形式。缺的是障碍物感知，不是换一种线型。

1. **真实几何**：使用测量后的节点矩形、端口位置、折叠高度和安全边距；修复多端口锚点可能超出卡片的
   布局问题，不继续假设所有卡片等高。
2. **自动布局**：按依赖层级、分支与真实尺寸分配通道，减小交叉；同时保留用户手动位置，只有显式整理才改。
3. **避障走线**：对边计算绕开无关节点的路径。采用有界路由与增量缓存；拖动保持连贯，落下后完成精确整理，
   不每一帧全图求解。算法与库选型先用合成复杂图做性能试验，不在此文宣称已确定最优库。
4. **选中强调**：悬停或键盘选择节点/端口时突出直连路径，必要时可查看上游/下游链；其余线降低权重但不能
   完全不可见。线端有方向，端口名称可见，不能仅靠颜色区别。
5. **交叉不是汇合**：交叉处采用可辨识的断口或跨线样式；真实汇合只发生在端口，不为交叉凭空画连接圆点。
6. **专家整理**：后续可提供手动走线控制点。它不是可执行 Reroute 节点，不生成新 Edge，不改变 ordinal。
   持久化之前必须明确严格的 UI-only edge-view 合同与兼容策略，不能随意往 Graph 塞未知字段。

不承诺任意图完全没有线与线交叉：非平面拓扑和任意用户位置不一定可实现。可验收目标是有可用通道的布局中
连线不穿过无关节点，交叉不被误读为连接，选中后能可靠追踪来源和目标。节点重叠、端口被包围等无解情况应
提示整理并提供可见降级路径，不静默断线、移动节点或篡改连接。

## 7. 视觉与尺寸

- 保留专业、克制的品牌；减少三重卡片边框、重复标题和无任务价值的全大写英文眉题。
- 常态节点用中性表面；品牌强调色留给选中与主操作，状态色配文字，不铺满画布。
- 右栏目标宽度约 320–380 CSS px，可调；左库约 240–280 CSS px，按需固定。这些是原型试验值，不是未经
  测试的冻结常数。图空间不足时先收左库，不缩小文字来保留全部面板。
- 宽屏允许固定更多信息，但应是用户主动选择，不另建“丰富版 Graph”。高 DPI 按 CSS 空间处理，不按物理
  分辨率机械决定密度。
- 核心控件支持键盘、焦点恢复、200% 缩放与 reduced motion。缩放到全图后摘要可收敛，但选中节点详情不能
  丢失；不能以极小字号伪装为“全部可见”。

## 8. 实施建议：按交付批次，不新增另一套架构阶段

| 批次 | 交付 | 门禁 |
| --- | --- | --- |
| 第一批：信息职责 | 顶部归类、任务语言、占位抽屉、右栏页签、当前/历史上下文分离 | 原命令资格不变；无画布遮挡；参数与交接主路径可直达 |
| 第二批：图形可读性 | 卡片摘要、端口几何、选中路径、尺寸感知布局与避障线 | 合成跨层/多端口/交叉/分支图，拖动可见，Undo 与保存重开正确 |
| 第三批：创作者验收 | 外部交接细节、错误恢复、DPI/键盘/性能与真实首次用户测试 | 原 Core/Runtime 回归；Studio typecheck/test/build/production E2E；正式首次用户门槛 |

优先关闭五个已报告问题，不在本轮扩张账户、云端、插件市场、完整剪辑器、工程媒体删除系统或新 Runtime。
此前工程数据实现的未提交改动保持原状，本提案不替它们重新验收，也不自动提交/推送。

## 9. 验收要看行为，而不是“看起来更简洁”

1. 1366×768、1920×1080 与高 DPI/200% 缩放下，任务条、主操作和节点设置不互相遮挡。
2. 第一次用户能指出如何开始、现在等谁操作、如何查看成品，无需解释 Run/NodeRun/Artifact。
3. 选中可配置节点，无须滚过日志即可访问基础参数；非法高级字段会显露，应用/放弃行为不变。
4. 浏览旧记录后能识别只读上下文；当前图有改动不会错误宣称已经完成。
5. 标准非重叠测试图中，路由对无关节点矩形交点为零；多端口位于正确边界，拖动与尺寸变化后重新验证。
6. 无法完全消除的线交叉仍可追踪；走线改变不改变端口绑定、ordinal、参数、reuse/stale 或历史 snapshot。
7. 50 节点常用交互继续达到现有 p95 ≤150 ms 目标；200 节点/1000 条历史不无界加载或冻结界面。
8. 外部文件仍显式确认、检查与 Submit；没有假百分比、误覆盖、自动执行或数据丢失。
9. 保留现有基线五名首次目标用户、25 个代表任务至少 23 个完成等门槛；作者全链路验收不代替首次用户证据。

## 10. 本次建议待审阅的取舍

- 是否采用上述一排顶栏、单一节点 Inspector、占位任务抽屉的主布局。
- 是否将高级视图和日志展开解耦：高级精确工具保留，但不一键铺开所有技术信息。
- 是否将持久手动走线点放在自动避障之后，先不扩大 UI 存储合同。

这些是展示与交互取舍，不重新讨论已冻结的自由 Graph、Runtime 或 AVEnhanceFlow 媒体流程。
