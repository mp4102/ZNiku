# v0.3.5 单一源媒体准入合同

本文件是执行备忘录的媒体节点实现说明，不改变 Graph Core、旧 exact definitions 或已保存工程。
规则参照 AVEnhanceFlow package **2.7.0** 的实际 `node_validation.py`、`video_signal.py`、`util.py`；
ZNIKU 不在运行时导入 AVEnhanceFlow，也不采用其任务文件、固定拓扑和目录命名要求。

## 职责与数据

- `source_admission.probe.admit_source`：先检查 header，再读取所需时间线，返回
  `SourceAdmission(header, timeline, frame_rate, signal, warnings, cadence)`。
- `SourceAdmission.namespace_summary`：提供已有下游可消费的有限信息结构，并记录新准入 profile。
  复用信息字段不代表执行过旧版 Source/SourceAligned 合同。
- `source_admission.timeline`：一次完整 packet 遍历建立 N；必要时增加 decoded best-effort 遍历。
- `source_admission.process`：有界、可取消的工具读取；使用 argv 和 `shell=False`。

输出包含实际 header、canonical FPS、packet N、信号工作解释、音轨 header、confidence 和警告。
不携带逐包记录、修复命令、内容摘要或能够恢复上次扫描的状态。

## 先检查 header

恰好一条视频，可以包含音频；未知 codec、非音视频轨道和容器内置 chapters 不支持。
要求正尺寸且 coded geometry 精确为 16:9，不限定 MP4/MKV 等后缀，也不要求年份目录。

`avg_frame_rate` 与 `r_frame_rate` 必须为正数，按相对容差 **2e-6** 比较，不要求字符串相同。
Source FPS 可在 **0.05%** 内吸附到 AV2.7 的常见广播有理帧率集合：24000/1001、24、25、
30000/1001、30、50、60000/1001、60、120000/1001、120。最终仍须与全片 cadence 等价。

色彩标签、SAR 和 field order 缺失或 unspecified 时，按唯一的 BT.709 SDR limited、left chroma、
progressive、1:1 SAR 工作域解释并警告；不因此失败，不要求额外确认。明确的 HDR、full-range、
非 BT.709、隔行、非方形像素、旋转或相互冲突的声明拒绝。标签解释不等于像素转换。

## 全片时钟与置信度

1. 完整读取主视频 packet 的 PTS/DTS 一次，packet count 是 N。
2. DTS 覆盖率至少 **99%** 且有至少2个有效时间戳时，采用 DTS；否则完整读取 decoded
   `best_effort_timestamp_time`。不混合两个时钟，不要求 raw PTS 等于 best-effort PTS。
3. 按所选时钟 `(样本数-1)/(末时刻-首时刻)` 计算跨度 FPS，再按同一广播集合吸附。
   稳定间隔容差为 `max(time_base*1.1, expected_period*3%, 2微秒)`。
4. 同时比较 avg、r、Source canonical 和 cadence FPS，相对容差仍为 **2e-6**。

| 条件 | high | medium（最低准入） |
| --- | --- | --- |
| packet N | 至少1000 | 正数且可形成至少2个时钟样本 |
| 稳定间隔比例 | 至少99.99% | 至少98% |
| 所选时钟样本数 / packet N | 至少99.9999% | 至少99% |
| 严格正向间隔比例 | 至少99.99% | 至少99% |
| 最大正向间隔 | 不超过1.5帧周期 | 不超过5帧周期 |
| 时钟跨度 FPS 对 cadence FPS 偏差 | 不超过0.1% | 不超过0.1% |

所有条件同时成立才准入。medium 以及缺失 PTS、部分时钟缺失等情况保留警告。
视频流 duration 优先于容器 duration；`N/FPS` 与其误差必须不超过 `max(2/FPS, 0.05秒)`。
不通过 duration 反推 N，不额外要求 header `nb_frames` 等于 packet N，也不要求 decoded 记录总数
等于 packet N；有效时钟覆盖、节奏、rate 和时长共同约束准入。

## 资源、进度与失败边界

由于 AV2.7 先从整片跨度确定 cadence、再统计相邻间隔，本实现把每个相邻差值作为8字节浮点数
写入 `TemporaryFile`，结束后以64 KiB块回读。它只是生命周期内的临时差值流：RAM 恒定、不含绝对
PTS/文件位置、不登记 Artifact、不成为 ledger 或恢复文件；成功、失败或取消均关闭并清理。
该回读不会再次遍历媒体。10万帧的差值约0.8 MB；DTS 不足时可能同时存在两条临时差值流。

FFprobe stdout 队列至多64行、单行至多64 KiB、stderr只保留有限尾部，header至多4 MiB。
header 预算60秒；每次完整遍历预算1小时。超时/非法输出失败，不自动改速或重试修改原片。
进度来自实际读到的媒体时间，并保留 fallback/统计区间；不是耗时预测。心跳保持已测量值，
不会随等待时间伪造增长。取消和 Runtime reporter 异常会终止工具并清理临时差值流。

## 可重跑验证

纯合成测试不依赖外部仓库、真实源或 FFmpeg：

```powershell
python -m pytest tests/test_source_admission_probe.py -q
python -m tools.check_source_admission_parity
```

可额外提供操作者明确信任的 AVEnhanceFlow 2.7.0 源码根目录：

```powershell
python -m tools.check_source_admission_parity --avenhanceflow-root '<AVEnhanceFlow源码目录>'
```

该工具仅导入纯函数并关闭外部源码 pycache 写入，不执行其 CLI、不打开媒体、不写任务。
固定63组：3种FPS（含27FPS非常规帧率）、3种帧数、7种正常/抖动/缺失/逆序/大间隔/漂移情况。
提供参照时逐项比较准入成败、confidence、覆盖率、跨度和 canonical cadence。

2026-09-15 已使用实际 AVEnhanceFlow 2.7.0 纯函数完成63组对照，结果一致（39组准入、24组拒绝）。
38项自包含测试通过；5个 Python 文件通过 Ruff/format、Windows和Linux目标 strict mypy。
合成测试覆盖
DTS边界、decoded fallback、原始PTS不同、缺失信号、header矛盾、取消、工具失败、临时流清理和进度。
这些是算法与集成前的工程证据，不是任何真实用户素材的准入或成片验收结论。

## 明确不证明什么

准入不证明原片无任何解码错误、所有帧都能被未来外部软件处理、音画主观同步或像素内容等价。
它不是完整 QC、hash、修复收据或外部模型验收。工具退出为零时的 stderr 不单独升级为全片证明门；
非零退出和合同失败仍拒绝。不会自动生成 CFR、补帧、丢帧、覆盖/备份/重命名原片。

外部修复候选要显式选择并经过同一准入；通过后作为新的处理参考，重新建立 N/FPS/音轨及下游规划。
不把外部报告当作免检凭据，也不声称候选与旧源内容等价。后续节点仍执行各自的输出存在、
可识别媒体、帧数和业务验证，旧 exact 工程不会被本模块静默放宽。
