## 2. 当前事实与问题判定

### 2.1 已经完成且不重做的能力

当前实现已经满足 0.2 Graph Core 的主要目标：

- 可以添加、删除、拖动、连接、复制、多选和组合当前 Project 中的节点；
- 支持多个 Source、零个或多个 Output、任意合法分支与汇合；
- typed ports、required input、单值 input、`ordered_many` ordinal 和 DAG 无环校验有效；
- 节点参数由 `NodeDefinition.parameter_schema` 约束；
- Graph、定义、Run、NodeRun、Artifact 和日志由 Python/Project Service 作为正式权威；
- automatic、command 和 manual external 节点能够通过同一 Runtime 执行；
- completed reuse、下游 stale、rerun-from-start 和应用重启后的 interrupted 语义已经验证；
- generic media smoke、AVEnhanceFlow v2.7.0 合成 E2E、真实 MR-off GUI 流程和最终成品已完成验收。

这些能力属于本次重构的回归红线，不以“改善体验”为由改写。

### 2.2 当前 Studio 为什么仍不是目标产品

当前 GUI 更接近“图形化 Runtime 工程控制台”，而不是面向视频编辑者的创作工具：

- 节点面板把 `type_id`、exact version、executor、端口数量作为主要信息；
- 节点卡片直接把技术 `node_id` 当成标题；
- 通用参数编辑依赖 raw JSON，并直接展示 `parameter_schema`；
- 新建和打开工程要求手写 `.zniku` 路径、Project ID 和 Project name；
- 模板向导暴露 Preparation、Expand、completed Run、canonical rational seconds 等内部概念；
- Run、snapshot、Artifact、waiting_external、readiness、stdout/stderr 和错误码占据主要界面；
- 未提供 Undo/Redo、节点别名、原生文件/目录选择、自动布局或轻量媒体预览；
- 禁用按钮通常没有稳定说明“为什么不能点”和“怎样恢复”；
- manual external 仍要求用户理解路径交接和协议状态，而不是完成一个被引导的外部处理任务。

Phase 5 证明了系统能正确完成工作，没有证明目标用户无需工程知识就会使用。v0.3.0 的完成判定必须从
“功能可运行”升级为“目标用户可独立完成”。

### 2.3 当前文档漂移

Phase 0 开始前，`README.md` 顶部仍写有“v0.2.1 Phase 0–3 已完成、Phase 4 待实施”和“向导尚未实现”，
与已经完成的 Phase 4–5 事实不一致。Phase 0 已同步修正该漂移，没有改写历史验收边界。

## 3. 产品定位与目标用户

### 3.1 第一目标用户

第一目标用户是具有普通视频处理知识、但不要求具备软件开发知识的视频编辑者。他们可以理解：

- 输入视频、输出目录；
- 分辨率、帧率、画质、编码器；
- 画面增强、补帧、章节和导出；
- 在 Topaz、Jasna 等外部工具中完成一次明确任务。

他们不应被要求理解：

- JSON、JSON Schema、UUID；
- `type_id`、definition version、executor、typed port、cardinality、ordinal；
- Run/NodeRun/Artifact identity、snapshot、stale reason；
- Python、npm、CLI、HTTP 服务或 stdout/stderr。

### 3.2 次要用户

- 高级操作者：需要自由调整节点图、查看精确媒体合同、选择局部重跑和诊断失败；
- Engine 开发者：需要核对 exact definition、ports、Schema、executor、validator 和完整日志。

高级能力必须保留，但不得成为第一目标用户完成正常任务的前置知识。

### 3.3 北极星任务

一名第一次接触 ZNIKU 的视频编辑者应能在不阅读仓库文档的情况下：

1. 双击启动 Studio；
2. 选择一个本机视频；
3. 选择“完整增强流程”或从空白工作流开始；
4. 修改三个常见参数；
5. 查看并自由调整生成的节点；
6. 开始处理并理解当前进度；
7. 按界面提示完成一次人工外部处理；
8. 识别并修复一次不合格外部产物；
9. 重新运行失败步骤，同时复用已经完成的上游；
10. 找到并打开最终成品。

正常路径中不得要求输入 raw JSON、绝对路径、Project ID、Run ID 或 Artifact ID，不得要求打开终端或阅读
stdout/stderr。

## 4. 已冻结的产品原则

1. **同一 Graph**：创作者模式和高级模式只改变信息密度，始终编辑同一 Project、同一 Graph 和同一参数。
2. **Python 仍是语义权威**：Schema、Graph 校验、模板规划、Runtime 状态和 validator 不在 TypeScript 重写。
3. **渐进披露**：默认只展示创作决策；技术身份、JSON、日志和完整诊断进入高级层。
4. **任务语言优先**：界面首先回答“现在发生什么、下一步做什么”，而不是首先暴露内部状态名。
5. **真实进度**：automatic 只显示可信测量；manual external 只显示等待、文件发现和验证状态，不伪造百分比。
6. **显式副作用**：覆盖、提交外部产物、重跑昂贵步骤和删除必须清楚说明影响。
7. **保留自由性**：模板只是创建普通 Graph 的快捷方式，生成后可以继续自由添加、删除、连接和配置节点。
8. **展示不影响执行**：名称、图标、分组、折叠、视口和模式切换不得导致 stale 或改变 Run snapshot。
9. **未知输入不猜测**：缺少展示元数据时安全回退；参数、Graph、状态和外部产物仍按原规则 fail closed。
10. **不以换皮冒充重构**：只改颜色、字号和按钮文字，而仍要求理解 JSON/Run/handoff，不算完成。

## 5. 权威关系与目标架构

```text
                     ZNIKU Studio 0.3.0
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
  创作者工作区         高级节点图          高级诊断
        └──────────────────┼──────────────────┘
                           │ 同一 Graph / ParameterDraft
                           ▼
               Project Service 0.3.0 wire
                  ┌────────┼────────┐
                  ▼        ▼        ▼
           Graph Core   Runtime   Presentation Catalog
                  │        │        │
                  └────────┼────────┘
                           ▼
                    同一 .zniku Project
```

| 内容 | 唯一权威 | Studio 的权限 |
| --- | --- | --- |
| Graph、节点、端口、边、DAG、required input、ordinal | Python Graph Core | 编辑、投影、即时辅助 |
| 参数类型、必填、枚举、范围、条件约束和默认值 | `NodeDefinition.parameter_schema` | 渲染表单、保存前即时提示 |
| 模板 Chapter/Leaf、动态端口和输出命名 | Python template service | 收集输入、展示 preview、发起 mutation |
| 节点执行、进度、复用、stale 和重跑资格 | Python Runtime/Project Service | 展示状态、发起正式 command |
| 节点名称、说明、图标、表单布局和单位 | `NodePresentation` | 正式消费，不反向定义语义 |
| 实例别名、分组、折叠、视口和面板布局 | `StudioState` | 编辑和保存，不进入执行签名 |
| 错误是否阻断 | Python diagnostic/Runtime state | 翻译为用户文案，不能改变结论 |

不恢复 Compiler、Freeze、领域级 Graph Revision、ExecutionPlan、canonical digest、Evidence 或第二套前端合同。
后文用于防止并发覆盖的 `storage_revision/ETag` 只是 Project Store 的乐观并发计数，不是不可变 Graph 版本，
也不构成新的运行权威。

## 6. 展示合同设计

### 6.1 PresentationCatalog

新增独立、严格、由 Python 定义并生成 Project Service JSON Schema 的展示目录。它通过
`type_id + definition_version` 精确绑定现有 NodeDefinition，但不成为 NodeDefinition 的一部分。

```text
PresentationCatalog
├─ contract_version = "0.3.0"
├─ locale = "zh-CN"
├─ categories[]
└─ nodes[]

NodePresentation
├─ type_id
├─ definition_version
├─ title
├─ description
├─ category_id
├─ icon_token
├─ palette_level
├─ keywords[]
├─ parameter_groups[]
├─ parameters[]
├─ ports[]
└─ card_summary_paths[]
```

约束：

- `title` 只是默认显示名，稳定身份始终是 `type_id@definition_version`；
- `icon_token` 只能引用 Studio 内置图标，不接受 SVG、HTML、脚本、文件路径或任意 URL；
- `palette_level` 只控制 `primary / secondary / advanced` 披露层级；
- `PortPresentation` 只能提供 `direction + port_id + label + description`；
- `data_type`、cardinality 和 required 必须从正式 `PortSpec` 读取；
- `card_summary_paths` 只能选择已有参数用于摘要，不能计算或改写值；
- Presentation 不进入 Graph、Run snapshot、execution signature 或 reuse/stale 判断；
- 仅修改名称、图标和帮助文本不要求提升 NodeDefinition version。

失败语义：

- 缺少第三方 Presentation：节点回退到通用 Schema/高级展示，Graph 仍可打开和运行；
- 找不到 exact definition：隔离该 Presentation，不猜测相近版本；
- 引用了未知参数或端口：隔离无效条目并显示非阻塞 Studio diagnostic；
- 内建 Presentation 有上述错误：CI 失败，不允许进入正式构建；
- Presentation 内容只按纯文本渲染，不执行 HTML 或脚本。

### 6.2 ParameterPresentation

```text
ParameterPresentation
├─ parameter_pointer       # RFC 6901 JSON Pointer
├─ label
├─ description (optional)
├─ group_id
├─ order
├─ importance              # primary / advanced
├─ control_hint
├─ unit (optional)
├─ placeholder (optional)
├─ enum_labels[]
└─ picker (optional)
```

`control_hint` 使用闭合集合，例如 `auto`、`text`、`textarea`、`integer`、`number`、`slider`、`switch`、
`select`、`radio`、`file_path`、`file_paths`、`directory_path` 和 `save_file`。

Presentation 明确禁止携带：

- required、default、minimum、maximum、pattern 或新的 enum 值；
- `visible_when` 等自定义业务表达式；
- 参数计算、值转换或命令模板；
- executable、argv、Python/JavaScript callback；
- 任何能改变 validator、executor 或媒体合同的内容。

字段合法性和条件显隐必须从正式 JSON Schema 解释。`enum_labels` 只能为已有 enum 值增加人类名称；
`picker` 的扩展名过滤只是界面提示，不代替媒体 probe 和 validator。

### 6.3 ParameterDraft

表单和高级 raw JSON 必须编辑同一份仅存在于当前 Studio session 的 `ParameterDraft`：

1. 选择节点时从 `NodeInstance.parameters` 创建副本；
2. 表单与 raw JSON 双向操作同一份 draft；
3. 不支持安全渲染的 Schema 局部明确回退到高级 JSON，不猜测；
4. 非法 draft 不写回 Graph；
5. 用户点击“应用设置”后才更新 NodeInstance parameters；
6. 正式应用后按现有规则使节点和下游 stale；
7. 离开节点且有未应用内容时，明确要求应用或放弃。

只使用 Schema 明示的 default，不根据控件、字段名或旧值推测业务默认值。隐藏的 required/非法高级字段必须
自动提升并显示，不能让用户面对没有原因的禁用按钮。

### 6.4 StudioState

实例别名和纯 UI 状态不得写入 parameters。在同一 `.zniku` SQLite 内建立独立 StudioState 表，并与
Project Core 在同一数据库事务中保存：

```text
StudioState
├─ contract_version = "0.3.0"
├─ viewport
├─ groups[]
└─ node_views[]

NodeViewState
├─ node_id
├─ display_name (optional)
├─ collapsed
└─ group_id (optional)

GroupViewState
├─ group_id
├─ title
├─ color_token
└─ collapsed
```

默认节点显示名按以下顺序解析：

```text
用户实例别名 → NodePresentation.title → type_id
```

约束：

- display name 不要求唯一；稳定身份始终是 node_id；
- 改名、分组、折叠、视口或颜色不改变参数、路径、executor 或输出命名；
- 创作者/高级模式属于本机用户偏好，不写入 Project；
- 选区、未应用 ParameterDraft、当前 Inspector tab 和临时错误属于 session，不写入 Project；
- 删除节点时清理对应 NodeViewState；复制节点生成新 node_id，可生成“副本”显示名；
- StudioState 加载损坏时回退默认布局并显示 warning，不得损坏或改写 Graph、Run 和 Artifact。

现有 `NodeInstance.ui_position` 在 v0.3.0 继续作为明确的非执行 Graph 字段保存，避免为纯 UX 重构搬迁已经稳定
的数据；新增别名、分组、折叠和视口进入 StudioState，绝不塞入 parameters。若持久化上述新增状态需要升级
`.zniku` SQLite schema，则采用 schema 3 和事务式 2→3 迁移。旧项目 Graph、definitions、历史 Run、Artifact
及 reuse/stale 结果必须保持不变；未知更高版本继续 fail closed。

### 6.5 展示操作与失效矩阵

| 操作 | Graph 执行内容变化 | 节点及下游 stale |
| --- | ---: | ---: |
| 修改 Presentation 文案或图标 | 否 | 否 |
| 切换创作者/高级模式 | 否 | 否 |
| 修改节点显示名、折叠或视口 | 否 | 否 |
| 移动节点 | 否 | 否 |
| 在选择器中取消 | 否 | 否 |
| 选择值但尚未应用 | 否 | 否 |
| 应用新的参数 | 是 | 是 |
| 修改入边或 definition version | 是 | 按现有 Core 规则 |
| 上游产生新 Artifact | 运行结果变化 | 按现有 Core 规则 |

## 7. 同一 Graph 的渐进披露

### 7.1 创作者模式（默认）

- 节点显示“导入视频”“画质增强”“补帧”“合并章节”“输出成片”等业务名称；
- 参数使用表单、下拉框、开关、数字输入、单位和路径选择按钮；
- 节点卡片只强调用途、关键参数、状态、进度和下一步；
- 端口显示“视频输入”“处理后视频”等名称；
- 主操作使用“开始处理”“继续外部处理”“检查并继续”“重新运行此步骤”“打开成品”；
- 默认隐藏 type/version、executor、raw JSON、ordinal、Artifact ID、Run ID 和 stdout/stderr；
- 阻塞问题必须说明发生了什么、保留了什么、用户现在该做什么。

### 7.2 高级模式

- 展示 exact type/version、typed ports、executor、raw JSON 和 Schema；
- 展示 Run、NodeRun、Artifact、handoff identity 和完整日志；
- 提供 Run all、Run to here、Rerun from here 和历史 snapshot 等精确控制；
- 允许编辑 raw JSON，但仍通过同一 ParameterDraft 和 Python 验证；
- 不提供绕过 Schema、跳过 Runtime 门禁、直接修改状态或执行任意命令的能力。

模式切换只能改变显示，不得更改 Graph JSON、参数、Run、Artifact、stale 或 Runtime command 资格。

## 8. 目标信息架构与关键流程

### 8.1 启动与工程首页

默认首页只提供：

- 新建视频工程；
- 打开已有工程；
- 最近工程；
- 服务不可用时的明确恢复操作。

Project ID 自动生成，默认不展示。开发浏览器模式可以在高级入口保留手工路径，但正式创作者路径必须通过
文件/目录选择器完成。

### 8.2 新建工程

```text
选择素材 → 选择处理目标/模板 → 设置常用选项 → 分析素材 → 确认工作流 → 开始处理
```

AVEnhanceFlow 的 Preparation、Expand、preparation Run binding、server preview 和第二 Run 继续真实存在，
但由 Studio 组织成上述用户流程。Python builder 仍负责 admitted facts、Chapter/Leaf、dynamic ports 和输出命名。

复杂 exact frame、encoder、MR 和模型信息进入“高级设置”，普通用户只看到对应业务问题。生成后仍得到普通
Graph，可继续自由编辑；自定义后的 Graph 不能继续伪称完全符合模板 profile。

### 8.3 自由画布

- 友好节点名、业务图标和关键参数摘要；
- 从端口拖线时只高亮兼容目标；
- 拖到空白处可选择“在这里添加下一步”，只推荐类型兼容节点；
- 提供自动布局、适应画布、缩放到选区和节点搜索；
- ordered_many 通过可拖动列表调整顺序，不要求输入 ordinal；
- 支持 Undo/Redo：添加、删除、移动、连接、断开、复制、参数应用、重排和批量宏；
- Undo/Redo 只修改当前 Project Graph，不回写历史 Run 或运行中的 snapshot；
- 常用批量操作作为一个 undo action。

### 8.4 参数 Inspector

默认只展示 primary 参数、推荐值说明和影响摘要；高级字段折叠。每个非法字段就地显示原因和恢复方式。
所有内建节点必须能通过图形表单完成合法配置，不能把 raw JSON 当作内建节点的正常入口。

### 8.5 运行中心

任一时刻只突出一个主操作：

| 当前状态 | 默认主操作 |
| --- | --- |
| 尚未运行且 Graph 合法 | 开始处理 |
| automatic 正在运行 | 查看当前进度 |
| waiting_external | 继续外部处理 |
| failed | 查看问题并重试此步骤 |
| completed | 查看输出 |
| Graph 不可运行 | 修复标出的设置/连接 |

Run all、Run to here、Rerun from here 和 Abandon Run 收入高级操作。运行汇总只显示完成步骤数和当前 automatic
节点可信进度，不把节点平均数伪装成媒体总体百分比。

### 8.6 外部处理助手

manual external 的创作者流程固定为：

```text
选中任务查看输入与要求 → 在外部工具处理 → 选择成品并确认导入（或按目标放置文件）
→ 检测目标文件 → 完整检查 → 显式提交并继续
```

助手应提供：

- 友好输入名和目标名；
- 打开目录、复制路径和外部工具提示；
- 输出容器、尺寸、FPS、帧数等检查清单；
- 只读 readiness 观察；
- “检查输出”和“提交并继续”两个清晰动作；
- 错误文件替换后的重新检查；
- 重试前说明哪些节点重跑、哪些 completed 上游复用。

文件存在只表示“已发现”，不得自动 Submit 或推进 NodeRun。最终仍按当前 handoff identity、目标路径、FFprobe
和节点 validator 完整重验。不得显示误导性等待倒计时，只显示已等待时间。

### 8.7 错误与诊断

默认错误卡片固定回答：

1. 发生了什么；
2. 哪些结果仍然保留；
3. 用户下一步应该做什么；
4. 如何定位到对应节点或字段。

稳定 Python code、原始 message 和 stdout/stderr 放在可展开高级详情。展示文案不能决定 blocking、retry、Submit
或 command 资格。未知错误码保留原始信息并保持失败关闭，不能吞掉错误。

### 8.8 媒体预览

v0.3.0 只提供受控的代表帧、处理前后静帧比较和“使用系统播放器打开”，不建设 Premiere/Resolve 式 NLE
时间线，也不在浏览器中加载完整长片。

Preview cache：

- 不登记为 Artifact；
- 不改变 Source；
- 不影响 reuse/stale；
- 不作为 QC 或模型效果证明；
- 只允许删除经过解析与校验的 preview cache 根；
- 不进入 `.zniku`、Git 或正式输出。

## 9. 本机文件能力与启动边界

普通浏览器 `<input type="file">` 无法可靠提供 Runtime 需要的本机绝对路径，把整部长片上传给浏览器再转交
Project Service 也不可接受。v0.3.0 必须先抽象 `HostBridge`：

```text
HostCapabilities
├─ open_file / open_files
├─ select_directory
├─ save_file
├─ reveal_in_file_manager
└─ open_with_system_player
```

Phase 0 用全部目标动作完成一个有界技术验证，然后在两种实现中冻结一种：

1. 薄 Windows WebView2/Python desktop shell；
2. loopback Project Service 显式触发的主机原生文件对话框代理。

Phase 0 已选择且只保留第二种路线。正式实现复用 launcher 管理的 Python loopback HTTP host；薄
WebView2/Python desktop shell 不进入 v0.3.0。依据与 prototype 证明边界见
[`architecture/host-bridge-prototype.md`](architecture/host-bridge-prototype.md)。

已冻结的产品决策是：**v0.3.0 正式支持 Windows 同机 loopback，开发时仍可使用普通浏览器；无论选择哪种实现，
最终必须做到双击启动和原生路径选择。**

HostBridge 约束：

- 只返回用户明确选择的运行主机路径，不上传或复制媒体；
- 用户取消无 Project、Graph、目录、Run 或 Artifact 副作用；
- 选择路径只更新 ParameterDraft，不代表文件已合法；
- 扩展名 filter 只是 UI 提示，正式验收仍由 Python 完成；
- 输出选择不提前创建、覆盖或删除目标；
- 不使用 shell 字符串打开对话框、目录或播放器；
- capability 不可用时明确降级，不伪装成功；
- v0.3.0 不向可信 LAN 暴露本机选择器或系统启动动作。

加入文件选择、打开目录和系统播放器能力后，loopback host 必须绑定 launcher 每次启动生成的随机 session
token，并限制精确 Studio Origin。它是本机误操作隔离，不扩张成账号、RBAC 或公网安全体系。

## 10. 保存、Draft 与并发决策

### 10.1 当前冲突

自由编辑时，新增节点尚未连接 required input、参数尚未填完是正常中间状态。当前 Studio 在 Graph 有
diagnostics 时禁止保存，Project Store 也只保存完全合法 Graph。这会使 Undo、自动保存、崩溃恢复和新用户
逐步搭建流程之间产生冲突。

### 10.2 已批准的窄幅基线修订方向

已冻结的方向是允许同一个 `Project.graph` 持久化“结构可解析但暂不可运行”的 authoring draft：

- Pydantic 模型、节点/边引用、字段类型和未知字段仍严格校验；
- `E_REQUIRED_INPUT_MISSING` 与由 JSON Schema `required` 关键字产生的缺参 diagnostic 可以随同一 Graph
  保存；其他 `E_PARAMETERS_INVALID` 不在 allowlist；
- Runtime 创建 Run 前仍必须通过完整且唯一的 Python Graph Validator；
- 不另存一张“可运行 Graph”，不建立隐形编译结果或第二套 authority；
- Studio 必须清晰显示“已保存，但还不能运行”及修复清单；
- 无法解析、未知 definition、非法 executor 等不可安全保留的输入仍 fail closed。

这项决策改变 0.2 基线的 Project 保存边界。Phase 0 已先把批准方向窄幅写入
`graph-core-baseline.md`，明确可保存 diagnostic 与不可保存错误的边界；正式持久化实现安排在 Phase 3，
不得暗中维护第二张 Graph，也不得超出已冻结 allowlist 放宽 Project Store。

### 10.3 Revision、Undo 与自动保存

按已批准的 authoring draft 决策：

- Project Store 增加单调 `storage_revision/ETag`，保存使用 compare-and-swap，迟到标签页不得覆盖新状态；
- valid/diagnosable 编辑采用 debounce + single-flight + latest-wins 自动保存；
- 拖动过程合并为一次保存和一次 undo action；
- 运行前强制 flush 最新可运行 Graph；
- 自动保存失败时保留本地 draft，显示可恢复错误，不谎报“已保存”；
- Undo/Redo 变化同样通过正常保存边界，不回写历史 Run；
- 参数仍采用显式“应用设置”，避免浏览控件时意外使昂贵结果 stale。

## 11. 明确非目标与范围红线

- 不重写 Scheduler、Node Runner、attempt、reuse/stale 或 rerun-from-start；
- 不把 AVEnhanceFlow 固化进 Runtime，也不新增固定全局拓扑；
- 不恢复 Compiler、Freeze、ExecutionPlan、Evidence、receipt、全局 checksum 或 full verification；
- 不建设 NLE 时间线、剪辑、调色、关键帧动画或完整代理播放系统；
- 不自动控制 Jasna、Topaz 等外部 GUI，也不伪造它们的内部进度；
- 不新增真实 MR/Enhancement/FI 算法或扩张 Engine 节点数量；
- 不允许插件注入任意 React、HTML 或 JavaScript 参数 UI；
- 不建设插件市场、账号、多用户、云协作、公网或 LAN 系统动作；
- 不让创作者模式形成第二个 Project、第二张 Graph 或第二份参数；
- 不为友好提示放宽媒体 validator、外部 Submit、覆盖或删除边界；
- 不把真实媒体、工程、日志、路径、preview cache、凭据或本机配置提交 Git；
- 不在完成目标用户验收前创建正式 tag 或 Release。

## 15. 风险与控制

### 15.1 Presentation 污染执行身份

风险：名称、图标或帮助文本加入 NodeDefinition 后，纯文案变化可能导致 definition 比较变化和结果 stale。

控制：Presentation 独立绑定，不进入 Run、Graph signature 或 reuse；相关不变式建立自动测试。

### 15.2 Schema renderer 猜错语义

风险：复杂 `oneOf/allOf/if/then/prefixItems` 被错误简化，导致字段丢失或错误默认值。

控制：先以全部内建 Schema 建 corpus；不支持的结构明确回退；Python 保存/运行重验永远保留。

### 15.3 Draft 保存形成第二套 Graph

风险：为保存未完成编辑而创建“隐藏可运行图”和“前端草稿图”。

控制：只允许同一 Project.graph 处于可运行或有 diagnostics 状态；Run 前同一 Python Validator 阻断。该变更
必须先修订基线。

### 15.4 Autosave 覆盖新状态

风险：多标签页、慢请求或拖动频繁写入导致旧响应覆盖新编辑。

控制：revision/CAS、single-flight、latest-wins、debounce、运行前 flush 和显式冲突，不自动覆盖。

### 15.5 HostBridge 扩大本机副作用

风险：任意网页调用 loopback 选择器、打开目录或播放器。

控制：仅 loopback、随机 session token、精确 Origin、显式用户点击、闭合 capability、argv/no-shell 和无 LAN
暴露。

### 15.6 外部半成品被提前提交

风险：文件刚出现仍在写入，UI 自动识别为完成。

控制：存在只显示“已发现”；可增加 size/mtime 稳定观察，但最后必须重新 probe、validator 和显式 Submit。

### 15.7 大 Graph 与长历史拖慢 GUI

风险：每次轮询或 render 全量扫描节点、边、Run 和日志。

控制：按 revision 增量读取、历史分页/聚合、预建索引、memoization、有界日志和 Phase 5 合成性能门禁；不因
UX 立即引入分布式状态或 WebSocket。

### 15.8 “简化”导致错误信息消失

风险：用户只看到友好文案却无法诊断未知问题。

控制：默认层给可操作解释，高级层永久保留稳定 code、原始 message、identity 和日志；未知错误不吞掉。

## 16. v0.3.0 完成定义

v0.3.0 只有同时满足以下条件才可称为 Acceptance Candidate：
