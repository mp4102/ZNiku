# v0.3.4 普通工作源：实现与验收记录

日期：2026-09-15。本文是实施记录，不是新的架构权威。
依据：[已批准收敛决策](v0.3.4-working-source-policy.md)。产品版本仍为 `0.3.4`，
开发分支为 `codex/v0.3.4`。批准收敛范围的实现与技术候选已完成；此状态不代表 Phase 5
真实外部验收、旧 T1 晋级或正式 Release 完成。

## 1. 用户能看到的变化

- 新工程默认普通工作源方案。检查给出可直接使用、需要工作副本或当前处理器不支持三种结论。
- 直接使用不复制原件。需要工作副本时，显示保帧、节奏/时长、音频、色彩和磁盘预算的影响。
- 缺色彩不是自动修复理由；明确选择 SDR 工作解释后可以继续，不伪装为原件实测声明。
- 内置 FFV1 重定时需明确确认，不覆盖原件，不自动补删帧，不是旧 T1 保内容修复。
- 外部新参考可以改变内容和帧数；先观察其实际属性，再决定工作解释，按新的 N 和音频来源规划。
- 外部候选已经合格、只有工作解释未确认时，只重新检查准入，复用已导入候选，不要求重交文件。
- 重试成功建立替代批次后，结束没有活动任务的旧失败批次，保留历史与产物；不让旧批次阻塞增强入口。
- 外部格式或目标率变化会产生新候选，旧候选的工作解释不能沿用；GUI 锁定准入重试设置，API 同样拒绝预授权。
- 旧严格保内容路线保留在高级兼容选择中；旧工程仍按原 exact 版本恢复，不自动迁移。

## 3. 检查和成本

普通源一次 FFprobe 调用合并全流帧/包读取，聚合帧数、展示时间、几何、工具色彩观察及音频信息。
报告最多保留有限属性变体，不保存全片逐帧账本。头读取和版本读取不是全片扫描。

| 路线 | 素材阶段完整扫描 |
| --- | --- |
| 直接使用 | 原件 1 次；准入不再完整扫描 |
| 内置 FFV1 | 原件 1 次、生成后候选 1 次；另有必需的 FFV1 编码过程 |
| 外部新参考 | 原件 1 次、提交时新候选 1 次；仅改准入解释不重扫候选 |
| 每个外部增强/FI 来件 | 对当前文件 1 次 N/PTS 检查；不因缺 `nb_frames` 再启动旧全片扫描 |

这些次数由执行回归检查，不是由日志阶段名称推测。仍保留头信息、轻量可读性与输出包检查，
不宣称整条工作流只有一次 I/O，也不拿短合成耗时估计长片性能。

Final 不再默认解码两遍整条音轨比较 PCM 摘要；核对所选轨道、相对起点、包数量、载荷总量与末端覆盖。
首包可选 duration 缺失不等于整条音轨坏了，缺少末端依据仍拒绝；原有音频尾差不自动裁剪或伸缩。
上述轻量检查不证明逐样本内容恒等，测试中的独立 PCM/framehash oracle 不进入产品默认运行。

工作副本预算按实际采样和位深估算未压缩像素量，加余量；显示为参考预算而非实际 FFV1 体积保证。
不再将所有输入一律按 6 字节/像素要求空间，也不默认生成整篇 4K ProRes。

内置重新定时使用固定的输入侧 `-r` 配合 `settb/setpts`、编码时间基和 passthrough；不是输出侧
补删帧同步。二者含义见 [FFmpeg 文档](https://www.ffmpeg.org/ffmpeg.html)。实际行为另以带 B 帧的
30→24 和 30→60000/1001 合成输入核对 N、PTS、文件声明及逐帧 oracle，不只依赖参数名称。
普通生成 MKV 对三项头帧率只容纳整数纳秒帧周期表示差；旧 30 fps 声明不能冒充目标 24 fps。

## 4. 不应误读的限制

- 当前主要处理范围仍是本地 MP4/MOV/MKV、支持的渐进方形像素 SDR 视频以及声明范围内的 AAC 音轨。
  HDR、已知色彩冲突/中途变化、解码错误或无法可靠解释的时间映射不由确认框覆盖。
- AAC priming/padding 的未支持组合是处理器能力限制，不是“原片损坏”；不偷偷转码或删除延迟信息。
- 16:9 是当前分章/增强预设的要求，不是通用 Source 或自由节点图的全局准入规则；预设在展开前检查。
- 外部源准备与 MR 不同：前者可更换 N/内容并重新规划；工作参考之后的 MR 仍需满足 N→N 对齐。
- 粗 time_base 不单独拒绝；实际帧时间严格对齐所选 FPS 时可用。非对齐、重复、逆序和帧数错误仍失败。
- 旧 T1 继续禁用，既有代表/留出失败事实不改写。普通重定时不冒称找回拍摄时钟或保留原播放节奏。
- 本轮不处理字幕/附件归档、音频格式转换、HDR 转换、真实 AI 画质、长片性能或 4K 真实全链路验收。
