# ZNIKU v0.3.6 自动化验证记录

本记录分开记录实现、合成验证和操作者验收，不把自动化通过等同于真实长片交付。
环境：Windows、Python 3.12.13、FFmpeg 8.1.2。仅使用新建合成目录；未改动真实工程、NAS 媒体或旧服务。

## Phase 1 / PERF-001

已实现：完整增强章直接引用，只创建邻章边界 part；对普通单轨、已知常量索引、已验证 rational FPS 的
ProRes MOV 使用有界 seek/读取停止。fractional FPS、首末帧、单帧区间及跨多个短邻章均有测试。
fragmented、非零 edit、未知索引/时钟等保留原安全路线；不扩大旧 exact 的接受集合。

三章各 600 帧、320×180、32 帧上下文的合成对照（媒体逻辑 AVIO，不是物理网络流量）：

| 指标 | 旧路线 | 快路径 |
| --- | ---: | ---: |
| 读取 | 77,029,245 B | 22,929,757 B |
| 写入 | 41,342,220 B | 22,626,651 B |
| 合计 | 118,371,465 B | 45,556,408 B |

逻辑读写减少 **61.51%**，全部输出 packet hash 等价。两轮短样本旧/新耗时为 0.810/0.780 s、
0.827/0.789 s；未清空 OS/NAS 缓存，不据此承诺长片加速倍数。
物理网络流量、NAS 峰值空间及长片耗时：未测量。正式 context 仍真实物化，未自动删除任何文件。

隔离暂存快照门禁：Python 专项 204 passed；mypy 238 files；Ruff/format、Schema 检查通过；
Studio typecheck、870 tests、production build 通过。进度 stage 为可选展示数据，旧响应无 stage 仍有效。
操作者真实验收：待 Phase 5。

## Phase 2 / PERF-002

已实现独立 `program-fused@0.3.6` / `final-publish-fused@0.3.6`，使用独立成果 namespace。
有序原始 FI 输入通过普通 Edge 直接进入融合节点；从已验收 metadata 重建各章半开区间，
单个顺序 concat 解码流按帧序号选择有效帧，重建 exact 时钟，只对全片末尾复制一帧，再连续编码一次。
选择表达式以平衡树写入 attempt 内受控 filter 文件，不受 Windows 命令行长度限制，也不并开一千个 decoder。
全片帧数、顺序、Main10 配方和原音轨封装沿用已有职责；不伪造裁边 Artifact。

新建向导需显式选择“0.3.6 融合编码候选（待验收）”，默认仍为已验收 0.3.5。
“额外导出裁后章节”默认关闭；开启后创建真实普通 Crop 分支，额外存储与 I/O 由界面说明。
已有工程、旧 exact producer/consumer 和历史 snapshot 不改写。

测试证据：

- 20 组逐帧 hash/PTS 对照覆盖四种源 FPS 的 2×、普通/异时基/fragmented/非零起始 PTS/等价小数 FPS。
- 实际执行 1,000 段顺序 concat 和平衡选择表达式，1,001 个结果帧的内容、顺序与时钟正确。
- 1/3/26/1,000 章、两种导出开关的 Graph 构造、保存/重开；旧图和旧接受集合保持不变。
- 12 帧、三章、带原音轨的真实合成媒体全链完成并可复用；可选 Crop 有真实文件和 Artifact。
- 故障/取消注入保留 raw，Program/Final 不登记部分成果；旧 Final 拒绝新 namespace。
- 融合默认分支未生成完整 crop/timescale MOV。实际 NAS 释放量与长片耗时仍未测量。

单遍 packet-copy 时基实验（FFmpeg 8.1.2，输入 timescale 12,000,000，短 ProRes）：

| 输出 FPS | 单遍帧/时钟等价 | 正式可选导出 |
| --- | --- | --- |
| 48、60 | 本轮合成通过 | 仍保留原安全双遍，不扩展为通用承诺 |
| 48000/1001、60000/1001 | 未通过 exact 时钟 oracle | 安全双遍通过 |

按有界实验止损：本版不启用单遍导出。融合编码不依赖该实验的成功。
隔离暂存快照：Python 两组 140 + 24 passed；mypy、Ruff/format、Schema、四组 corpus/preview 通过；
Studio 875 tests、typecheck、production build 通过。以上不是实际 Aion 或 GPU 长片验收。

后续远端漂移检查发现检入 corpus 的新增条目顺序不符，已使用原生成器完整重建并在 `96eadd5` 修正；
不是修改节点语义。所有后续门禁同时核对实际检入资产，不能只引用隔离快照通过。

## Phase 3 / DATA-001

已实现工程数据维护入口：按需扫描四类占用，默认不选文件，选中内部中转后必须勾选不可恢复并显式确认。
服务只接收短期票据及候选 ID，不接收任意删除路径。网络结果不明不自动重试，逐项报告删除/跳过/失败，
大小是逻辑字节，不声称 NAS 快照会同步释放物理空间。

清理资格只限已绑定 attempt 内、known-exact context/crop 产生的范围/时基中转。
新 `scratch-index.json` 仅记录相对位置、职责及低成本文件身份，是非权威维护提示：缺失或写失败只失去
清理资格，不阻断媒体完成，不成为 Artifact、receipt 或新执行权威。旧未知文件不按名称追认。
扫描对目录条目、深度、引用 JSON/ffconcat 均有预算；截断时整次预览不提供删除候选。

确认重验会话、版本、Run 终态、attempt 归属、索引/文件身份和所有正式引用；票据一次性且五分钟失效。
活动/等待 Run、外部来件、已登记历史成果、声明输出、日志、目录/文件链接、共享硬链接及未知文件均保留。
复用已有维护互斥，不重建 Runtime、不修改 Graph/Run/Artifact/Result，也不改变 reuse 结论。

合成测试包含缺失/变化身份、换会话/CAS、过期、预览中断、部分权限失败、一次性重放拒绝、历史引用、
ffconcat 合法空白与未知指令拒绝、有界空目录遍历及真实短 ProRes 索引 hook。
隔离暂存快照 Python 210 passed / 1 skipped；mypy 250 files、Ruff/format、Schema/corpus 通过；
Studio typecheck、886 tests、production build 通过。跳过项仅为 Windows 无符号链接创建权限，
已有模拟 reparse 及硬链接拒绝用例通过。没有执行真实数据清理。
