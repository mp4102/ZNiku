## 2. 验收目标与非目标

1. 普通用户选择平均章数（默认1）、多个`HH:MM:SS`时间点或多个精确帧点，最多999切点/1000章。
2. Python以 admitted N/FPS 生成确定的连续范围；899切点/1801帧得到899+902。
3. 叶增强后按章合并；FI使用明确的增强上下文输入，外部结果检查通过后由自动节点精确裁边。
4. 每个内部跨章插值时刻只保留一次；全片末尾单次补尾，最终2N@2fps且沿用原始音轨。
5. 不建立整片增强/FI ProRes必经文件；展示真实磁盘成本，产物长期保留。
6. 新旧工程、节点、收件与结果不串用；每次失败从头重跑，独立有效分支仍复用。
7. 仍是普通可编辑Graph；Studio只显示Python计算结果，Runtime不理解章/叶/FI。
8. 分叶独立设置最长1–60分钟、默认5；每章取最少叶数后均分。短章只有一叶，不补长、不跨章、不制造零碎尾叶。

不做黑屏识别、任意倍率FI、VFR自动修复、外部GUI自动化、pre_chaptered自动跨源上下文、
旧工程自动转换、媒体自动清理或Graph Core重构。不把新模型运行成本扩为本轮真实媒体授权。

### 4.1 Phase 1 独立预览合同

`POST /api/studio/templates/chapter-overlap-fi/preview` 仅接受：

- `contract_version="0.3.2"`；工程 `project_session_id`、`expected_storage_revision`、`preparation_run_id`。
- `settings.chapter_selector`：`average{count}` / `exact_frames{frames}` / `exact_times{times}`。
- `settings.leaf_max_minutes`：严格整数1–60，省略默认5；省略selector默认平均1章。

N/FPS只能从当前工程已完成、仍有效的admission/effective-video直接Artifact读取；核对current结果、
会话、存储计数、源和分析产物的存在/size/mtime，不接受浏览器自报probe、Graph、媒体范围或执行参数。
只读结果返回源Artifact身份、全部章/叶范围、原始/对齐切点、精确有理秒及显示时码，
`execution_available=false`；不写工程，不创建Run/attempt/目录，不解码媒体。
错误包含 `code/message/field_path/related_run_ids`，新域错误用独立0.3.2 envelope；HTTP语法/Origin等
共享传输失败仍用旧通用错误。旧客户端路由、wire0.3.0、exact definitions均不变。

JSON Schema由Python生成；Phase 1没有新生产定义或GUI字段，所以Presentation corpus保持原集合，不创建TS planner。
Phase 1当时没有公开`expand`入口；Phase 3新增独立完整请求，Phase 1旧预览请求不能据此展开。

### 4.1.1 Phase 3完整新链wire

`processing-preview`只验证用户设置；`full-preview`和`expand`共享严格0.3.2请求：
会话/CAS/明确preparation Run + `processing{settings,enhancement,fi_profile,program_encode}` + `publication`。
三个端点均位于`/api/studio/templates/chapter-overlap-fi/`；完整预览只返回Python规划/上下文投影及节点数，
不传第二张Graph。展开重新核对文件stat和分析结果，用一个Store事务保存普通Graph，返回旧0.3.0 Status。
仅纯preparation图可由向导展开；已有自定义或已展开图转普通节点编辑，不覆盖用户分支。

新`/api/studio/graph-save`只接受现有`SaveProjectCommand`，body上限32MiB，仍走同一command/CAS/GraphValidator。
旧`/command`仍为4MiB；超限在读取body前413。传输别名不新增Graph语义，模板参数请求仍4MiB。

### 4.2 分叶和规模预算

分叶公式与短章规则见合同§3.3。1–60分钟是用户输入范围；实际叶最短一帧，外部AI另有独立最短输入要求。
每章内 `cap=floor(FPS×60×L)`、`m=ceil(n/cap)`、`q,r=divmod(n,m)`；不以浮点或旧ties-to-even超出时长上限。
只读planner预算10000叶，先计数再分配，超限 `E_CHAPTER_PLAN_RESOURCE_LIMIT`；不静默截断，不改章数。
这个预算不是10000叶Graph可以通过现有传输、显示、Runtime启动的承诺。

现有4 MiB保存请求预算保持不变。Phase 1纯合成generic上游图测得：1000章×1叶约0.72MiB、×4叶约2.51MiB；
×10叶约6.07MiB，会413且不读取超限body、不改工程。Phase 3必须为完整新图实测并给出有界传输方案，
不能只凭planner通过就暴露无法保存的规模；也不能为本次前检全局无限增大HTTP上限。
