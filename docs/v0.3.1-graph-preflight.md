# v0.3.1 图形实施前试验报告

状态：§13 几何选型试验已执行；批次 B 的真实 GUI 验收尚未开始。记录日期：2026-09-09。

## 1. 结论与选型

采用“**实际尺寸的稳定分层排列 + 小型有界正交通道路由**”作为批次 B 的实施路径，继续使用 React Flow，
不新增图编辑器框架。本次已经运行的替代算法能修复指定合成图里的穿节点问题，新增依赖为零；不是把
smoothstep 改名，也不是声称任意图最优。ELK/dagre 不在本次引入；若后续真实布局质量不足，可再以相同
fixtures 量化比较，不能以库的名气替代门禁。

实施前门禁的结论是 **可进入实现**，不是“批次 B 已完成”。算法仍需移植为生产 TypeScript、接入实际测量、
细粒度失效和有限调度，再接受 DOM/浏览器/键盘/历史视图测试。试验不会把以下资源预算变成产品限制。

## 3. 基准与替代算法的真实差异

### 3.1 当前基准

- `src/studio/graph.ts:autoLayoutGraph`：镜像其 DAG rank + 原节点顺序，位置公式为
  `x=80+rank*360, y=100+row*280`。这里只镜像公开公式，不动态执行生产 TS；测试检测源公式漂移。
- `src/components/WorkflowNodeCard.tsx`：镜像当前百分比端口公式。
- 路径直接调用已锁定的 `@xyflow/react@12.11.3` 的 `getSmoothStepPath`，保留真实默认圆角半径 5 和
  offset 20。官方 API 接收端点与方向，没有障碍矩形参数；因此它本身不负责避开其他卡片。
  [React Flow 官方 API](https://reactflow.dev/api-reference/utils/get-smooth-step-path)

端口公式 `58 + (i-(n-1)/2)*22` 使用百分比，不是按卡片像素行排列：

| 每侧端口数 | 首尾百分比 | 每侧超出卡片的端口数 |
| --- | --- | --- |
| 1 | 58…58 | 0 |
| 2 | 47…69 | 0 |
| 6 | 3…113 | 1 |
| 8 | -19…135 | 3 |
| 16 | -107…223 | 11 |

G05 每组两张卡片，且每张同时有左右两侧，因此完整统计中的越界分别为 4/12/44。增大卡片高度无法修复
百分比超过 100%/小于 0% 的问题。高卡片也会突破当前 280 的固定行间距；G06-tall 有 1 对实际矩形重叠。
这里只记录，尚未修改生产卡片。

### 3.2 替代路径

1. 按同一 DAG rank、稳定原节点顺序排列；列宽取该列实际最大宽度，列间 144，纵向累计实际高度与 64 间距。
   这解决尺寸重叠，暂不实现全局最少交叉或最短总线长优化。
2. 端口输入模拟“已测量的端口行锚点”，落在真实矩形左右边界；它不是对当前 DOM 已完成测量的证据。
3. 每个障碍扩展 12 个几何单位，源/目标有明确向右出入口；提取矩形边界、锚点和外部通道组成压缩坐标格。
4. A* 只走未穿越矩形内部的水平/垂直格边，以 Manhattan 距离与稳定并列规则搜索；使用直角折线，暂不加
   圆角，避免先画圆角再漏算障碍。G08 同端口多边产生可区分的临时轨道，不保存 waypoint。
5. 端口被挡、通道/搜索/时间预算不足或不可达时，输出带明确 reason 的 smoothstep 降级线；端点仍来自
   **当前**正确锚点。无空路径、隐藏边、偷偷移动节点或改线；降级线可能穿障碍，绝不计作避障成功。

### 3.3 相交检查

对最终 SVG 的 M/L/Q 路径做独立审计。直线使用区间裁剪；二次曲线求矩形边界方程根，再在参数分区内判断，
不是稀疏采样。源/目标只豁免从/到正确锚点水平向右的首/末出入口段，其他回穿自己的路径仍检查。
碰撞数按“边–障碍矩形对”统计，不是像素数；沿扩展矩形边界的路线保持了原卡片 12 单位间距，允许通行。
测试单独覆盖细障碍、只触边、圆角相交和错误出入口，避免算法与审计共享同一个错误结论。

## 5. 预算、确定性、缓存与取消

试验默认上限：60,000 格点、单边 40,000 扩展、全图 400,000 扩展、单边 100 ms、全图 1,000 ms。它们是
隔离算法的安全天花板，**不是适合浏览器拖动的交互预算**；CI 正确性测量保留余量，避免机器负载导致误判。

搜索每 128 个扩展检查耗时，格图预处理逐障碍检查；内存/搜索量另有确定性硬上限。耗时截止是协作式检查，
不是硬实时抢占，单个 JS 操作、校验、GC 及平台调度仍可能越过截止。稳定并列规则保障资源充足时同输入路线
一致；接近时间上限时，负载不同可能改变降级时点，不能声称墙钟截止下的所有运行逐字一致。时间失败用可
注入时钟测试，而不是依赖机器刚好跑慢。

`GeometrySession` 当前仅保留一份几何缓存：无几何变化全命中；任何障碍变化全失效，所以 G07 中**无关**
节点移入通道也会重算。它验证安全下限，不是假装已经实现最优增量失效。批次 B 需建立“改变矩形及原路径
包围盒/端口”的相关性失效，保留对非邻接边的检测；普通进度响应不能重建几何求解。

异步票据测试覆盖当前视图与历史视图相同节点 ID、不同位置，旧结果拒绝，取消后拒绝，伪造/null 票据拒绝。
这只是纯函数模拟，不是生产 React 时序门禁，也没有模拟真实 Undo/保存副作用。当前同步实验不能在中途
响应浏览器取消事件；真正接入时必须合并请求并检查视图+几何版本，不能维护无界旧任务队列。

批次 B 的执行建议：先接入主线程有界轻量路径更新，落下后一次完整求解；不在每次 pointermove 全图重算，
不把 1 秒安全天花板搬进交互。以 50/200 节点实际 DOM 测量决定 8–12 ms 轻量切片和约 32 ms 完整计算预算
是否足够；这些数值是待校准起点，不是本报告已验证的 GUI SLA。若真实 p95/输入响应或取消不能达标，就转
单 Worker + 最新请求覆盖/版本拒绝方案，不能以重试队列掩盖卡顿。

## 6. 官方库核查与没有选择它们的原因

仅核查官方项目文档/许可证及官方 npm 发布元数据，没有下载/安装新的库，没有把未实测的库排出性能名次。

| 方案 | 官方能力/维护边界 | 许可与依赖元数据 | 此次决定 |
| --- | --- | --- | --- |
| 既有 smoothstep | 端点路径函数；不接收障碍 | 既有 React Flow MIT 依赖 | 保留基准与明确降级，不作避障 |
| dagre | 有向图尺寸布局；React Flow 官方将其与 edge routing 区分 | @dagrejs/dagre 3.1.1：MIT，直接依赖 @dagrejs/graphlib 4.0.5 | 没有解决任意手动位置的独立避障需求，暂不加第二个布局依赖 |
| ELK/elkjs | 有层级/端口布局，支持 Worker；不是编辑器；独立 edge routing 仍有专门问题边界 | elkjs 0.12.0：包元数据 EPL-2.0 OR GPL-3.0-or-later；官方 LICENSE.md 为 EPL-2.0，未声明普通 dependencies | 能力强但仍需适配、几何版本与取消设计；暂不引入 |
| 本次受限算法 | 尺寸排列 + 手动位置通道避障 + 固定预算，维护范围自行掌控 | 仓库内原创实验，无新增第三方依赖；本轮不新增或变更仓库许可 | 有实际夹具/相交/时间证据，作为本版实施路径 |

## 7. 批次 B 仍须补齐的验收

1. 实际卡片行、字体/长标题/错误/折叠/缩放后的 DOM 测量与正确 anchor，保留现有拖动 identity 修复。
2. 50/200 节点真实拖动、选择、参数输入 p95；测量读取/求解/绘制分开记录，不仅记录算法时间。
3. 限定最新任务队列、落下后重算、非邻接障碍失效、旧 Run 与当前图同 ID 的真实 React 迟到响应隔离。
4. 一次拖动/整理只有一次 Undo/保存；取消整理不提交历史位置。选择/未应用草稿/参数/边/ordinal/Run snapshot
   保持不变，reuse/stale 结论不变，使用正式服务证据验证，不能从纯投影测试推导。
5. 降级样式、原因、正确当前端点可见；边交叉跨线/断口、方向、焦点高亮和多边顺序提示，不能画成真实汇合。
6. 1000 条历史的有界服务查询与 UI 展示，窄窗口、125%/150% 高 DPI、键盘和可访问性。
7. 新生产实现接入后更新基准漂移门禁，保留旧算法参照和对照报告；不能让“独立实验通过”长期掩盖生产回归。

本报告不变更 Graph Core、Studio UX 正式语义、产品版本、Run 验收或尚未完成的首次用户门槛。
