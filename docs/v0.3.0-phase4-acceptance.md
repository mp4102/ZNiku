## 1. 创作者运行中心

同一个 Studio 工作区按当前正式状态突出上下文主操作：开始处理、查看进度、继续外部处理、查看问题并重试、
查看输出或修复设置。创作者层使用任务名称、中文状态和友好节点名；精确 Run all、Run to here、Rerun from
here、Abandon Run、Run identity、snapshot 和原始日志保留在高级节点图／高级诊断，不删除既有自由图能力。

- Run 历史以时间、目标及结果呈现，仍精确绑定原 Run；旧记录不会被当前 Graph 编辑或别名修改回写；
- automatic 使用现有 current／total／unit 或 fraction，没有可信测量时显示不确定进度；
- 完成步骤数与当前节点进度分开显示，不把节点平均数包装成媒体总体百分比；
- manual external 只显示已等待时间、文件观察与检查状态，不显示百分比、ETA 或等待倒计时；
- 问题卡片说明原因、影响、保留的结果、恢复建议和定位动作。稳定错误码、原始 message 及有界日志仍可
  在高级诊断中查阅；未知错误使用安全通用提示，不猜测成功、修改 blocking 或授予 command 资格；
- 禁用动作提供原因与恢复入口；服务离线保留最后可信内容，但不能冒充当前已连接或已完成；
- 日志按精确 Run／NodeRun 定向读取，只在高级层或诊断打开时加载，不随默认状态轮询反复拉取。

这些变化只调整展示和用户操作组织，不新增 Runtime 状态机，也不改变 Graph、attempt、reuse 或 stale。

## 2. 外部处理助手与失败边界

助手把同一个正式 handoff 组织为以下步骤：

1. 查看节点的输出要求和检查清单；
2. 使用正式 HostBridge 引用打开输入／工作目录，或按需复制路径；
3. 在操作者选择的外部工具中完成处理；
4. 检测目标文件，仅显示缺失、空文件或已发现；
5. 显式选择“检查输出”，调用 Python 的完整 probe 与节点 validator；
6. 确认外部工具已完成写入后，显式选择“提交并继续”。

### 交付说明来自 Python

`RunDetailEnvelope.handoff_contracts` 继续绑定原 Run snapshot、最新 waiting NodeRun、handoff 及已登记输入
Artifact。AVEnhanceFlow v2.7.0 使用既有专用合同；本阶段补齐普通媒体 Transform 和其他 manual 插件的纯文本
投影，不让 React 解释或计算媒体约束。

普通 Transform 展示参数中明确声明的工具／模型、可选尺寸、FPS 和帧数关系。帧数关系解析与正式媒体 validator
共用同一 Python helper；generic FI 的既有 `N → 2N` 与 AV27 FI 的 `N → 2N-1` 各自保持其 exact definition
合同，不相互替换。未知插件只展示声明和节点 validator 边界，不冒认内建媒体规则。

### 检查不等于提交

- 文件存在不代表合格，不会自动 Submit，也不会登记 Artifact 或推进 NodeRun；
- 完整检查仅产生当前页面的只读观测。size／mtime 只用于撤销过期按钮资格，不是验收凭据或媒体身份；
- 输入、目标和响应必须匹配当前 Run／NodeRun／handoff 及 server-declared output targets；迟到或串线响应
  不得进入另一项任务；
- 失败文件被替换后必须重新检查。点击提交时页面再次完整预检，并核对与上次显式检查的文件观测是否一致；
  文件变化或检查失败则取消本次提交，要求用户重新检查并再次明确确认；
- 真正的 Submit command 仍由 Runtime 再次验证精确 handoff identity、输出文件、FFprobe 和节点 validator；
  前端按钮与预检结果不能跳过它；
- 检查失败说明与被动文件观察分开保存，后续“已发现”不会悄悄抹掉上次完整检查失败的原因；
- 路径／目录动作复用 Phase 2 的有限 HostBridge，不增加任意 raw path、shell 或可执行命令 authority。

## 3. 重试影响的正式只读投影

新增 `POST /api/studio/rerun-preview`，严格复用 `RerunFromHereCommand` 请求形状：

| 请求字段 | 用途 |
| --- | --- |
| `operation = "rerun_from_here"` | 与正式重跑意图一致；该 route 只预览、不执行 command |
| `run_id`／`node_id` | 指定原 Run 及其执行闭包内的节点 |
| `project_session_id` | 拒绝已关闭、重开或切换工程的旧页面 |
| `expected_storage_revision` | 绑定用户已保存并确认的当前 Graph |

请求与已有 command 一致，不携带 `contract_version`；额外字段、错误类型和未知 operation 均拒绝。
响应 `RerunPreviewEnvelope` 的 exact `contract_version` 为 `0.3.0`，另外包含：

- 原请求的 session、storage revision、Run 与 node binding；
- `mode = same_run | new_run`；
- `rerun_node_ids`、`reusable_node_ids` 和 `projected_at`。

两组节点必须唯一、互斥，所选节点必须出现在从头重跑集合。Studio 只显示 Python 返回的集合，不在 TypeScript
重写下游闭包、候选复用或媒体 quick-probe 规则。

### 与正式命令一致的选择

- 原 Run 仍可处理、且当前执行 Graph／definitions 未改变时，预览新 attempt 的重跑闭包，以及闭包外已完成
  且输出 quick-probe 可读的结果。独立 pending／waiting 节点保持原状态，不被误列为已复用或已重跑；
- 需要建立新 Run 时，按当前全图拓扑顺序与正式 reuse 候选规则检查直接输入 Artifact、节点配置和输出。
  缺失输出、stale 或被请求重跑及其下游不能伪称可复用；
- UI-only 位置变更仍不迫使建立新 Run，不影响复用判断；
- 预览前后都检查 session／CAS；慢 probe 期间工程被另一写入改变时，返回冲突，不接受旧清单；
- 预览不持久化 Run／snapshot／attempt，不创建工作目录，不登记 Artifact，也不因 quick-probe 失败写 stale；
- 点击“确认从头重新处理”前再次核对页面工程、视图、未保存编辑及参数 draft；正式 command 仍重新校验并创建
  新 attempt，不能接续节点内部进度。

预览是一份即时说明，不是 Freeze、ExecutionPlan、预约执行或未来复用保证。取消预览没有 Runtime 副作用。

## 4. 状态读取与输出复制热路径

### 有界历史读取

Repository 新增 SQL keyset 窗口查询。status 在 SQLite 中先选择最近 20 条终态、全部非终态，以及明确指定的
active／view Run；历史分页只读取请求的 1–100 条及判断下一页所需的一条记录。游标必须精确属于当前终态历史，
不能把其他工程的游标作为合法位置。

status 和历史分页不再先 `list_runs()` 反序列化整个历史。被选中 Run 的完整读取、结果关系校验，以及真正的
执行／Submit／reuse 门禁仍保留；没有用不验证的缓存取代 SQLite authority。有界日志保持每个 stdout／stderr
最多 128 KiB，客户端不能提供任意日志路径。

### OutputFile 进度采样

原复制循环每读取 1 MiB 就调用一次包含 attempt binding／SQLite 检查的 progress callback。本阶段将展示采样
合并为最多每 250 ms 一次，保留首个样本与 EOF 核验后的精确字节样本。

每块复制仍检查短写与源大小漂移，最终媒体 probe、validator、显式覆盖及 Artifact 登记条件全部不变。
progress 达到最后一个字节不代表验收完成，只有 Runtime 正式成功状态才表示完成。这一修改降低已确认的回调
频率，但本阶段没有运行用户长片吞吐基准，也不宣称具体倍数的性能提升。

## 6. 浏览器验收记录

使用 computer-use 在隔离浏览器页操作当前 Studio production build，连接正式 Python Project Service。
临时 Graph 为 Source → automatic Transform → external Enhancement → OutputFile；源为 FFmpeg 生成的
12 帧、160×90 视频。实际验证结果：

1. 点击“开始处理”后，两自动节点完成，external 保持 waiting；界面显示完成 2/4 步及已等待时间；
2. 将纯文本合成文件放入当前 handoff 目标，完整检查拒绝，external 输出数仍为 0、下游保持 pending；
3. 替换为合格视频并检查通过，任务仍 waiting，尚未登记输出；只有点击“提交并继续”后才完成 external；
4. 预先放置的合成目标文件触发 OutputFile 的 no-overwrite 失败，三个上游结果保留，失败输出数为 0。
   默认卡片按正式 `execution_error` 显示处理失败及恢复建议；精确目标冲突原文保留于高级详情，前端不按
   原始错误字符串猜测类别；
5. 重跑预览为 same_run：输出步骤 1 个、可保留上游 3 个；取消后尝试数仍为 4，产物数仍为 3；
6. 将专用测试冲突文件移到保留名称后重新预览并确认，同一 Run 完成。仅 OutputFile 新建 attempt 2，
   上游三个 NodeRun／Artifact 身份不变；尝试总数 5，产物总数 4。独立 FFprobe 确认输出 12 帧、160×90；
7. 从已完成记录再重跑 external，预览 new_run：重跑 external／output 两步、可复用 source／transform 两步。
   确认后建立新 Run，两个上游标记 reused，新的 handoff 不继承旧的检查或提交资格。
8. 停止本次隔离 host 后，主按钮切换为“重新连接”，明确提示正在显示上次状态；外部检查／提交仍禁用，
   没有隐藏的自动重试。随后关闭本次验收页，测试端口不再监听，不影响其他本机服务。

浏览器反馈还促成三个纯展示修正：选中外部任务时助手优先于长参数表并由主按钮直接滚入视图；节点参数摘要
逐行显示；窄侧栏取消叠加缩进，交付要求改为标签和值纵排。检查与提交之间的被动观察不会把“已检查”提示
错误退回“未检查”。这些修正已有相应组件／Workspace 回归。

不读取或修改操作者的真实媒体、既有真实验收工程或外部工具。临时工程、媒体、日志及服务配置不进入 Git。
本次只验证浏览器与正式服务集成，未启动真实 Topaz／外部增强工具，也未验证原生文件管理器或系统播放器。
HostBridge 精确引用与不可用恢复说明由自动测试覆盖；桌面入口与原生 E2E 仍属于 Phase 5。
这只是合成媒体技术操作者验收，不替代 Phase 6 的真实短片或首次目标用户验收。

## 7. 操作者检查入口

前后端需同时更新到当前分支。按 README 启动后，在默认创作者层使用上下文主按钮；精确运行命令、原始状态与
日志在高级层。外部处理依次选择“检查输出”和“提交并继续”；检查失败时按卡片提示替换文件后重试。

节点失败或需要重做时先阅读重跑／复用清单，再选择“确认从头重新处理”。只查看或取消该窗口不执行重跑。
服务离线、工程有未应用设置或存储冲突时，先按禁用原因恢复，不通过旧页面重复强制提交。
