## 普通视频流程

1. 双击完整候选目录中的 `ZNIKU Studio.exe`，确认网页显示 **v0.3.5**。不要只复制 exe。
2. 新建视频工程，填写素材组织方式、视频素材、工程名称、工程保存位置。工作数据默认在工程旁。
3. 保持默认 **ZNIKU 标准视频流程 · 0.3.5**。旧流程在“工作流版本与旧工程兼容”中，不必选择。
4. 设置片名、年份、章节、分叶、增强、FI 与编码。马赛克修复默认关闭；不需要时不要开启。
5. 点击“开始分析素材”。分析读取媒体时间轴，不修改原片；进度表示已读取位置，不是预计剩余时间。
   可取消并点击“重新分析”从头读取。取消不代表原片有问题。
6. 分析通过后确认章数、帧数、切点和成片位置。缺失色彩标签的工作解释等普通警告不要求额外确认。
   确认工作流后进入普通画布，启动处理，按每个外部节点的输入与交付要求执行。

正常顺序保持：可选马赛克修复 → 分章分叶 → 逐叶增强 → 章内合并 → 重叠上下文 FI → 裁边 → 连续编码和原音轨封装。
章节默认1章；分叶默认最长5分钟，独立可设1–60分钟，不跨章。不足一叶的整章仍为一叶。

## 源分析不通过时

- 先查看具体分析原因；不再自动转码、重定时或反复触发内置修复树。
- 可以在外部使用 VideoSourceRepair 等工具处理，ZNIKU 不会自动调用外部工具。
- 在分析页选择“选择修复后的视频”。仅选择文件不会修改工程，仍可以“取消选择”。
- 确认选用后，工程 Source 引用切换到候选并重新分析。候选通过同一准入才可进入下一步。
  其自身的帧数、帧率和音轨成为新参考；不沿用旧规划，也不声称与旧视频逐帧内容等价。
- 选用候选只改变引用，不复制、更名、覆盖或删除原片。请长期保留候选；归档工程时一并保存这个外部参考。
- “源故障修复候选”和“第0项马赛克修复”不同：前者重建参考，后者必须保持已选参考的 N→N、帧率、几何及帧序约定。
