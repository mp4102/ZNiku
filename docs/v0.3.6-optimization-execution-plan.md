## 1. 目标与范围

一句话目标：**保持帧边界、画质配方与成果安全，减少整章中转和无效读取，让用户明确知道当前在做什么、
何时应等待、何时该交付下一步。**

v0.3.5 已达到操作者本机全流程可用目标。本版是在该结果上做性能与交付体验优化，不重新建设 Graph Core，
不要求操作者重做已验收的外部增强与 FI。

本版交付范围：

1. FI 上下文准备不再复制自己的完整增强章，邻章只读取必要边界区间。
2. 新流程把精确裁边并入最终连续编码，避免必经的裁后 ProRes 与时间戳中转文件。
3. 保留可选的独立裁后章输出；单遍时基修正只做有界验证，失败不阻塞融合编码主路线。
4. 工程数据按用途展示占用，提供严格限定范围的、用户确认后的内部中转清理。
5. 完成 UX-001～003：章级自动预选、清楚的文件角色说明、统一真实进度与下一步提示。
6. 提供可复核的正确性、逻辑读写、存储峰值和耗时对照，以及可独立验收的 Windows 本机候选包。

不在本版范围：

- 更改增强/FI 模型、降低 ProRes 品质、改变缩放/颜色配方或默认换成有损中间格式；
- 缩减已采用的重叠上下文来换速度，放宽帧数/相位/时基校验；
- 自动迁移旧 Graph、旧 handoff、历史 Result 或真实媒体；
- 删除已登记 Artifact、外部来件、源文件或成品，自动归档/自动回收；
- 改写 Scheduler、节点内部 resume、通用虚拟视频、虚拟文件系统、跨项目去重或分布式存储平台；
- 新的 GUI 大改版、旧 v0.3.1 A/B/C 批次重做、控制外部 AI 软件、默认依赖新增硬件；
- 擅自公开上传 Windows 捆绑包，选择项目许可证，合并 main 或发布 tag/Release。

## 3. 已核实的性能与存储基线

以下来自 2026-09-23 对一个已完成的约两小时、1080p、三章十五叶工程的只读目录 stat、SQLite 记录与
既有 FFmpeg 日志检查。公开文档只保存汇总，不含真实片名、路径、Run ID、媒体或日志。
本轮起草不重新扫描、播放或处理该工程。

### 3.1 逻辑占用

`.data` 共 116 个文件，3,198,227,748,125 字节，约 **3.20 TB / 2.91 TiB**。以下 GB 使用十进制。

| 类别 | 逻辑大小 GB | 说明 |
| --- | ---: | --- |
| FI 裁边目录 | 1247.806 | 正式裁后章、成功时基中转、旧失败轮次中转 |
| FI 上下文目录 | 577.945 | 正式 FI 输入及 context-parts |
| 外部 FI 原始成果 | 542.684 | 必须保留的昂贵外部成果 |
| 增强章合并 | 288.778 | 当前已登记成果，不纳入本版清理 |
| 外部增强分叶 | 288.778 | 必须保留的昂贵外部成果 |
| FFV1 分叶 | 181.303 | 当前已登记成果，不纳入本版清理 |
| 编码、封装、外部前处理及其他 | 约 70.934 | 包含正式绑定媒体与少量元数据 |

已观察到的中转规模：

- context-parts 的三个完整增强章副本：约 **288.778 GB**。
- 成功 A/B/C 裁边的 `timescale.mov`：约 **542.345 GB**。
- C 章旧失败轮次的未完成时基中转：约 **163.070 GB**；数据库确认该轮次 failed。
- 上述约 **994.193 GB** 是后续分类审查的候选上界，**不是已批准、已证明可全部安全删除的清单**。
  当时 Artifact 表没有指向 context-parts 或 timescale 的路径，但仍须重新核对全部正式引用及文件身份。
- 新融合流程可能不再生成的“成功裁后章＋时基中转”约 **1084.7 GB**，是未来生成量估算。
  该数与前述 994.193 GB 有交集，禁止相加宣传。

文件逻辑长度不等于 NAS 实际分配、快照或去重后的物理占用；“已移到回收目录”也不等于释放了空间。

| 步骤 | 已记录节点耗时 | FFmpeg 日志读取 GB | 日志写入 GB |
| --- | ---: | ---: | ---: |
| 上下文准备 | 1888.486 秒，约 31 分 28 秒 | 287.976 | 190.901 |
| 精确裁边 | 2538.018 秒，约 42 分 18 秒 | 352.036 | 351.953 |

这些是已执行程序报告的逻辑读写量，不是网卡/磁盘物理计数，也不是新增性能基准。
节点耗时包含执行与收尾；失败轮次的网络/容量等待不得混入正常性能平均值。

### 3.3 已定位的实现原因

- `src/zniku/source_aligned/adapters.py` 的 `fi_context` 对每个来源区间先生成 part，连自己的完整章也复制；
  再合并成正式 FI 输入。`chapter_batch.adapters` 复用该实现。
- `src/zniku/chapter_overlap/media_io.py` 的 `copy_prores_range` 以包序号丢弃区间外内容，当前仍读取到 EOF。
- 当 raw 的时基不符合目标时，先写 `.timescale.mov`，再重建 exact 时钟写正式裁后 MOV，并保留中转。
- 双遍路径规避过 FFmpeg 时基重缩放异常，不能无验证移除。两步都使用 stream-copy，不是重复 AI 或重编码。
- 内部 MOV 的计数主要来自同一 FFmpeg 输出包数及 header；当前问题不应误诊为每步强制 full decode/hash。

## 4. 目标处理方式

```text
已验收增强章 + 显式连接的相邻增强章
    → 本章直接引用、仅取边界 → 一份真实 FI 输入 MOV → 外部 FI raw
                                                        │
                         ┌──────────────────────────────┴─────────────────┐
                         ▼                                                ▼
               精确选帧并连续编码（新默认）                     导出独立裁后章（可选）
                         ▼
               原音轨封装、验收、正式发布
```

这只是新标准模板，不限制自由 Graph。增强先合章再 FI 的次序、邻章增强输入的普通 Edge、
外部显式提交均保留；不要求外部 FI 工具读取 ffconcat 或内部范围清单。

### 4.1 PERF-001：上下文组装减 I/O

1. 对完全覆盖且已满足 codec、帧率、时基、几何、信号要求的增强章，直接作为组装输入；不复制整章 part。
2. 邻章只读取有用区间。使用已验证的索引定位、帧边界选择和明确停止条件，不能只添加近似 `-ss`。
3. 快路径明确限于已验证的 ProRes/容器/时基组合；其他允许输入继续走原安全路径，并说明回退原因。
4. 输出仍为完整、可交给外部软件的实际 MOV；帧数、包序、像素、exact FPS、时钟和信号不变。
5. 新 attempt 的中转只在本 attempt 内产生；不改上游媒体、旧成果和旧等待目录，不使用 NAS 硬链接捷径。
6. “取边界”“组装 FI 输入”“检查输出”显示真实阶段。没有测量的阶段不编百分比。

### 4.2 PERF-002：精确裁边并入连续编码

新 Program 节点直接接受有序、已验收的 FI raw `VideoFile`。Python 从直接输入的局部 metadata 重算
负责区间，不接受客户端自由覆盖其意义，不扫描数据库寻找未连接的“邻章成果”。

不可退让的数学门禁：

以下沿用现有 2× FI 合同：原片共有 `N` 帧，本章负责零基半开区间 `[s,e)`，`n=e-s`；
上下文输入从原片第 `a` 帧开始。裁边区间的编号相对于本章 FI raw，不是全片 FI 编号。

- 非末章保留 `[2(s-a), 2(e-a))`，共 `2n` 帧。
- 末章保留 `[2(s-a), 2(e-a)-1)`，共 `2n-1` 帧。
- 各章全局负责范围连续且唯一，合计 `2N-1`；只在完整序列末尾补 1 帧，得到 `2N`。
- 来源、章节顺序、profile/相位、几何/信号及绑定检查不减少；等长错裁也必须被拒绝。
- 仍为一次连续成片编码，按顺序、有界资源消费章节；不退化为每章有损编码再拼接，也不开上千个输入 decoder。
- 任一步失败不登记半成品；中断重跑整个新 attempt，不能从已编码到的章节接续。

禁止把仍指向 raw 路径的 Artifact 伪称为已裁后的 `VideoFile`，禁止创建通用虚拟媒体体系。
可选“导出独立裁后章”继续输出真正媒体，与融合编码作为普通分支共存，不成为默认流程的必经磁盘步骤。

接口实施前冻结清单：新 Program 的 exact ID/版本、raw producer 接受集合、参数 Schema、validator、
metadata 输出及命名；下游 Final/发布节点若 producer 接受集合变化，使用新 exact，不放宽旧定义。
复用现有成片发布能力，避免重新引入最后整片复制。

### 4.3 单遍时基修正：有界实验，不绑架主路线

仅为需要独立裁后章的路径研究单遍 packet-copy 的 exact 时钟修正。
以一轮候选方案和完整帧/PTS 回归为探索边界；不能通过就记录结论并保留双遍安全实现，
不引入自研 muxer、不无限试参数，也不阻断融合编码。

融合编码路线通过时，即使可选导出仍用双遍，本版仍可按如实记录的范围验收；不得宣称所有裁边都已单遍。

## 5. DATA-001：存储分类与受控清理

### 5.1 分类并不等于允许删除

| 用户看到的分类 | 例子 | v0.3.6 行为 |
| --- | --- | --- |
| 归档成果 | 原片/修复参考、外部增强、FI raw、最终成品及工程 | 保留；不提供本版清理动作 |
| 可重新生成的已登记媒体 | 分叶、增强合章、FI 输入、独立裁后章 | 展示占用及重算代价，仍保留 |
| 内部计算中转候选 | context-parts、timescale、确定归属的失败中转 | 证明安全后可预览并明确确认清理 |
| 未知或无法确认 | 手工文件、未支持旧布局、无法读取的引用 | 显示原因并保留，不能猜测删除 |

“可重建”不代表廉价，也不代表可以删掉仍被 Artifact 绑定的路径。本版**不实现通用 Artifact 回收**，
不新增 tombstone、GC 守护进程、回收数据库或自动生命周期。以后如要删除已登记媒体，须另审归档和
reuse/stale 语义；不能把旧 completed 结果缺文件仍称为可复用。

### 5.2 扫描与确认合同

1. 只从当前工程正式记录定位已登记 attempt，使用有界、按需/手动刷新的 stat 汇总；不在每次 UI 轮询时
   递归扫描 NAS、不读完整媒体、不生成全库 hash。
2. 初版清理只在无活动/等待 Run、无运行进程、无导入/检查/提交/存储维护时启用；复用本机互斥规则。
3. 候选必须是已知 exact adapter 产生的内部文件，并核对该 attempt 的实际产物及全部已知正式引用。
   文件名、后缀、round 编号、失败状态、年龄都不能单独证明可删。
4. 任何 Artifact（包括历史 Result 和 reuse 引用）、有效输入、手工来件、incoming、声明输出目标、
   运行所需文件、日志、工程及正式成品均排除；内部 ffconcat 等若仍有消费依赖也必须排除。
5. 新旧路径都须解析并证明严格位于对应 attempt 内，排除数据根、跨根路径、symlink/junction/reparse、
   共享硬链接等风险；归属、引用或文件身份无法可靠核实则拒绝该候选。
6. UI 只提交服务端预览句柄和已选候选，不接收任意删除 raw path。预览绑定工程会话、存储版本、
   attempt 与文件身份/属性，有有效期；确认前重新检查状态、引用和路径，变化则要求重新预览。
7. 使用现有本机互斥与短时确认机制，不声称阻止所有外部文件操作，不建设分布式 lease 或全 NAS 锁。
8. 默认全保留，扫描/预览不删除；完成、关闭、重跑或删除画布节点不触发自动清理。历史工程首次打开
   不应用新策略，只在操作者主动进入维护后列出可识别候选。

### 5.3 用户可见的结果与失败

- 入口放在现有“工程数据”维护区，不在画布主操作区增加一个同权重的“清空数据”按钮。
- 列出任务/章节/轮次、角色、大小、为何属于中转、为何其他文件被保留；默认折叠完整路径。
- 确认页注明仅删除选中的内部中转、不可恢复、不会重算和不会清理正式成果。
- 显示逻辑待回收量；仅成功删除的字节计为已删除，不保证 NAS 快照同步释放物理空间。
- 单纯移动到回收目录不宣称已释放空间；本版不为释放 TB 级容量再复制一份完整“备份”。
- 文件系统动作不宣称与数据库跨系统原子。逐项报告成功/跳过/失败；中断保留其余文件，重新扫描后由用户
  再次确认，不自动重试结果未知的删除，不把部分清理当全成功。
- 清理不回写 Graph、历史 NodeRun、Artifact、Result 或复用结论；若发现正式成果丢失，单独报告并遵守
  原有缺失/失效规则，不能以清理名义修复或掩盖。

## 6. UX-001～003 联合落地

原始问题、合成示例和完整专项清单保留在 [优化记录](studio-optimization-log.md)，本节只规定集成要求。

### 6.1 UX-001＋UX-002：章级交付一次看懂

- Python 根据当前章、明确 leaf 编号和唯一对应关系生成预选；保留规范名匹配，对受支持的外部追加后缀
  使用冻结语法，不靠选择顺序、年份、大小或时间猜测。
- 同号多件、跨章、含混编号、一源多用不自动选；缺件可分批，人工映射保留。
- 用户手工更改不被无关刷新覆盖；候选换代、文件变化或票据失效必须重新确认。
- 每行按“本章第几段 → 选用处理好的文件 → 接收后名称 → 本次操作 → 折叠路径”排布。
- 外部复制并保留原件、本章目录更名、无需操作分别显示真实说明；来源/收件/检查后成果路径不混用。
- 预选不复制、不验收、不 Submit；确认收件、整章检查、显式提交的顺序保持不变。

### 6.2 UX-003：统一操作状态与真实进度

- 常驻单行任务摘要、节点细进度条、右侧助手使用同一正式状态投影，绑定工程会话、Run、最新 NodeRun、
  attempt/handoff；切到历史视图不能串用当前活动项。
- 点击立即显示“正在请求/等待服务响应”；只有得到服务端事实后才写“已受理/正在接收”。
- 有真实帧数、字节数和可信总量才显示确定进度。否则显示操作、轻量动效和已用时，不假造百分比/ETA。
- 缺少可信服务端开始时间时只标“请求等待时间”，不能把浏览器等待时长称为实际复制/检查耗时。
- 取边界、组装、选帧编码、输出检查、结果登记按实际阶段显示；不等权平均不同子阶段或不同节点的百分比。
- 100% 媒体写入之后仍可能检查/登记；仅正式完成才显示完成。下游等待邻章时说明依赖，不假报编码中。
- 外部等待显示“需要你操作”，无倒计时、忙碌转圈或外部 AI 进度。只禁重复/冲突动作，查看与缩放仍可用。
- 断线显示最后可信状态和“结果待确认”，不自动重放收件、提交或清理。迟到响应不能覆盖新任务。
- 复用现有轮询/进度所有者，必要时增加有界的本机操作展示字段，不新增 Runtime 状态、任务数据库或队列。
- 进度推送、日志与持久化限频，不把每帧/每字节变化同步写进 NAS SQLite；保留 v0.3.5 热路径修复。
- 状态栏独占布局行，不遮画布；支持键盘、200% 缩放、reduced motion，读屏通知限频。

| Phase 1 | PERF-001 上下文减 I/O；UX-003 对应媒体阶段 | 内容等价、快路径有界读取、整章 part 不再生成 |

### Phase 0：实施前冻结

- 从 `v0.3.5` 建立拟定分支/隔离工作树，不切换或覆盖仍在使用的旧工作树与程序。
- 同步产品版本、Python/npm 元数据与锁文件到 `0.3.6`；不统一抬升无变化的 wire、Schema 或旧 definition。
- 固化新 Program/受影响下游的 exact 矩阵、默认模板选择及 legacy 回归；同步必要下位基线和项目约束。
- 固化 scratch 允许规则与拒绝规则。若无法在现有上位删除边界内实现，先报告冲突，不扩大权限。
- 确定基准运行环境、计量来源、短样本边界及输出空间上限。沿用候选版本隔离，不接管 v0.3.5 实例。
- 明确 UX 状态数据来源和能力缺口；没有字节进度的接口先使用不确定进度，不凭计划声称已具备。

### Phase 1：上下文快速路径

- 先建立旧实现结果 oracle，再优化整章引用、边界提取和停止条件；检查小章跨多个邻章，不限于仅前后两章。
- 以快路径 allowlist 与 fallback 保护旧容器差异。对不符合门槛的输入不悄悄换配方或降低检查。
- 输出身份/业务 metadata/正式命名不变；保留取消、进程归属、失败不登记以及新 attempt 重跑。
- 将相应阶段接到 UX-003，验证进度采集本身不抵消 I/O 收益。

### Phase 2：融合裁边编码

- 注册新 exact 节点、Presentation、模板和受影响的 Final/发布消费者；不直接改写旧 producer 接受集合。
- 从 raw 的有序输入与 metadata 重算区间，完成单次连续编码，保留一帧 tail 与原音轨封装规则。
- 可选裁后章导出作为真实分支；不为保持旧节点数量而显示虚假的“裁边已完成”节点。
- 单遍时基实验通过则只在已证明组合启用；失败保留原导出路径，记录回退范围。
- 新模板默认切换须在 Phase 5 集成门禁通过后落实；此前清楚标识候选，不替换旧流程。

### Phase 3：工程数据维护

- 服务端分类与只读占用预览先行，再实现确认接口和最小 UI；复用现有工程存储位置与本机授权边界。
- 只支持已知内部中转规则，未知旧布局只展示；不要求给每个插件建设通用清理语言。
- 使用合成目录和文件模拟引用、权限、共享链接、换盘、状态变化及中断，不在真实工程试删。
- 验收预览与实际删除清单一致、异常结果真实、正式成果不变；真实清理另获指定范围授权。

### Phase 4：交付体验联合验收

- UX-001/002 同批完成，避免有自动预选但文件角色仍看不懂。
- UX-003 覆盖收件、检查、Submit、媒体处理、维护扫描与清理的连续状态，不把不同来源粗暴归为 busy。
- 慢响应、失败、断线、重复点击、多章、多 Run 和历史视图分别回归；与 Phase 1/2 的真实进度闭环。
- 保留已批准布局，不增加挡住画布的悬浮进度面板，不重排无关功能。

### Phase 5：综合交付

- 全量代码、类型、构建、合同一致性、生产浏览器、媒体与清理安全回归。
- 同一环境与同一输入做旧/新对照，分别报告保留量、峰值、读写、耗时与 fallback；原始详细记录不进入 Git。
- 真实短样本/已有外部成果只读复用须获明确授权，使用独立工程和工作目录，不能只复制 `.zniku` 就声称隔离。
- 不要求重做已通过的 AI；若短样本性能不代表长章，报告局限，长章写入测试另列预计容量与时间并获授权。
- 构建与精确提交一致的 Windows 本机候选，审计、隔离首启/二次启动/退出、ZIP 解压回验。
- 操作者验收后更新文档状态；commit、push、PR、merge、tag、Release 按当时明确授权分别执行。

## 8. 可核验的成功标准

### 8.1 正确性优先

- 不更改源文件、外部原件及旧成果，非法/未知输入继续失败关闭。
- 合成帧标记、packet/pixel oracle 验证范围首尾和帧序；不是只比较帧总数。
- FPS 至少覆盖 `24/1`、`30/1`、`24000/1001`、`30000/1001` 及对应 2×；覆盖外部等价小数 FPS。
- 覆盖首末章、1 章/多章、短章跨多邻章、单帧合法区间、非零起始 PTS、受支持的 fragmented MOV 与时基差异。
- 新融合编码与已验收旧裁后序列在编码前的帧选择相同；编码配置/尾帧/音轨保持一致。
  不把有损编码文件字节完全相同设为无条件门槛，也不把同帧数视作内容等价。
- 对直接输入变化验证普通 stale/reuse；取消、失败、重跑不登记部分成果，不引入节点内恢复。

### 8.2 性能与存储门禁

| 项目 | 验收要求或目标 |
| --- | --- |
| 上下文全章中转 | 快路径不产生自己的整章 part；仍产生真实 FI 工作输入 |
| 邻章边界读取 | 快路径有明确定位/停止，读取量随所需区间而非整章长度增长，允许有界容器索引开销 |
| 上下文 I/O | 代表性三等长章快路径，相对旧路径媒体逻辑读写减少至少 50% 为目标；实测未达须解释并优化，不虚报关闭 |
| 融合编码存储 | 默认融合分支不生成完整 crop/timescale MOV；可选导出分支另计 |
| 内容保留 | 删除策略默认不变；节省“未生成”与“已确认清理”分开统计 |
| UI 响应 | 注入慢请求时，下一次可渲染更新即出现请求反馈；本机代表任务点击反馈 p95 目标 ≤150 ms |
| 进度可信度 | 三处状态绑定一致，无测量不造百分比；收尾与 completed 分开；服务更新滞后明确显示 |
| 清理安全 | 非候选、被引用、路径不明或运行状态改变均零删除；部分成功如实报告 |

数量级估算：A 章上下文逻辑读写有望由约 479 GB 降至约 191 GB；不是完成承诺。
wall-clock 不承诺固定倍数，应记录重复样本、冷/热缓存说明和范围；物理 NAS 流量只在实际测量后报告。
测试不清空系统/NAS 缓存，不修改系统安全或网络配置来制造漂亮数字。

基准至少分别记录：运行配置、输入/输出帧数、处理路线、阶段耗时、FFmpeg 逻辑读写、最终保留量、
工作目录峰值与采样间隔、是否启用 fallback。未测得项目写“未测量”，不得用容量/耗时反推成网卡吞吐。
短合成做多轮对照，昂贵真实样本按授权预算；外部 AI 等待与失败停顿不计为 adapter 纯处理耗时。

### 8.3 UX 联合场景

- 同章 5 份带 `_slp` 后缀的乱序文件自动预选 5/5；`leaf-0002`/`leaf-0010` 不按字典错配。
- 缺件可分批；重复号、跨章、含混号和一源多用不猜测；人工调整保留，取消零文件副作用。
- 无需展开路径就知道处理段、所选成果、接收后名称、原件是否保留及下一步。
- 慢收件/检查/Submit 全程有可见反馈；未知结果不能自动重试，外部等待无倒计时。
- 查看、缩放、键盘和 reduced motion 可用，状态栏不遮挡画布；内建页面自动无障碍无 critical/serious 问题。
- 操作者验收本版闭环；不以本次验收冒充旧计划要求的五名首次用户研究已完成。

## 10. 风险与止损

| 风险 | 处理 |
| --- | --- |
| seek/时基造成一帧错位或速率异常 | 帧序＋PTS oracle；不合格快路径回退，不放宽合同 |
| 融合后多输入资源无界 | 顺序消费、有界 argv/decoder；规模测试，不把参数藏进另一套执行计划 |
| 为省空间误删昂贵成果 | 仅未登记且无依赖 scratch；预览、确认、重验、拒绝未知 |
| NAS 状态变化/删除中断 | 逐项真实结果；不承诺跨系统原子，不自动重试未知副作用 |
| 进度展示增加 NAS 热路径 | 复用并限频；测量生产者、持久化和 UI 延迟，不逐帧写库 |
| 开发范围膨胀 | 单遍时基只一轮实验；已登记 Artifact 回收、融合“增强合章＋上下文”、NVMe 自动搬运后置 |
| 误伤已完成工程 | 新分支、新 exact、新模板、独立测试根；旧图/成果/包不迁移 |

出现帧序不等价、正式文件被误删、非法 Artifact 登记或伪完成任一项，相关阶段直接不通过，不能用性能收益抵消。

## 12. 已批准冻结的决策

1. 本版范围为两项 FI 性能优化、限定 scratch 维护及 UX-001～003，不做通用存储重构。
2. 新默认链采用“FI raw → 精确选帧并连续编码”；独立裁后章变为可选真实输出，旧工程不自动改图。
3. 单遍时基修正是有界实验，未通过可保留双遍导出，不阻塞已验证的融合默认链。
4. 所有现有正式成果继续保留；本版只提供未登记、无正式依赖中转的显式清理，不提供自动清理。
5. 约 994 GB 是既有工程的待审查候选上界，不是可直接删除量；真实清理和昂贵媒体写入另按范围授权。
6. 先冻结并验证减 I/O，再做融合编码和清理，最终联合关闭 UX；允许独立工作并行，不绕过阶段退出门禁。
7. 审阅本草案不触发分支、版本、运行或发布动作；明确批准开始实施后才进入 Phase 0。
