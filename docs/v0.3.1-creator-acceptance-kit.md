# v0.3.1 候选验收任务包

本包用于新桌面候选的操作者检查和真实首次用户测试，不是通过证明。当前没有招募或代填任何首次用户。
门槛来自[正式方案 §18](v0.3.1-ui-optimization-plan.md#18-首次用户验收不降低原正式门槛)，不能降低。

## 1. 操作者先确认

1. 若旧页面还在使用，先完成必要保存，通过“工程 → 退出应用”确认退出；只关标签页不会停止服务。
2. 完整保留新候选目录，双击 `ZNIKU Studio.exe`。检查首页或工程菜单中的 `v0.3.1 验收候选` 标识。
3. 新建一个独立测试工程。选测试素材、工程位置、成片位置，先核对确认页；不覆盖已验收工程和成品。
4. 新工程旁的同名 `.data` 是长期工作数据，不是安装缓存。需要专用磁盘时显式选择，不手动移动已绑定文件。
5. 同一工程可以自由添加、连线、分支和改参数。参数需要“应用设置”；“整理布局”只改位置，可撤销。
6. 外部节点进入等待后，在“文件”页看清实例名称、输入和要求，打开它自己的收件文件夹。
   直接复制任意名产物或“选择处理好的文件”均可；多候选须明确选择，替换已有目标须确认。
7. 收纳/复制成功不表示处理完成；继续“检查输出”，再明确点击“提交并继续”。不使用旧任务的目标路径。
8. 最后用“查看输出”确认实际文件。媒体处理时间、主观画质和界面操作体验分别评价。

如果显示的仍是旧版本，先检查旧服务是否真正退出；不要删除 AppData、工程或 `.data` 来尝试升级。
出现错误时保留素材和目标，用界面的正常问题说明反馈；必要时自行脱敏高级详情，不上传原片、工程、token。

## 2. Windows 原生操作清单

每项记录候选 BUILD-INFO、日期、实际系统缩放和结果。已通过旧包的项目也须在新包重新检查。
“未执行”和“失败”分开记录，不能因为没有观察到错误就填通过。

| 编号 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| W01 | 双击；再次双击 | 两次均可打开页面，第二次不产生第二套服务 |
| W02 | 文件/多文件/文件夹/保存选择器 | 临时前置，取消无副作用；返回后界面可继续使用 |
| W03 | 选择器打开时再次请求选择 | 只有一个原生选择器；说明先完成或取消，不循环抢焦点 |
| W04 | 向导与外部导入各取消一次 | 原参数、原片、旧目标不变，不创建隐形工程或输出 |
| W05 | 打开收件目录、输出目录及系统播放器 | 打开当前绑定对象；目录/播放器不因 Studio 退出而被误杀 |
| W06 | 退出对话框取消，再确认退出、重开 | 取消后可用；确认后服务停止，最近工程仍在 |
| W07 | 在外部等待时退出并重开 | 仍是同一等待任务，可重新检查并显式提交，无自动推进 |
| W08 | 正在自动处理时尝试退出 | 明确拒绝退出，已有任务继续；不是取消处理 |
| W09 | 历史只读 → 返回当前编辑，含未应用参数 | 历史不变，草稿不静默丢失，不对旧图启动处理 |
| W10 | 125% / 150% / 200% 实际 Windows 缩放 | 主操作、参数应用、选择器可达，任务区不盖画布 |

Windows 缩放由操作者主动选择，并记录原值后自行恢复；Chromium DPR 模拟不能填为 W10 通过。

## 3. 工程数据与外部收件专项

只在独立测试工程进行。媒体长期保留政策不因完成、重跑、退出或删除画布节点改变。

| 编号 | 验收操作 | 检查重点 |
| --- | --- | --- |
| D01 | 新工程默认数据位置 | 工程旁 `.data`；外部等待前专属收件目录已经存在 |
| D02 | 新工程选择专用磁盘 | 实际写到所选盘；不可用时不回退系统盘 |
| D03 | 旧工程打开，查看数据位置 | 不自动迁移，不重命名已有产物 |
| D04 | 有产物工程预览迁移，先取消，再确认 | 取消不复制；确认后路径切换且原目录原件保留 |
| D05 | 打开归档检查 | 列出工程数据外的源和输出；不能宣称只存 `.zniku` 就是完整归档 |
| D06 | 直接收件与 UI 复制两种方式 | 都要求完整检查及显式 Submit；源文件始终保留 |
| D07 | 多候选、错误文件、正在变化的文件 | 不自动猜选；拒绝不合格或过期确认，旧合格目标保持 |

## 4. 首次用户主持说明

招募至少 5 名未读仓库文档、无需理解 JSON/DAG/Runtime 的视频编辑者，匿名编号 U01–U05。
另外一名真实技术操作者编号 T01；产品作者不能计入 U01–U05，自动化代理不能计入任何真实参与者。

每人从相同的新候选和独立工程开始，使用同一规格的只读短素材。主持人先检查工具与素材可用，
但不代建任务答案，不教按钮路径，不介绍 Run/ID/JSON。任务描述只交代目标；一旦提供提示，记录为“有协助”。
可以要求参与者边操作边说明想法；不要暗示正确答案。参与者可以停止，未完成如实计入，不替补掉失败样本。

### 五个任务（给参与者的目标）

| 任务 | 只向参与者说明的目标 | 主持人观察，不提前提供答案 |
| --- | --- | --- |
| J1 | 打开软件，选择素材和保存位置，创建可以开始处理的工作流 | 找到入口，理解成片位置；取消/重新选择不产生隐形输出 |
| J2 | 修改三个常见处理参数，添加并连接一个步骤，再保存重开 | 参数显式应用；位置、连接与设置保持；能撤销错误操作 |
| J3 | 开始处理；遇到准备好的失败，找到原因并正确重试 | 解释原因与下一步；失败从头重跑，已完成上游不重复 |
| J4 | 找到外部任务，识别不合格文件，换成合格文件并继续 | 分清同名任务；确认替换、完整检查、显式提交，不假完成 |
| J5 | 修改一处设置，理解哪些步骤要重做，完成后找到并打开成品 | 不把历史完成当成当前完成；查看复用/失效，定位实际文件 |

失败与不合格样例只放在独立测试资料中，绝不改坏参与者源素材。外部 AI 等待时间不计操作时间；
外部产物必须满足当前测试任务，不能用未验证旧成果冒充新包的真实媒体闭环。

## 5. 汇总判定

在实际收齐 U01–U05 的 25 个任务后才计算。缺失记录不填零分或通过，也不缩小分母提高通过率。

- 无协助至少 23/25；独立端到端至少 4/5；安全关键动作 5/5。
- 默认任务技术泄漏 0 次；错误原因/下一步至少 4/5 能解释正确。
- 时间中位数：J1 ≤300 秒；三个参数 ≤90 秒；添加连接 ≤120 秒；失败重试 ≤120 秒；外部检查提交 ≤180 秒。
- 各关键任务 SEQ 中位数 ≥5.5/7；SUS 总体中位数 ≥80。
- critical/serious 自动无障碍问题为 0；Source 改写、非法 Artifact、假完成、假进度均为 0。
- T01 独立回归多 Source、多 Output、零 Output、分支/汇合、有序输入、高级参数和历史只读。

任何数据破坏、非法提交、假完成、snapshot 被改写或绕过确认直接失败，不能由平均分抵消。
仅提交匿名表格和脱敏问题；用户身份、真实素材路径、工程、媒体、日志和凭据不进入 Git。

## 6. 交付等级

自动化及打包通过、尚缺原生/真实/首次用户证据时为“技术候选可测试”；全部门槛满足才是“UI 优化验收完成”。
正式发行还需要另行授权 PR/merge、tag/Release 与第三方分发许可审阅。本任务包本身不改变任何完成状态。
