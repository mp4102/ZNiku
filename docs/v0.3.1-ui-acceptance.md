## 2. 唯一状态所有者：核对源码后的迁移约束

本节记录实现起点的事实与后续 A 的迁移顺序；本轮没有搬动工作区组件或新增运行控制区。

| 状态或动作 | 当前唯一所有者 | 后续视图重组的边界 |
| --- | --- | --- |
| 当前 Graph、StudioState、撤销与保存 | `useAuthoringProject` → `EditHistory` / `AuthoringSaveController` | 保留同一 document/session；子面板不得再持有独立可保存 Graph |
| 参数编辑 | `StudioWorkspace` 的 `parameterDraft`、`parameterText` 与 `selectionGuardRef` | 表单和 raw JSON 是同一草稿；设置/文件/诊断页签只能共享，不能各初始化一份 |
| 当前/历史选择 | `viewRunId`、`showRunSnapshot`、`setTrustedViewRunId`、`selectRun` | 只切换视图；打开默认当前完整图，显式历史只读，不改 Run snapshot |
| 轻量状态与项目投影 | Workspace 的 status 轮询 effect、`acceptStatus`、generation/sequence | 抽屉复用投影，不增加另一个轮询或状态数据库；迟到响应不替换编辑 |
| 选中 Run 详情 | `loadDetail` 与 detail 轮询 effect | 按 Run/resource 合并请求和退避，拒绝不匹配 generation、Run 或回退状态 |
| 历史分页 | `loadOlderRuns`、`historyCursorRef`、独立 sequence | 有界读取；新 status 的同一 Run summary 优先，切换后旧页不能回写 |
| 外部检查和 Submit | `loadReadiness`、`checkedOutputs`、`handoffActionRef`、`handoffIsCurrent` | 正式服务完整重验；检查通过不等于完成，页面不自动 Submit |
| 外部文件选择/复制 | `useHandoffImport` 的 scope、flight、selection handle 和确认票据 | 原生选择无复制；显式确认后保留源；晚回执不能投给其他任务 |
| 收件观察与收纳 | `HandoffInbox` 与 Workspace 的 `inboxSubmissionFences` | Submit 时暂停旧观察，可信新 detail/空闲状态后恢复，不能只改按钮外观 |
| 所有正式 command | `executeCommands` / gateway → Python | 重组组件只传原 callback；不让新顶栏、抽屉各自执行一套命令 |
| 运行/重跑准备 | `saveThenRun`、`requestRerun`、`confirmRerun` 与 `flushAuthoring` | 保存门禁和影响预览仍绑定当前 session/CAS；确认后才调用正式命令 |
| 节点测量、拖动与坐标保存 | `GraphCanvas` / `use-canvas-node-geometry`；authoring 的 `begin` / `end` | 测量缓存只在 session；一次手势一次 Undo/保存，不因轮询换 identity |

以上标识对应 [StudioWorkspace](../apps/studio/src/studio/StudioWorkspace.tsx)、
[authoring hook](../apps/studio/src/studio/use-authoring-project.ts)、
[文件导入 hook](../apps/studio/src/studio/use-handoff-import.ts) 和
[画布测量 hook](../apps/studio/src/studio/components/use-canvas-node-geometry.ts)。

### 2.1 操作资格不能随按钮搬迁改变

| 操作 | 正式绑定/前置条件 | 不能增加或省略的行为 |
| --- | --- | --- |
| 运行当前 Graph | 未应用参数处理、保存 flush、session/CAS、Python 完整校验 | 不带旧参数启动；不将 UI 检查替代 GraphValidator |
| 打开/创建/替换工程 | 未应用草稿保护，既有保存与明确放弃流程 | 不以导航暗中丢弃草稿 |
| 查看历史 | `changeSelection` 的草稿保护、generation、Run ID、只读 snapshot | 不执行命令，不将所选历史写成新的活动 Run |
| 外部文件预览/确认 | Project session、Run、NodeRun、handoff、port、ordinal、selection handle | 不接受前端拼接的 raw target；原文件不移动/删除 |
| 检查/提交已有 handoff | 当前绑定、健康通道、完整检查、前后产物观察一致、显式 Submit | 不增加“下一次处理的 ParameterDraft 必须先保存”这一新资格 |
| 重跑预览/确认 | 当前图 flush、Run/node、session/CAS、generation 与影响清单 | 只从头创建新 attempt，不把按钮叫作节点内部 resume |
| 放弃本次处理 | 现有服务资格与明确任务选择 | 不顺便删媒体，不成为节点 Inspector 末尾的隐蔽整批操作 |

当前代码以 `viewRunId` 加载单份 detail；活动待办摘要来自正式 `run_summaries`，两者不是同一个含义。
后续任务抽屉可在查看旧历史时显示当前待办导航，但不能把旧历史 detail 当成待办详情，也不能再启动一份
无界 detail 轮询。点击待办后才切换精确目标，状态所有者仍在 Workspace。

旧历史 completed、另一任务 waiting、当前图有未应用参数三者共存时：顶栏动作归被查看历史，任务行保留
另一个活动待办的标题和导航，草稿不丢失。切换节点仍可被现有草稿保护阻止；这是导航约束，不是新的
Runtime Submit 资格。A 必须为此组合补集成测试。

### 2.2 批次 A 的组件迁移顺序

1. 固定上述 session/资源绑定和原命令 callback；先补行为回归，不复制状态所有者。
2. 从 `RunCenter.tsx` 拆出只消费 props 的主操作、历史、问题与任务摘要视图。
3. 将 `ProjectShell` 改为占位布局；同一批替换 `RunCanvasOverlays`，不保留新旧两个常驻控制区。
4. `NodeInspector` 建立稳定页签，参数/导入/收件控制器仍由当前所有者传入；页签切换不重置草稿。
5. 整理菜单与任务文案，精确动作继续回调原 command，并保留禁用原因与错误定位。
6. 将高级精确视图和日志展开解耦，错误摘要不受折叠影响；有界日志读取仍由原 resource key 控制。
7. 运行当前/历史、草稿、外部导入/Submit、CAS、断连和迟到响应组合回归后，才删除旧展示分支。

这是后续实现依据，不是本轮已经完成上述七步。

每变体 20 次重复通过；可解变体的端点错误、障碍相交、降级均为 0。G09 故意无解/超预算时的 3 条降级线
及相交如实保留，不算避障成功。

这些数据只支持选型，不宣称生产画布已修复、任意图最优或 1000 Run UI 已经通过性能验收。

[图形实施前试验报告](v0.3.1-graph-preflight.md)；可复现命令和数据在

### 4.2 交接竞争的修复边界

- Runtime 在 `get_run()` 的同一个 SQLite 读取快照中解析精确 NodeRun 与 latest attempt，按身份判断
  替代；快照之外的补查只区分未知/跨 Run，不能把更晚的对象混入旧快照。同 Run 的后生 attempt 仍拒绝。
- 只读观察可能在返回前已经过时，因此不作为登记许可。Repository 原有写事务继续重验父 Run、latest、
  waiting 与输出；未知 Run/NodeRun、跨 Run、真旧 attempt、非 waiting 和错误 handoff 的失败语义保留。
- Workspace 在本地交接动作、command、服务 active operation 或该 handoff 的暂停期间不启动新的被动
  readiness。解除暂停必须依赖空闲时发起并返回的可信 detail，不能把旧 status 的 idle 当成本地 Submit 完成。
- 已发出的被动 HTTP 仍有物理请求记录。Submit 先使其观察失效并等待结束，最多 5 秒；未结束就停止本次
  用户操作，不发 Submit、不自动重试、不假装旧请求取消。排空后仍执行原完整 probe、产物一致性和精确绑定。
- 跨 Run 导航的被动物理请求总上限为 8，只有真正结束才释放名额；这是 UI 资源预算，不是 Runtime 并发合同。
  导入/收纳释放 busy 后触发原有 detail 周期刷新，不新增第二个轮询或让操作中的回调穿过暂停门禁。
- 这不是提高 E2E 超时或删除 409 断言；生产闭环仍不允许未预期请求错误，完整流程与负向用例一起重跑。
