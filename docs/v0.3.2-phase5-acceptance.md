## 2. 新建并运行

1. 双击新候选的 `ZNIKU Studio.exe`，在新页面创建工程，不在旧工程上尝试重建。
2. 素材组织方式选单一完整视频，选择测试视频、工程名称和工程保存位置。
3. 工作流方案明确选择 **ZNIKU 重叠 FI · 0.3.2 候选**。已经分章的多文件素材继续使用旧流程。
4. 首轮采用平均3章；每段最长时长默认5分钟。短于5分钟的章保持单叶；章长超过上限时取最少叶数均分。
   另行验证精确时间和精确帧切点，不把切点当重复间隔。
5. 填片名与年份、增强模型/倍率、编码选项；输出父目录可沿用工程位置。
   FI显示软件v1.0、Aion、待真实验收。上下文默认左32/右32帧、最短输入2帧，均为工程候选值。
6. 完成分析，确认Python返回的章/叶数、帧数和输出位置，再创建普通节点图并运行。

已展开图不会被向导重写。日后的节点参数、连接及重跑在同一节点图中操作；改动直接输入/参数会按既有规则
使下游失效，不改变其他有效分支。不要将旧FI结果接入新Program来绕过新合同。

## 3. 外部增强与FI的文件分工

| 文件示例 | 你要做什么 |
| --- | --- |
| `Example (2026).A.leaf-0001.enhancement.mov` | 交付本叶增强结果；输入输出帧数相等，尺寸按声明倍率 |
| `Example (2026).A.enhancement.fi-input.mov` | **交给Aion处理的输入**，含真实邻章上下文；不是仅正式A章 |
| `Example (2026).A.enhancement.fi-raw.mov` | 提交外部完整原始FI来件，保留全部上下文，不手动裁边 |
| `Example (2026).A.enhancement.fi.mov` | 系统另存的精确裁后正式章，不覆盖raw |

章增强完成后，系统先合并本章全部叶。需要的邻章增强未完成时，FI上下文节点等待普通图依赖；没有模型ETA。
每个外部attempt拥有独立目标目录。可用UI选择文件复制，或按收件助手复制到专属目录；文件出现不等于完成，
仍须检查并显式提交。输入不足最短要求、帧数/FPS/geometry/来源错误都必须修正，不能用复制帧或错误声明凑数。

系统将裁后章顺序送入一次连续Program编码，只有全片末尾补一帧；最终视频为2N帧、2倍原始精确帧率，
再封装原音轨。不产生整片ProRes必经文件。上下文、raw、crop仍可能各占接近整章的一份空间，不能当作小缓存。
某些MOV需要先以packet copy归一时间基，再执行精确裁边；额外staging文件也保留。这不是视频重编码，
但仍有磁盘读取和复制成本，不能预期两TB输入瞬间完成。

## 4. 必须由真实输出证明的门禁

先短片，后长片。长片只有在短片通过且明确指定源/工程/输出范围后才开始。

- Aion的明确2×模式是否实际输出2M−1；输出时序是否符合输入位于偶数位置的候选相位约定。
- 同一短样本的整段参考和多章上下文结果，比较切点附近的运动、硬切、首尾，保留原始外部输出。
- 左/右上下文与最短M能否满足这个具体软件/模型；不够时调整候选范围并重验，不把帧数检查当相位证明。
- 平均3章、单章、899帧这类非整秒精确边界；短章和非整数FPS的总时长及切点处不能丢失或重复内部时刻。
- 4K增强输出尺寸、实际单文件大小、处理耗时与磁盘峰值：用户因耗时明确暂缓本轮验证，不记作通过。
  首轮1080p的音画同步和观感已由用户确认，不据此外推4K。
- 退出重开、外部长时间等待、原始来件保留、复用/失效、取消后新attempt从头处理。
