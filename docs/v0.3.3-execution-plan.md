## 1. 用户可见的结果

1. 可以返回“处理方案”及前面步骤查看，返回本身不改变工程或运行。
2. 第三页为“处理与成片设置”：片名/年份，0 可选外部修复（默认关闭），1 分章分叶，
   2 增强，3 FI，4 编码与输出。总开关直接可见，只有关闭时收起其条件参数。
3. 新流程的分析只执行原片 Source/Admission，不因外部修复尚未完成而卡在分析页。
4. 确认后生成一张完整的普通 Graph，外部修复作为第 0 个可选处理节点，完成后才分章分叶。
5. 已完成的外部文件仍走同一个任务助手：选择文件/收件目录 → 检查 → 明确提交。不自动提交。
6. 接受明确声明且可解码的 MP4/MOV/MKV；不要求操作者先使用命令行转换。

```text
原片 → Source/Admission → 规划与确认
                            │
                            ▼
                可选外部前处理 → 分章分叶 → 增强 → 章内合并
                                                        → 重叠 FI → 裁边 → 连续编码
原片音频 ─────────────────────────────────────────────────────────→ 最终封装
```

## 2. 规划和执行身份

新 profile 为 `zniku.source-aligned-overlap@0.3.3`，首先支持单一 `program`。
`pre_chaptered` 和旧 MR preparation 保持原流程，不冒称适用新单一时间轴合同。

规划只使用已登记原片与 Admission，不接受浏览器上报 N/FPS。SourceExpectation 保存
`original_video_artifact_id/source_media_artifact_id/admission_artifact_id/frame_count/frame_rate`。
plan 中的 Artifact ID 明确指原片，不预填未来修复结果的 UUID。

新 Split 从实际直接输入建立 effective video binding：修复关闭时必须为所声明原片；开启时必须有
新外部节点验证生成的同一原片绑定。下游参数约束原片及帧范围，直接输入 metadata 传播实际有效视频 UUID；
Merge/Context/Program 不允许混入不同 effective video 的结果。重试产生新 Artifact，沿用现有 reuse/stale。
不得执行时改写 Graph、Run snapshot、未来 Artifact ID 或查询隐藏媒体索引来补依赖。

新八类处理节点使用独立 `0.3.3` exact definition，新增 metadata namespace `zniku.source.aligned`。
旧定义的 Schema、validator 和结果含义保持不变；通用低层媒体函数可复用，但不能用伪造旧身份的请求执行新语义。

## 3. 外部交付合同

外部步骤是普通 `manual_external`，输入为原片 video 和明确原片/Admission 关联，保持 N→N。
操作者声明工具/模型/版本以及未剪辑、未变速、未增删/重排帧；声明不是软件对画面内容的证明。

必须验证：

- 原片绑定、总帧数和精确有理帧率；
- 归一化后的展示时间节奏、有效覆盖与累计漂移；不能只比较播放器显示的 FPS；
- coded geometry、方形像素、逐行、方向和兼容 BT.709 SDR/limited signal；
- 恰好一条可识别视频流，以及显式允许的容器/流布局；
- 输入、导入副本、正式目标与 Submit 的绑定；失配不登记 Artifact、不执行下游。

编码、码率、文件大小、GOP、关键帧位置和受支持的位深可以不同。不同 time_base 和统一时间戳平移可以
合法，必须按实际时间与量化精度判断；不要求原始 PTS/DTS 整数相同，不静默修复 VFR 或真实时间断裂。
不把容器 duration 的末位差异当作实际丢帧，也不靠复制尾帧凑 N。

外部输出格式是明确设置，默认 MP4，可选 MOV/MKV。对应三个静态输出定义
`zniku.source_aligned.external.mp4/.mov/.mkv@0.3.3`，参数 const 与输出后缀一致。
验收依据真实容器，不是扩展名；不会把 MP4 原样复制后伪装成 MKV，也不暗中重编码。
变更交付格式遵守普通参数/节点变更与新 attempt 规则，不能改写已有等待任务的冻结目标。

帧数、时间轴和来源声明无法自动证明逐帧画面内容相同；删一帧再补一帧等内容错误仍需要外部工具约定与
操作者复查。可用合成 frame marker 作为测试 oracle，不建立全局 full decode、hash 或 Evidence authority。

本节点的精确时间轴检查会顺序解码读取原片与来件；导入、检查、Submit 都复用正式验证路径，不能把
上一次按钮结果当成免检凭据。大文件检查可能耗时。manual 检查暂不提供可中途取消/百分比，不代表
外部软件仍在处理；有界超时、错误缓冲和子进程回收防止无限挂起。此限制必须在助手中明示，不伪报进度。

## 4. 原音频与起点

最终音频始终来自原片，不使用外部文件的音轨替代。新 Final 从直接原片读取首视频展示时间与音轨起点，
保留相对偏移，输出验收同时检查轨道和时间对齐。已知压缩音频时钟量化/起始样本边界需要明确容差；
不以音轨数与 codec 相同冒充音画同步证明，不靠改速或任意裁音补偿未知偏移。主观口型同步仍需真实验收。

本轮明确不支持需要保留额外编码预滚/MP4 edit-list 样本裁剪、但当前 MKV 包复制不能保持首解码样本
位置的原音轨。新流程在原片规划预检阶段即报告 `E_SOURCE_ALIGNED_AUDIO_PRIMING_UNSUPPORTED`，
不让操作者完成昂贵增强/FI 后才发现此已知问题；执行节点和 Final 仍再次检查。不会静默转码音频、
裁掉 packet 或只调整时间戳来冒充完整保留。MP4 容器本身不被一律拒绝；这是原片音轨的有条件限制，
不是外部 MP4 视频交付限制。合成测试覆盖正/负/多音轨偏移及 AAC 首样本变化拒绝。

## 5. 向导修改与兼容边界

- 未创建工程：配置是 session 意图，返回、取消和预览无副作用。
- 只有原片准备图：处理方案与处理参数可返回修改；新 MR 意图仅在确认生成工作流时应用，复用原片分析。
- 已创建的素材/工程身份可以查看，不能让仅修改表单看起来已更新实际分析；需要重建分析的操作明确区分。
- 已展开或手工编辑的图：不由向导整图覆盖；明确定位到普通图编辑，旧 Run 与产物保留。
- 旧 MR 等待任务：显示原来的真实配置，提供直接打开外部任务入口，不显示假关闭，不自动转成新格式。
- Python 负责 CAS、会话、输入 freshness、图保护和执行合法性；TypeScript 不复制业务规划或放行结论。

## 6. 执行批次

## 7. 验证门禁

- 合成原片与外部结果：三容器；N/FPS/几何/色彩冲突；VFR、时序断裂、量化及统一平移；原音频偏移。
- MR off/on 构图；未交付也能完成原片分析；未通过的交付不能启动 Split；显式提交后推进完整链。
- 错源、等长异源、混 effective、错误章/叶范围、重试与下游 stale；没有未来 UUID 或 snapshot 回写。
- 旧 AV27/overlap exact definition、工程与外部等待兼容；普通自由图不被向导覆盖。
- 导入取消/失败保源与旧目标，文件出现不 Submit，多容器声明与真实封装矛盾失败。
- 全量 Python tests，双平台 mypy，Ruff，lock/Schema/corpus/版本检查；Studio typecheck/tests/build/生产 E2E。
- 纯合成新旧媒体 smoke；独立 wheel/桌面候选审核，旧包和服务不被替换。

真实长视频、外部 AI 操作、画面对应和主观音画同步由操作者验收；自动化结果不冒充真实软件能力证明。
完成后 commit/push，不自动 PR、merge、tag、Release、迁移数据或重启用户服务。

## 9. 候选操作与真实验收

1. 使用本版本独立 Windows 候选目录内的 `ZNIKU Studio.exe`，不要只复制exe、不要删除`_internal`。
   本机状态通道是`Studio-v0.3.3-candidate`；旧版本最近工程不会自动迁移进来。
   本轮本地交付目录为`build/v0.3.3-source-aligned-candidate-20260914-r2/dist/ZNIKU Studio`。
   `BUILD-INFO.json`如实记录构建时为`1018fb4`之上的未提交工作树，不能把基点误认作候选源码提交；
   文件级一致性审计负责确认本轮实际源码/生产资源，后续commit不会重写该构建记录。
2. **新建一个测试工程**：素材选择原片，例如`Example.mp4`，不是`Example.RM.mp4`。
3. “处理方案”选择“ZNIKU 原片规划与重叠 FI · 0.3.3（推荐）”。
4. “处理与成片设置”第0项默认关闭；需要外部修复时开启，填写工具/模型，按真实交付选择MP4/MOV/MKV，
   确认不剪辑、不变速、不增删或重排帧；分章、分叶、增强和FI仍按各自设置。
5. 先完成原片分析与工作流预览。存在不支持的音轨预滚时，此处即明确阻止，不能以改后缀绕过。
6. 确认创建工作流并开始处理。到第0步时，打开外部助手选择处理好的文件，或复制到其专属收件箱。
   文件出现/复制成功不代表已提交；检查通过后点“提交并继续”。系统按原片坐标切分实际通过的修复结果。
7. 继续增强与重叠FI，最终人工检查帧对应、边界、画质和音画同步；中间产物和外部原始来件保留。

已展开的旧工程继续用原exact合同，不自动升级；需要新第0步和多容器交付时新建本版本工程。
当前仍是本地验收候选，不是正式Release。真实外部工具结果、长片耗时、主观同步与画质仍待操作者验收。
