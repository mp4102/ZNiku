## 1. 实施结果

Phase 2 在不改变 Graph／Runtime 语义的前提下，把创作者从工程首页带到一个仍可自由编辑的普通 Graph：

- 新增工程首页，提供引导式视频工程、空白工作流、打开工程、最近工程与服务恢复入口；
- 空白工程 ID 改由 Python Project Service 生成 UUIDv4，AVEnhanceFlow 建项身份由 Studio 会话自动生成；
  两者均不要求用户输入，默认界面不显示 ID 或绝对路径；
- 将 AVEnhanceFlow v2.7.0 的 preparation／expand 包装为“选择素材 → 处理方案 → 设置 → 分析 →
  确认工作流”，同时保留 Python preview、no-overwrite 和 exact preparation Run binding；
- 新增正式 HostBridge `0.3.0` 合同，用原生 picker 选择输入媒体、`.zniku` 保存位置和输出目录，并以
  Artifact／handoff／picker authority reference 打开文件管理器或系统播放器；
- Schema 参数表单的 file/directory picker 只更新当前 `ParameterDraft`，不会自动应用参数或触发 Graph
  mutation；取消、错误、迟到响应及较新的 draft 均有明确隔离；
- Python 从 current preparation Artifact 投影文件名、大小、容器、视频格式、分辨率、帧率、时长、帧数、
  结构化音轨和预计步骤；普通创作者视图不读取 Artifact ID，也不在 React 复制 probe 或格式算法；
- 最近工程仅保存在本机浏览器偏好中，严格校验版本与字段，不写入 Project、Graph 或 Run snapshot。

## 2. 关键不变量

- HostBridge 只监听既有 Project Service 的 loopback host；每次 launcher session 使用至少 256 bit 随机
  token 与精确 `http://127.0.0.1:<port>` Origin，token 不进入 URL、日志、Project、Storage 或响应；
- capability 是六项固定闭集；有副作用的调用只能使用 POST，并先取得绑定单一 capability、5 秒有效、仅可
  消费一次的用户动作票据。失败、取消、参数错误和 capability 不匹配都会消费票据，客户端不自动重试；
- 系统动作不接受浏览器 raw path、executable、argv 或 shell；Python 只解析当前 session picker handle、
  精确 Run Artifact 或最新 waiting handoff，并使用固定 argv 与 `shell=False`；
- `open_with_system_player` 还必须通过闭合音视频后缀、Windows ADS 拒绝和轻量 FFprobe `MediaFile`
  校验；任一检查失败均返回稳定错误且不启动系统进程；
- picker 取消不创建文件、目录、Project、Run 或 Artifact；save picker 只返回目标，不提前创建或覆盖；
- “分析素材”只绑定当前命令响应的 exact `active_run_id`；重开已有 preparation 时由用户按时间明确选择已
  完成记录，Python 再验证绑定，Studio 不猜 newest/latest；
- preparation preview 没有 admitted media facts 时不猜媒体信息；expanded preview 只投影 Python 已复核的
  current Artifact，且不携带完整路径、Artifact ID、hash 或 extradata；
- 任一输入、设置、向导重开或较新请求都会使旧 preview／picker response 失效；确认前不替换 Graph；
- 空白、多 Source、非 AVEnhanceFlow 和任意合法自由 DAG 继续存在，模板没有进入 Runtime 业务分支。

### 3.1 阶段覆盖重点

- Project Service 覆盖自动 UUID、既有工程 no-overwrite、严格请求模型和 exact preparation Run 绑定；
- HostBridge 覆盖 token／Origin、一次性票据、固定 capability、picker 取消、句柄权限、系统动作 raw path 拒绝、
  系统播放器后缀／ADS／FFprobe 校验以及 `shell=False`；
- Studio 覆盖工程首页、最近工程、服务恢复、五步引导、基础/高级设置、picker draft 隔离、迟到响应 fencing
  和人类可读摘要；
- Graph Core、Runtime、generic media 与 AVEnhanceFlow v2.7.0 回归继续由全量 Python 门禁及两个合成媒体
  smoke 证明，不能用前端 mock 替代。

### 3.2 正式 HostBridge 面

- `GET /api/host-bridge/capabilities` 只读取当前 launcher session 的能力状态；
- `POST /api/host-bridge/user-actions` 为一次用户动作签发短时、单用途票据；
- `POST /api/host-bridge/invoke` 消费票据并执行固定 allowlist 中的 picker、文件管理器或系统播放器动作；
- Studio 只持有 session token 与不透明 authority reference，不把 raw path 当作系统动作授权。

## 4. 证据边界与未实施范围

Phase 2 验证的是已经启动的 Studio、正式 loopback HostBridge 合同与创作者建项流程。Phase 5 才负责可分发的
双击 launcher、production 静态站点生命周期、单实例、真实原生窗口 E2E、媒体预览、完整无障碍与视觉性能
收敛；因此本阶段不宣称新用户已经可以在未安装 Python/npm 的机器上双击交付物完成建项。

Phase 2 没有实现 Phase 3 的 Undo/Redo、StudioState/schema 3、autosave/CAS、画布人体工学或批量宏，也没有
实现 Phase 4 的运行中心重构和外部处理助手，更没有改变 Scheduler、Node Runner、Artifact 验收、reuse/stale
或 AVEnhanceFlow v2.7.0 领域算法。

package/product 版本仍为 `0.2.0`。本阶段完成不代表 v0.3.0 Acceptance Candidate、正式发行、tag 或 Release。
