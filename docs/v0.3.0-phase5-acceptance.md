## 已实现内容与边界

1. `zniku.desktop`：Windows single-instance launcher、OS 分配可用端口、健康检查后打开默认浏览器，
   同源 production React/Python 服务。PyInstaller one-folder 包自带 Python/Tk/媒体工具；创作者无需终端。
2. 退出必须显式确认。活动自动处理/检查/保存时拒绝关闭；空闲与 `waiting_external` 可关闭，既有结果与
   等待任务保留。关闭准入与 command 同锁，不存在 check-idle 后新任务抢入窗口。
3. Windows JobObject 只管理本实例自动进程树；系统浏览器、Explorer 与播放器固定 argv、显式 breakaway。
   意外中断后仍按原 Runtime 规则建立新的 attempt，不恢复节点内部进度。
4. 随机端口会改变浏览器 Origin，最近工程与显示模式因此改由 launcher 本机偏好保存，并在新页面初始化时
   恢复。严格闭合集合、最多 8 条，失败不影响 `.zniku`；不保存 token、Graph 或 Run。
5. `MediaPreviewRequest/Envelope`：token/Origin 授权 POST，只接受现有 Artifact、当前 handoff 或 picker
   handle，加工程 session 绑定；拒绝 raw path、任意时间、命令和未知字段。
6. 固定 FFmpeg 首个可解码视频帧，最长 15 秒，最大 640×360，不上采样小源；PNG 最大 2 MiB。
   单路生成、32 项/16 MiB 内存 LRU。无磁盘缓存，无新增 Artifact，无删除目录，Source 与工程不变。
7. A/B 只显示两张静帧；不保证时间点对齐，也不证明画质或正式检查通过。切换节点/工程/Run/候选使旧响应
   失效，不自动播放、不自动检查、不自动 Submit。
8. 中文默认文案、Schema 字段错误关联、对话框焦点环/恢复、键盘连接和跳转、focus-visible、reduced motion、
   高对比设置与窄视口布局。移除 8–11px 字号，正文/表单提高至 13–14px。
9. 生产 bundle 按图画布、Schema 和应用拆分，不提高 warning 阈值掩盖大块脚本。显示优化不削弱 Runtime
   validator、覆盖、stale/reuse 或 handoff 规则。

## 发现并修正的问题

- ReactFlow Handle 的 generic div 带不合法 `aria-label`：隐藏拖线圆点的冗余读屏语义，保留完整可读端口
  文本与键盘连接对话框；不把无键盘动作的圆点伪装按钮。
- 画布状态层 `pointer-events:none` 被“编辑当前工作流”按钮继承：只对实际按钮恢复事件，保留空白拖图。
- 已选节点图标的对比度只有 4.03:1：提高文字对比，不降低扫描门槛。
- 用户工程名称中 `</script>` 会中断 bootstrap：对嵌入 JSON 作 HTML-safe 转义并回归测试。
- 退出 `confirm=1` 被 Literal 接受：增加 exact boolean 校验，未知/非法请求不关闭应用。
- 原子偏好写入使用独占唯一临时文件，不覆盖旧同名 `.tmp`；失败只清理本次所有的临时文件。
- 历史忽略目录 `build/lib` 残留旧模块，首次 wheel 审计发现污染。旧 build 整体移至唯一的本地忽略备份，
  没有删除；清洁重建后逐项比对 wheel 与当前源码，拒绝 legacy 模块、媒体、工程、日志或 cache。
  首次污染 wheel 不作为交付物；桌面候选独立使用当前源码与全新构建目录。

## 2026-09-08 原生选择窗口置顶修复

操作者先反馈 `E_HOST_BRIDGE_DIALOG_BUSY`，随后找到被浏览器遮挡的选择窗口。根因是正式
`WindowsHostPlatform.choose_paths` 只创建隐藏 Tk root，未设置置顶属性；向导、工程打开/保存、节点参数
和外部成品导入共用该入口，所以都有同一问题。第二次请求被互斥正确拒绝，不是媒体合同校验失败。

修复范围：

- 四种 picker 统一使用已映射的透明临时 toolwindow owner，设置 topmost，并在打开时只请求一次焦点。
  选择、取消、准备/调用异常均尝试撤销 topmost、销毁 owner，最外层始终释放互斥；不修改用户工程或路径。
- 使用 Windows owned-window 的置顶关系，不绑定或操纵 Chrome HWND、不轮询抢焦点，不更改系统策略。
  [SetWindowPos 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
  说明 topmost owner 与 owned window 的关系；键盘前台资格仍受
  [Windows 前台限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)
  约束，不能把 Z-order 与始终获得键盘焦点混为一谈。
- 共用有限的 `E_HOST_BRIDGE_DIALOG_BUSY` 人话映射，提示先完成/取消已有窗口，不再归咎所选媒体；首页、
  向导、节点参数和导入保留高级原始详情。未知错误不猜测原因，不自动重试，不增加 HostCapability。
