## 1. 问题与改动

旧界面把工程保存与工作数据选盘呈现为两个并列步骤。只选工作数据目录后，仍提示同时缺少工程位置
和名称，无法指明实际缺项。这是展示层把可选配置误导成必选配置，不是操作者不会使用。

新建向导现在按以下顺序呈现：

1. 选择素材。
2. “保存工程”：工程名称标为必填，“选择工程保存位置”标为必选；选中后显示文件名及完整路径。
3. 常驻工作数据摘要：默认自动安排到工程旁同名 `.data` 文件夹，说明中间产物和外部结果长期保留。
4. 默认折叠的“高级存储设置（可选）”：只有需要专用磁盘时才展开选择工作数据父目录。

选用专用磁盘后，折叠高级区不会隐藏当前存放位置。取消选择保留已有填写；“恢复工程旁默认”只修改
这次建项设置，不改变工程名称/工程文件位置，不移动、删除文件，也不自动创建目录。

缺项按实际问题分别提示并聚焦：

- 名称为空：`请填写工程名称。`
- 保存位置为空：`请选择工程保存位置。工作数据位置不能代替工程文件位置。`

两项均缺少时先提示名称，补齐后再提示位置。错误与控件通过无障碍描述关联；重复“下一步”仍会定位
到缺项。没有桌面选择器的开发入口会展开原有手工路径区，不尝试聚焦禁用按钮或自动弹出原生窗口。

## 2. 保持不变的边界

- `.zniku` 与外置媒体数据仍按 Graph Core 基线各司其职，不把大文件塞入 SQLite。
- Python 继续决定实际数据目录、校验与建项；前端不新增路径派生或第二份存储合同。
- 默认创建不传 `data_parent_directory`；显式选盘才传，恢复默认后再次省略。
- 选择/折叠/取消本身不创建 Project 或 Run；创建仍由“开始分析素材”明确触发。
- 已有工程的数据位置不自动迁移，不新增清理策略，不调整 Core、Runtime、Graph、Schema 或版本。
- 保留先前的选择器进程隔离，以及关闭、断线、修改表单后的迟到响应拒绝和未知写入结果保护。

## 5. 操作者确认后的四项布局

### 5.1 默认层与高级层

首步仅有四项设置，按阅读与 Tab 顺序排列：

- **素材**：素材组织方式 → 选择视频素材。
- **工程**：工程名称 → 工程保存位置。

两个分组使用一致的标签列与控件列，选中结果紧随对应控件；不再常驻数据目录说明、开发入口或
独立的高级存储入口。窄屏标签改为上下排列，小高度视口使用向导内部滚动，下一步固定可达。

其余全部进入唯一、默认关闭的“高级选项（可选）”，内部按用途分区，而不是多个并列折叠入口：

1. 工作数据：当前存放规则、专用磁盘选择、恢复默认及长期保留说明。
2. 章节名称：仅对预分章视频出现，默认章名可以直接使用，需要时才修改。
3. 手动路径（开发用）：工程与素材路径的同一组表单值，不另建隐藏配置。

自定义数据位置后，折叠标题仅显示“已自定义工作数据位置”状态标记，具体路径与说明仍在高级区内。
高级区的打开/关闭本身不修改 Graph、参数、路径值，也不发送创建/运行请求。

先按整片选择素材、再切换为预分章时，为空章名补上可编辑的“章节 N”，保留已有非空自定义名。
手动清空章名后折叠，下一步失败会重新展开高级区并定位错误输入；工程名/工程位置的精确提示继续保留。

### 5.2 键盘问题与修复边界

生产回归发现：已打开工程的 ReactFlow 会在 document 上捕获 Space，并阻止原生 HTML summary 的默认
开合。空工程没有画布，因此单独测试空工程会漏掉这个问题。已在合成工程中稳定复现红例，再验证修复。

向导、工程首页、数据管理、重试对话框，以及画布内部的连接/添加下一步/整理布局对话框占用界面时，
画布暂停其全局平移、选择、多选、缩放键位与节点键盘交互；关闭后恢复原有默认。未替换 summary 的
原生行为，也未重建 Graph 或修改运行合同。相关测试验证暂停/恢复不产生图编辑副作用。
