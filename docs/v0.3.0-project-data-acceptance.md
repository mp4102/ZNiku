## 实际交付

1. SQLite schema 4 独立保存 `ProjectStorage`。新桌面工程默认工程旁同名 `.data/attempts`，向导可选择专用
   磁盘父目录。旧 schema 2/3 普通读取、运行不升级；首次 authoring/配置升级前保留唯一数据库备份。
2. 既有工程保留原位置。顶栏“工程数据”展示归档依赖，提供无历史时的明确配置和有历史时的预览/确认迁移。
   迁移只复制本工程 attempt，分块字节比对和源/目标变化检查通过后，单事务切换路径，原位置全部保留。
3. 外部 attempt 进入等待前创建专属收件目录。页面每两秒只读观察，任意来件名、多候选明确选择、覆盖明确
   确认；经原 Runtime validator 检查后同盘规范收纳，不产生第二份完整媒体，也不自动 Submit/Artifact。
4. “选择处理好的文件”继续复制外部源并保留原文件。两种方式最终仍需原有“检查输出 → 提交并继续”。
5. AV27 正式目标支持章内 leaf 点分命名，Merge 后再 FI；旧 handoff 固定目标不重命名。Graph 的标识、
   端口、ordinal、参数、执行合同与历史结果不变，Runtime 不引入 AV27 业务分支。
6. 工程数据、已登记成果和历史产物长期保留；完成、退出、重跑或删除节点不自动清理媒体。

## 明确边界与用户验收

- 已配置数据根缺失或变成链接时明确拒绝，不重建空目录或回退系统盘。当前保存绝对位置，手动移动工程不会
  自动重定位数据；换盘使用明确迁移。迁移要求全部 Run 已终结，目标为新目录；失败副本可能保留。
- 收件同盘收纳使用短暂硬链接别名复用原 validator，需要文件系统支持；不支持时明确失败，可使用原有 UI
  复制导入。临时别名不是归档副本。
- 当前 AtomicSplit 直接产生 leaves，不额外生成整章 `.A.mkv`，也不跳过单 leaf 的 Merge。
- 归档检查只覆盖已登记 Artifact。源素材、发布成片或第三方节点未声明的外部依赖需要另行保留，不宣称完整
  离线归档包。历史文件名保持原样，不为了新命名改写已验收成果。
- 用户先在旧页面明确“退出应用”，再双击 11 号新包；刷新旧网页不等于升级。先用新工程测试默认/自定义
  位置与收件流程，再自行决定是否对已验收的旧工程执行预览和确认迁移。

本记录不代替真实新包、专用磁盘迁移或外部增强工具的用户验收，也不宣称 v0.3.0 全部阶段已经关闭。
