## 1. 已观察事实与诊断边界

操作者先选择工程数据父目录，再恢复默认位置后，页面报告本机服务不可用并无法继续操作。
Windows Application Error 记录桌面候选在 2026-09-13 10:23:18 发生 `0xc0000005`；检查时服务进程
已退出，原服务端口不再监听。实际运行包的相关 Python 源与前端资源已与当前仓库逐字节核对。

“恢复工程旁默认”只更新向导本地状态并使旧预览失效，不执行目录迁移、删除、创建或媒体处理。
前端把服务 stale 传入向导 busy，导致关闭按钮及 Escape 同时不可用，这是已确认的独立缺陷。

旧选择器在 HTTP 工作线程中反复创建和销毁 Tk，只有互斥锁，没有进程级故障隔离；普通 Python
异常包装无法拦截原生访问冲突。本次尚无 native crash stack 证明具体崩溃指令，因此不把线程/析构
风险写成已经证实的唯一原因。修复应同时消除该生命周期风险并隔离原生崩溃的影响范围。

## 2. 修复边界

### 原生选择器

- 每次选择通过固定 helper 子进程完成，Tk 仅在 helper 主线程中创建、使用和销毁。
- 父服务继续拥有 HostBridge 互斥、权限、请求和 selection handle；不把 Project 或会话 token 交给 helper。
- 固定 executable/argv、`shell=False`，使用严格有界的纯数据管道；不增加 HTTP 能力或任意命令入口。
- helper 非零退出、输出损坏或协议不符均返回明确失败，不接受部分成功，不结束父服务。
- 保留四类选择器的临时置顶 owner、取消无文件副作用及单一打开语义。

### 向导

- 服务不可用与正在进行的操作分开表达，不再因断线封死关闭和返回入口。
- 暂停后重开保留当前页面的表单草稿；本地恢复默认不得被旧 picker 响应覆盖。
- 连接失效后不把旧 selection/probe/preview 票据当作当前 authority，恢复后由用户显式重选/重验。
- 重连只恢复读取，不自动重放创建工程、保存、导入、提交或运行。
- 当前页面的内存草稿不是第二份 Project/Graph，也不承诺跨刷新、关闭标签页或新桌面实例保存。
